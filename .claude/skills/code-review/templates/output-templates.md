- 🔴 **[IC##]** Critical: {내용} — {유래 사례 ID} 회귀 위험 / 운영 경험
- 🟡 **[IW##]** Warning: {내용} — {유래 사례 ID} 운영 사례 / 운영 경험

- 🟡 **[W##]** Warning: {내용}
- 🔵 **[S##]** Suggestion: {내용}

> **패턴 ID 표기 우선순위**:
> 1. 운영 안티패턴 매칭 시 — IC/IW ID + 유래 사례 ID (예: `[IC01] ... — {유래 사례 ID}`, `[IW05] ... — {유래 사례 ID}`, `[IC07] ... — 운영 경험`)
> 2. severity-rules 매칭 시 — 프론트엔드 항목은 `frontend-rules.md` 에 **실제로 있는 ID** 를 대괄호로 표기하고,
>    백엔드 항목은 카테고리 표기(Critical / Warning / INFO)를 쓴다 — `severity-rules.md` 에는 번호 ID 가 없다.
>    ID 를 지어내지 않는다. 그 파일에 없는 번호를 쓰면 근거 없는 지적이 된다.
> 3. 휴리스틱 판정 시 — [H]
