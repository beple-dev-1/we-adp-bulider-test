# 코드 리뷰 심각도 규칙 (공통)

기술 스택과 무관하게 적용되는 기준이다.
프로젝트 고유 규칙은 `project-rules.md` 에 따로 둔다.

## CRITICAL (즉시 수정)

### 비즈니스 로직
- 금액·재고·포인트처럼 되돌리기 어려운 처리에 중복 방지가 없음
- 조회 → 비교 → 갱신 패턴에 동시성 보호가 없음
- 외부 호출·DB 호출의 오류 반환값을 검사하지 않고 다음 단계로 넘어감
- 재실행 시 같은 결과가 보장되지 않는 배치·잡

### 보안
- 개인정보가 로그·응답에 노출됨
- 인증 없이 접근 가능한 보호 대상 엔드포인트
- 시크릿·비밀번호·API 키 하드코딩
- 사용자 입력을 검증 없이 출력(XSS)하거나 쿼리에 직접 넣음(인젝션)

### 자원
- 커넥션·파일·스트림을 닫지 않는 경로가 있음
- 자원을 잡은 상태로 외부 호출을 기다림 (풀 고갈 위험)

## WARNING (권고 수정)

### 성능
- 인덱스를 타지 않는 쿼리 (선행 와일드카드 LIKE, 전체 스캔)
- 동기 요청 경로에 무거운 집계·반복 조회가 들어감
- N+1 조회

### 안정성
- **전역 예외 처리기가 프레임워크 기본 오류를 덮지 않음** — 본문 파싱 실패·경로 파라미터 타입
  불일치·지원하지 않는 메서드가 프레임워크 기본 응답으로 새어 나가면 오류 응답 계약이 깨진다
  (정적 리뷰에서 놓치기 쉽다 — 런타임 검증 항목과 짝으로 본다)
- 외부 호출에 타임아웃이 없음
- 예외를 잡고 아무것도 하지 않음(빈 catch)
- 실패 시 알림·복구 경로가 정의되지 않음
- 환경별 값(URL·키)이 코드에 박혀 있음

## INFO (참고)

### 컨벤션
- 프로젝트 컨벤션 미준수 (들여쓰기·네이밍·import 순서)
- 주석·문서 부재
- 디버그 출력 잔재
