# 화면 코드 리뷰 기준 (공통)

> 화면 파일(템플릿·컴포넌트·JS·CSS)에 대한 리뷰 기준이다.
> 경로 규칙은 프로젝트마다 다르므로 `config/scope.yaml` 을 기준으로 판단한다.

---

## S01 — 사용자 입력 출력 (CRITICAL)

- 사용자 입력이나 서버 응답을 이스케이프 없이 그대로 마크업에 넣는 코드.
- 프레임워크의 자동 이스케이프를 끄는 옵션(원문 삽입·`innerHTML` 계열)을 쓴 곳은 전부 확인 대상.
- 이스케이프를 끌 이유가 있다면 그 값의 출처가 신뢰 가능한지 코드로 보여야 한다.

## S02 — 하드코딩 (WARNING)

- 환경별로 달라지는 값(도메인·엔드포인트·키·기능 플래그)이 화면 코드에 박혀 있음.
- 색상·간격 같은 값은 디자인 토큰·변수로 뺐는지 확인.

## S03 — 비즈니스 로직 위치 (WARNING)

- 금액 계산·권한 판정·상태 전이가 화면 쪽에만 있고 서버에 없음.
- 화면 검증은 편의이고, **서버 검증이 없으면 검증이 없는 것**이다.

## S04 — 응답 처리 (WARNING)

- 비동기 호출의 실패 경로가 없음 (에러 콜백·상태 코드 확인 부재).
- 로딩·빈 상태 처리가 없어 사용자에게 멈춘 화면이 보임.

## S05 — 상태 복원 (WARNING)

- 화면 일부를 갈아끼우는 방식(부분 렌더·모달 재오픈)에서 스크롤 위치·포커스가 초기화됨.
- **모든 진입 경로**를 확인한다 — 최초 진입 / 인플레이스 갱신 / 닫고 재진입.

## S06 — 잔재 (INFO)

- 디버그 출력, 주석 처리된 코드 블록, 사용하지 않는 자산.

---

## 검증 방식 주의

- 값 검사만으로 화면 통과 판정을 내리지 않는다. 값이 맞는데 렌더가 깨지는 경우가 있다.
- 화면을 바꿨으면 실제 렌더를 확인한다 (`config/stack.yaml` 의 `runtime` 설정 참조).
