# 프로젝트 코드 리뷰 기준 (프로젝트가 채우는 슬롯)
<!-- HARNESS:UNFILLED — 이 파일을 프로젝트 내용으로 채운 뒤 이 줄을 지운다. 지우면 작성 완료로 본다. -->

이 파일은 **비어 있어도 된다.** 비어 있으면 `/code-review` 는 `severity-rules.md` 의 공통 기준만 적용한다.

여기에 적을 것은 공통 기준으로 잡히지 않는 것들이다.

- 이 프로젝트 도메인에서 반드시 지켜야 하는 순서·검사
- 프레임워크 관용구 (이 코드베이스에서만 통하는 패턴)
- 과거에 사고가 났던 지점 (재발 방지)
- 팀이 합의한 금지 사항

한 항목은 한 줄로 쓰고, **판정 가능한 형태**로 쓴다.
"주의한다" 는 리뷰에서 쓸 수 없다. "X 호출 후 Y 검사가 없으면 CRITICAL" 처럼 쓴다.
