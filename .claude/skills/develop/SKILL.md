# /develop {스코프} [{과업번호}]

이 세션에서 **어디를 고칠 수 있는지** 정하고 구현에 들어간다.

---

## 0단계: 프로파일 확인 (건너뛰지 않는다)

```bash
bash .claude/scripts/check-profile.sh
```

- 종료 코드 `3` — **미연동**. 여기서 멈추고 사용자에게 출력 내용을 그대로 전달한다. 구현에 들어가지 않는다.
- 종료 코드 `0` — 연동됨. 다음 단계로 간다.

---

## 위임 맵

| 단계 | 담당 |
|---|---|
| 1~5 스코프 설정 | 본 스킬 (메인 Claude) |
| 서버·로직 구현 | `dev-backend` 에이전트 |
| 화면 구현 | `dev-frontend` 에이전트 |
| 기존 구현 탐색 | `code-investigator` 에이전트 |

에이전트를 쓸 수 없는 상황이면 임의로 대행하지 않고 사용자에게 먼저 묻는다
(`.claude/rules/base-rule.md` 서브에이전트 원칙).

**서브에이전트에는 Plan Mode 를 적용하지 않는다** —
`.claude/docs/agents/common/subagent-plan-mode-policy.md` 참조.
계획은 이미 상위 스킬이 세웠고, 실행 단계에서 다시 계획을 세우면 중복·혼란·대기만 늘어난다.

## 입력 형식

```
/develop {스코프}[+{스코프2}] [{과업번호}] [--ref-read {스코프}]
```

- `{스코프}` — `config/scope.yaml` 의 `scopes[].id`. **쓰기 대상이 둘이면 `+` 로 잇는다**
  (예: `/develop schedule+platform 001`). 셋 이상이면 스코프 분할을 다시 보거나 과업을 쪼갠다.
- `{과업번호}` — 3자리 숫자. 주면 계획서를 로드하고, 없으면 계획서 단계를 건너뛴다.
- `--ref-read {스코프}` — 그 스코프를 **읽기 전용**으로 추가한다.

## 실행 절차

### 1단계: 인수 검증

- 스코프 id 가 `config/scope.yaml` 에 없으면 사용 가능한 id 목록을 출력하고 멈춘다.
- 스코프를 안 줬으면 목록을 보여주고 사용자에게 고르게 한다.

### 2단계: 경로 해석

- 쓰기 허용 = 지정된 **모든** 스코프의 `allowedPaths` 합집합 + `sharedModules`
  + 산출물 경로(`project.yaml` 의 `outputDir`).
- 스코프를 둘 지정했으면 세션 요약에 둘 다 적는다. 한쪽을 슬쩍 끼워 넣지 않는다.
- 읽기 전용 = 해당 스코프 `refReadPaths` + `--ref-read` 로 받은 스코프의 `allowedPaths`.
- 금지 = `config/scope.yaml` 의 `protectedPaths`.
- 경로는 워크스페이스 루트 기준 **상대경로**로 쓴다. 절대경로가 불가피하면 슬래시(`/`)를 쓴다.

### 3단계: 기밀 보호

- `protectedPaths` 에 걸린 파일은 읽기·수정·복호화 모두 금지한다.
- 시크릿이 필요하면 파일을 열지 않고 사용자에게 직접 값을 요청한다.
- 이 금지는 읽기 전용 스코프에도 같이 적용된다.

### 4단계: 코딩 지침 로드

- `project.yaml` 의 해당 모듈 `guideline.backend` / `guideline.frontend` 경로를 읽는다.
- **표식을 구분해 판정한다.** 하나만 보면 나머지가 조용히 새어 나간다.
  판정 기준의 정본은 `check-profile.sh` 의 `adv()` 함수다 — 표식이 늘면 그쪽이 먼저 바뀐다.

  ```bash
  grep -oE 'HARNESS:[A-Z]+' "{지침 경로}" | head -1
  ```

  | 상태 | 판정 | 세션 요약에 적는 것 |
  |---|---|---|
  | 값이 비어 있다 | 지침 없음 | `지침 문서: 없음` |
  | `HARNESS:UNFILLED` | 지침 없음 (배포된 빈 템플릿) | `지침 문서: 없음 ({경로} — 미작성)` |
  | `HARNESS:DEFAULTS` | **공통 절만 유효** | `지침 문서: {경로} — 공통 기본값만, 프로젝트 고유 규칙 없음` |
  | `HARNESS:NA` | **이 프로젝트에 해당 없음** | `지침 문서: 해당 없음 ({경로} — NA)` |
  | 표식 없음 | 지침 있음 | `지침 문서: {경로}` |

  - `NA` 는 "빠뜨린 것" 이 아니라 **"안 쓰기로 한 것"** 이다. 화면 없는 프로젝트의 화면 지침이 그렇다.
    이것을 미작성으로 보고하면 사용자가 채우려 들게 된다. 구분해서 적는다.
  - **표에 없는 표식이 나오면 그 사실을 요약에 적고 지침 없음으로 본다.** 임의로 해석하지 않는다.

- **`DEFAULTS` 를 그냥 "지침 있음" 으로 적지 않는다.** 요약에 경로만 적히면 서브에이전트가
  그것을 프로젝트 규칙으로 알고 파일을 열어 본 뒤 각자 다시 판정하고 각자 보고서에 적는다
  (2026-09-01 실측 — 에이전트 셋이 연속으로 같은 재판정을 보고했다. 같은 일을 세 번 했다).
- **판정 결과 한 줄을 서브에이전트 프롬프트에 그대로 실어 보낸다.** 그러면 재판정이 사라진다.
- **주석 처리된 샘플을 지침으로 읽지 않는다.** 지침 문서의 "프로젝트가 채울 항목" 절은
  채우기 전까지 주석 안에 **예시**가 들어 있다. 그것은 이 프로젝트의 규칙이 아니다.
  샘플이 특정 라이브러리를 지시하는데 이 프로젝트가 그것을 안 쓰기로 했다면 **샘플이 틀린 것이다.**
- 공통 컨벤션은 `.claude/rules/convention.md` 를 항상 적용한다.

### 4.5단계: 실행 환경 확인

- `config/stack.yaml` 의 `env`·`toolPaths` 를 읽는다. 빌드·테스트 명령을 돌릴 때 이 둘을 먼저 적용한다.
- 명령이 처음이라면 `bash .claude/scripts/check-profile.sh --verify-commands` 로 한 번 실행해 확인한다.
  적어놓기만 한 명령은 첫 테스트에서 무너진다.
- **`runtime.browser: true` 인데 이 세션에 브라우저·스크린샷 도구가 없으면 지금 사용자에게 알린다.**
  화면을 고치기 시작한 **뒤**에 알면 늦다 — `testing.md` 트랙2 는 "렌더를 눈으로 확인" 을 요구하는데
  그 확인을 못 하는 채로 구현이 끝나고, 결과서를 쓸 때가 되어서야 드러난다.
  알릴 때 세 가지를 함께 준다.
  1. 이 세션에서는 렌더 확인이 불가하다는 사실
  2. 대신 어디까지 가능한지 (lint · 빌드 · 컴포넌트 테스트 · 서빙 자원 대조)
  3. 렌더 확인을 **별도 세션으로 미룰지**, 지금 도구를 붙일지 사용자가 고르게 함
  값 검사로 통과 판정하지 않는다. 못 한 것은 못 했다고 결과서에 적는다.

### 5단계: 형상관리 확인

- `config/stack.yaml` 의 `vcs` 를 읽어 이 세션의 커밋 경로를 확인한다.
- `vcs.commitDeploys: true` 면 **커밋이 곧 배포**다. 커밋 전 `/code-review` 가 필수임을 요약에 명시한다.
- `vcs.kind: git` 이고 `commitDeploys: false` 면 브랜치 작업이 가능하다. 기본 브랜치에 직접 커밋하지 않는다.

### 6단계: 계획서 확인 (과업번호를 받은 경우)

**6-1. 루트 계획서**

- `{outputDir}/plans/{과업번호}/` 를 읽는다.
- 없으면 `/dev-plan {과업번호}` 를 먼저 하도록 안내하고, 계획 없이 구현할지 사용자에게 묻는다.
- 계획 없이 진행하기로 했으면 **그 사실을 세션 시작 요약과 결과서에 남긴다.**
  안 남기면 산출물 고리가 끊긴 것을 결과서 단계에서야 알게 된다
  (`check-workflow-artifacts.sh` 가 잡지만, 그때는 이미 구현이 끝난 뒤다).

**6-2. 이번에 구현할 페이즈 문서의 §2 선행 조건 (건너뛰지 않는다)**

- `{outputDir}/plans/{과업번호}/phases/phase_{N}.md` 의 **§2 선행 조건**을 읽고 충족 여부를 판정한다.
- 충족되지 않으면 **구현에 들어가지 않는다.** 선행 페이즈를 먼저 돌린다.
- **루트 계획서의 `의존 페이즈` 컬럼만 보고 병렬 가능하다고 판단하지 않는다.**
  그 컬럼은 산출물 의존을 다 담지 못한다 — 스코프와 의존 번호가 같아도
  페이즈 문서가 "먼저 끝낸다 · 동시 진행 금지" 를 명시하는 경우가 있다
  (2026-08-31 실측 — 공용 CSS 와 공용 컴포넌트를 두 페이즈가 같이 건드리는 구조였다).
- 같은 스코프의 페이즈를 **병렬로 돌리려면 조건이 둘이다. 둘 다 봐야 한다.**

  **조건 1 — 파일이 안 겹치는가.** 각 페이즈 §3 구현 대상 파일 목록을 대조한다.
  겹치면 순차로 돌린다.

  **조건 2 — 서로 같아야 하는 값이 있는가.** 파일이 안 겹쳐도, 두 페이즈가
  **같은 것을 각자 표현**하면 병렬이 그것을 갈라놓는다. 빌드도 테스트도 안 잡는다.

  | 갈리기 쉬운 것 | 예 |
  |---|---|
  | 표시 형식 | 날짜·금액·전화번호 포맷 |
  | 사용자 문구 | 빈 상태 안내·오류 문구·버튼 이름 |
  | 번호 체계 | 0부터인가 1부터인가 |
  | 색·간격 | 공용 CSS 를 금지한 구조에서 특히 |
  | 용어 | 같은 개념을 다르게 부름 |

  해당하는 것이 있으면 **병렬을 시작하기 전에 값을 확정하고, 각 페이즈 프롬프트에
  같은 문장으로 넣는다.** 확정할 수 없으면 병렬을 포기하고 순차로 돌린다.
  (2026-09-01 실측 — 목록·상세가 같은 글의 작성일시를 각자 포맷하는 구조였다.
  형식을 프롬프트에 못박아 넣어서야 갈라지지 않았다. 계획서에는 형식이 없었다.)

  조건 2 로도 다 못 막는다 — 구현 **도중에 발명되는** 해법은 시작 시점에 없다.
  그건 아래 8.5단계 병렬 수렴이 맡는다.

**6-3. 페이즈가 바뀌면 스코프를 다시 연다**

- 계획서가 페이즈별로 다른 `/develop` 호출을 지정했으면, **페이즈를 넘길 때 그 스코프로 다시 호출한다.**
  앞 페이즈에서 열렸던 스코프는 닫힌다 — 누적되지 않는다.
- 예: P1 `order+platform` → P2 `order+catalog` 이면, P2 에서 `application.properties` 는 쓰기 금지다.
- 서브에이전트에 위임할 때는 **그 페이즈의 쓰기 허용·금지를 프롬프트에 다시 적어 넘긴다.**
  에이전트는 이 세션의 스코프 상태를 모른다.
- 9단계 자가 점검도 페이즈 단위로 한 번씩 돌린다.

**6-4. 계획서가 미룬 결정을 먼저 닫는다 (구현 전)**

계획서는 "develop 착수 시 확인" 으로 결정을 미룰 수 있다. **그 결정을 열어 둔 채 구현하지 않는다.**

```bash
grep -rn "<!-- OPEN -->" "{outputDir}/plans/{과업번호}/"
```

**자연어 낱말을 grep 하지 않는다.** 예전에는 `착수 시 확인|미확정|사용자 확인 필요` 를 찾았는데
두 가지가 다 틀렸다 (2026-09-01 실측).

- 한국어는 부정을 어미로 만든다 — 계획서의 **"미확정 아님"** 이 `미확정` 에 그대로 걸렸다.
  **이미 닫힌 결정 2건이 "구현 전에 물어라" 로 올라왔다.** 안 도는 것보다 나쁘다.
- 정작 열린 결정 2건은 `정하고`·`선례가 없어` 로 적혀 **하나도 안 걸렸다.** 신호가 음(-)이었다.

표식의 정본은 `docs/agents/dev-planner/references/root-doc-schema.md` §4 다.
계획서를 만드는 쪽과 읽는 쪽이 **같은 표식 하나**를 본다.

1. 걸린 항목이 있으면 **구현 전에 사용자에게 묻는다.**
2. 확정되면 **아래 4종에 전부 되먹인다.** 하나라도 빠지면 그 문서가 거짓말을 시작한다.

   | 되먹일 곳 | 왜 |
   |---|---|
   | 브리프 | 설계 결정의 정본이다. 여기가 안 바뀌면 다음 과업이 옛 결정을 읽는다 |
   | 루트 계획서 | 전제·위험 표의 "미확정" 을 "해소" 로 바꾼다 |
   | 해당 페이즈 문서 | 구현 지시가 여기 있다. 반대로 적혀 있으면 에이전트가 반대로 만든다 |
   | **테스트 계획서** | **가장 잘 빠뜨린다.** 새 동작인데 TC 가 없으면 `/qa-test` 가 계획서 기준으로 도니 **끝까지 아무도 모른다** |

3. **새 동작이 생겼으면 TC 를 추가한다.** "고쳤으니 됐다" 로 넘기지 않는다.
4. **그 결정이 기존 처리 경로를 가로채지 않는지 본다.** 특히 catch-all·인터셉터·필터·
   전역 핸들러를 새로 넣을 때. 계획서 다른 절이 "이 예외는 안 잡는다" 라고 써 뒀는데
   더 넓은 핸들러를 넣어 그 주의를 무력화하는 일이 난다
   (2026-09-01 실측 — `Exception` catch-all 을 넣었더니 미매핑 경로 예외까지 삼켜
   화면 딥링크가 전부 500 이 됐다. 러너는 전부 GREEN 이었고 트랙2 에서야 드러났다).
5. 되먹임을 마치면 `bash .claude/scripts/check-workflow-artifacts.sh` 를 한 번 돌린다.

**6-5. 페이즈 간 인계물의 실행 주체를 정한다**

계획서는 "확인해서 다음 페이즈에 알린다" 를 쓸 수 있다. **그 확인을 누가 하는지는 안 쓴다.**
그래서 아무도 안 하고 추정으로 대체된다.

```bash
grep -rn -A20 "## 8. 다음 페이즈 인계" "{outputDir}/plans/{과업번호}/phases/"
```

**섹션 이름을 찾는다. 자연어 낱말을 찾지 않는다.** `phase-doc-schema.md` 가
`## 8. 다음 페이즈 인계` 를 **고정 섹션**으로 규정하므로 모든 페이즈 문서가 그 제목을 갖는다.
`확인한다`·`실측` 같은 흔한 말을 찾으면 우연에 기대게 되고, 6-4 처럼 부정문까지 물게 된다.

- 나온 항목을 **인계물 목록**으로 만들고 각각 실행 주체를 정한다.
- **서브에이전트가 못 하는 유형은 메인이 직접 한다.** 서버를 띄워 실제 응답을 보는 것,
  실행 결과의 문자열 형식을 확인하는 것 등이 그렇다. 구현 에이전트는 이것을
  "트랙2 영역" 으로 보고 미확인으로 남긴다 — 그 판단 자체는 틀리지 않다.
  > **"메인이 대행하지 않는다" 는 원칙은 *구현* 대행 금지다. *확인* 금지가 아니다.**
  > 이 구분을 헷갈려 확인을 미루면 추정이 그대로 코드에 굳는다.
- 확인한 값은 **다음 페이즈 문서 §2 선행 조건에 실측값으로 적어 넣는다.** 보고에만 남기지 않는다.
- **미확인인 채로 다음 페이즈를 시작하지 않는다.**
  (2026-09-01 실측 — 날짜 직렬화 형식을 실측하니 응답 경로마다 소수 자릿수가 달랐다.
  추정 보고에는 그 차이가 없었고, 화면이 문자열을 잘라 썼으면 깨졌다.)

### 8단계: 접근 제어 (세션 내내 적용)

파일을 수정하기 전에 매번 판정한다.

1. `protectedPaths` 에 걸리면 → 거부. 사용자에게 알린다.
2. 쓰기 허용에 들어가면 → 수정한다.
3. 읽기 전용에 들어가면 → 읽기만 한다. 수정이 필요하면 사용자 승인을 받는다.
4. 어디에도 없으면 → 멈추고 사용자에게 스코프 확장 여부를 묻는다.

임의로 스코프를 넓히지 않는다.

### 8.5단계: 병렬 수렴 (병렬로 돌렸을 때만)

병렬 페이즈를 돌렸으면 **끝난 뒤 산출물을 서로 대조한다.** 이 단계가 없으면 갈린 채로 커밋된다.

1. 각 에이전트 보고에서 **"계획서에 안 적혀 있어 내가 정한 것"** 항목을 모은다.
2. 각 항목에 대해 묻는다 — **"이 판단이 다른 병렬 페이즈에도 해당하는가?"**
   - 해당하면 그 페이즈에도 적용한다.
   - 적용하지 않기로 했으면 **왜 아닌지를 한 줄 남긴다.**
3. 적용 결과를 **계획서에 되먹인다.** 다음 과업이 같은 것을 또 발명하지 않게.

- 이 단계는 **이미 받은 보고만 읽으면 된다.** 추가 탐색이 필요 없어 값이 싸다.
- 6-2 조건 2 로는 이걸 못 막는다. **시작 시점에 존재하지 않던 해법**이기 때문이다.
  (2026-09-01 실측 — 목록 화면이 구현 중 "의존성이 안 바뀌면 재요청이 안 나간다" 를 발견해
  재시도 카운터를 발명했다. 상세 화면은 같은 문제를 갖고도 그 해법을 몰랐다.
  병렬이라 서로를 못 봤고, 코드리뷰가 정본 이탈로 잡아냈다.)
