# HANDOFF.md 템플릿

> pack 스킬 **2단계** 에서 참조하는 워크스페이스 루트 `HANDOFF.md` 작성 형식.
> **로컬 전용** — 어느 레포에도 커밋하지 않는다 (`base-rule` 참조).
> 진행 중 컨텍스트를 담는 **단일 파일**이며, 완료된 작업은 `HANDOFF_HISTORY.md` 로 이동한다.

## 구조

```markdown
# HANDOFF — {YYYY-MM-DD}

## 하네스 판

- 판: {`.claude/VERSION` 첫 줄} ({둘째 줄 — 날짜})
- 없으면 `알 수 없음 (.claude/VERSION 없음)` 이라고 적는다. **비워두지 않는다.**

> zip 으로 배포하면 커밋 해시가 없어 **받은 쪽이 자기 판을 식별할 수 없다.**
> 정합성 검사도 판을 찍지만 그 출력은 세션 안에서만 보이고 사라진다.
> 이 문서가 다음 세션·다른 사람에게 전달되는 유일한 경로다 —
> 여기 없으면 마찰 보고에 판이 안 붙고, 검사 종수가 회차마다 늘어
> "통과 14 · 실패 0" 이 판마다 다른 뜻이 된다.

```bash
sed -n '1,2p' .claude/VERSION 2>/dev/null || echo "알 수 없음"
```

## 진행 중인 작업
- 과업번호: {N | 없음(사유)}
- 스코프: {scope | 없음}
- 브랜치: `{브랜치명}` (브랜치를 쓰지 않는 환경이면 "해당 없음")
- 현재 단계: {phase}

## 작업 요약
{이번 세션에서 수행한 작업 요약 — 서술 + 필요 시 bullet}

## 변경 파일

### 소스 변경
{VCS 상태 명령 기반 변경 파일 목록 — 변경 없으면 "변경 없음"}

### 하네스 (Git)
{git status 기반 변경 파일 목록 — 커밋/머지 상태 포함. 변경 없으면 생략}

## 다음 단계
1. {남은 작업 항목}

## 미결 사항
- {해결 안 된 질문이나 결정 사항}

## 보안 자가점검
- [ ] 시크릿·운영 설정 파일 미열람·미변경 (`config/scope.yaml` 의 `protectedPaths`)
- [ ] 시크릿(키·비밀번호·DB 접속정보)이 코드·문서·주석에 포함되지 않음
- [ ] 개인정보(이름·연락처·주민번호 등) 로그 노출 없음
- [ ] 커밋 상태 확인 (`vcs.commitDeploys: true` 면 커밋 즉시 반영됨)
- [ ] Git(하네스) 머지 상태 확인 (피처 브랜치 → PR → squash merge)
```

## 작성 규칙 (2단계에서 적용)

1. **날짜**: `YYYY-MM-DD` (KST).
2. **브랜치**: 브랜치를 쓰는 환경에서만 기록한다.
3. **변경 파일**: 소스와 하네스를 다른 레포에 두는 환경이면 반드시 분리해 기록한다 — 혼재 커밋 금지.
4. **완료 항목 이동**: 이번 세션에 완료된 작업은 `## 다음 단계`/`## 진행 중인 작업` 에서 빼고 `HANDOFF_HISTORY.md` entry 로 옮긴다 (3단계).
5. **보안 자가점검**: 매 갱신 시 전 항목을 재확인한다.
