# HANDOFF_HISTORY.md 형식

> pack 스킬 **3단계** 에서 참조하는 워크스페이스 루트 `HANDOFF_HISTORY.md` 작성 형식.
> **로컬 전용** — 어느 레포에도 커밋하지 않는다 (`base-rule` 참조).
> 완료 이력을 **시간 역순**으로 누적하는 단일 파일. 새 entry 는 파일 상단(`---` 바로 아래)에 prepend.
> prepend **방법**(전문 Read 없이 셸로 합친다)은 pack `SKILL.md` 3단계가 단일 출처다 — 여기서 재서술하지 않는다.

## 파일 골격

```markdown
# HANDOFF HISTORY

---

## {YYYY-MM-DD} — {제목} — 완료 ({커밋/PR 식별자})

**작업자**: {name} · **과업번호**: {N | 없음(사유)} · **{VCS}**: {커밋/머지 요약}

### {자유 소제목 — 예: 변경 요약}
- {핵심 변경}

### 검증 방법
- {정적 확인·개발서버 검증·dry-run 등}

### 잔여 (다음 세션)
- {남은 항목 — 없으면 생략}

---

## {그 이전 날짜} — {이전 entry 제목}
(동일 구조)

---
```

## 작성 규칙 (3단계에서 적용)

1. **entry 헤더**: `## {YYYY-MM-DD} — {제목}`. 날짜만 사용(시각 생략).
2. **메타 라인**: `**작업자** · **과업번호** · **{VCS}**` 를 한 줄로.
   - 하네스(Git) 작업: `**GitHub**: 피처 브랜치 {branch} → squash merge ({sha})` 형식 (`base-rule` 하네스 워크플로).
   - 소스 커밋: `**커밋**: {리비전 또는 해시}` 형식.
   - 하네스 호스트가 GitLab 이면 `**GitLab**: ... MR` 로 표기.
     호스트는 `config/stack.yaml` 의 `vcs` 와 `git remote -v` 결과로 판단한다.
3. **본문**: `###` 자유 소제목으로 구성한다. 강제 구조는 없으나 **변경 요약·검증 방법**은 권장한다.
4. **종결**: 각 entry 끝에 `---` 구분선을 둔다.
5. **순서**: 항상 prepend (최신이 위).

## entry 추가 판정

| 조건 | entry 추가? |
| ---- | ----------- |
| 이번 세션 완료 작업 1건 이상 | ✅ 추가 |
| 완료 작업 0건 (진행만) | ❌ `HANDOFF.md` 만 갱신 |

## 조회

- **전문 Read 금지** — 누적 파일이라 계속 커진다. 항상 필요한 만큼만 잘라 읽는다.
- 최근 N개 entry: 파일 상단부터 `## ` 헤더 N개까지 읽는다.
- 특정 과업/제목: 날짜·제목 키워드로 `grep "^## "` 후 해당 구간 확인.

## 누적 안내

`## ` 헤더가 과도하게 누적되면(예: 100개 초과) 3단계 마지막에 안내만 출력한다 — **자동 회전·삭제는 하지 않는다.**

```
⚠️ HANDOFF_HISTORY.md 에 entry 가 {N}개 누적되었습니다. 비대해지면 직접 잘라내거나 분리 파일로 옮기세요.
```

잘라내거나 옮길 때도 **전문 Read 를 하지 않는다** — `sed`·`tail` 로 구간을 잘라 새 파일로 만든다.
전문 Read 후 Write 로 되쓰면 2,000줄 상한에 잘려 뒤쪽 entry 가 사라진다.
