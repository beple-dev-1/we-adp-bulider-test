# /setup — 하네스 연동

`config/` 의 자리표시자(`__FILL__`)를 채워 하네스가 이 프로젝트에서 돌게 만든다.

## 이 스킬이 다른 스킬과 다른 점

**0단계에 프로파일 게이트를 두지 않는다.** `/develop`·`/qa-test`·`/code-review`·`/git` 은
미연동이면 멈추는데, 이 스킬은 **그 미연동 상태를 고치러** 들어온다.
게이트를 태우면 자기 자신이 막힌다.

## 왜 자동으로 채우는가

`stack.yaml` 의 값은 **사람이 판단하는 것이 아니라 스택이 정하는 것**이다.
Maven 프로젝트의 컴파일 명령은 어디서든 `mvn -q -DskipTests compile` 이다.
그런데 그 문자열을 아는 것은 개발자뿐이고, 자리표시자 대부분이 그런 종류다.

그래서 이렇게 나눈다.

| 종류 | 처리 |
|---|---|
| 스택이 정하는 값 | **프리셋에서 가져온다** — 빌드·테스트·런타임 명령 |
| 코드베이스에 답이 있는 값 | **탐지한다** — 소스 루트·공통 패키지·시크릿 경로·VCS |
| 다른 값에서 계산되는 값 | **파생한다** — `tempDir`·`shortName`·모듈 `outputDir` |
| 사람만 아는 값 | **묻는다** — 프로젝트가 무엇인지·DB 를 쓰는지 |

**묻는 것은 마지막 종류만이다.** 나머지를 물으면 답할 수 없는 사람을 막아 세우는 것이다.

## 절차

### 1단계 — 탐지 (묻지 않는다)

```bash
bash .claude/skills/setup/scripts/detect-stack.sh
```

`KEY=VALUE` 줄로 사실만 돌아온다. 이 스크립트는 판정하지 않는다 — 판정은 네가 한다.

> 🔴 **`IS_SKELETON=true` 가 나오면 여기서 멈춘다. 이것만은 판정을 맡기지 않는다.**
>
> 압축을 푼 폴더에는 `.claude/` 가 이미 있어 거기서 세션을 여는 것이 자연스럽다.
> 그대로 진행하면 **골자 저장소 자신을 프로젝트로 연동**하게 되고,
> 게이트까지 통과해 "연동 완료" 가 나오는데 **실제로는 아무 프로젝트에도 안 붙은 상태**다.
> 즉시 드러나는 오류보다 나쁘다 — 조용히 틀린 대상에 붙는다.
>
> 사용자에게 이렇게 알리고 끝낸다.
>
> ```
> 여기는 하네스 골자 폴더다. 연동할 프로젝트가 아니다.
>
>   1. 이 폴더의 `.claude` 를 프로젝트 폴더로 복사한다
>   2. 그 프로젝트 폴더에서 세션을 다시 연다
>   3. 거기서 /setup 을 부른다
> ```

돌아오는 것 중 쓸 것.

| 키 | 쓰는 곳 |
|---|---|
| `PRESET_CANDIDATE` | 어느 프리셋을 적용할지 |
| `DIR_NAME` | `workspaceName`·`projects[].name` 기본값 |
| `SOURCE_ROOT` · `FRONTEND_ROOT` | `scope.yaml` 의 `allowedPaths` |
| `COMMON_DIRS` | `sharedModules` |
| `SECRET_CANDIDATES` · `DATA_DIR` | `protectedPaths` |
| `VCS_KIND` · `VCS_BRANCH` · `VCS_REMOTE` | `vcs` 블록 |
| `WRAPPER_MAVEN` · `WRAPPER_GRADLE` | 명령을 `mvnw`·`./gradlew` 로 바꿀지 |
| `NPM_SCRIPTS` · `NPM_MISSING_*` | 프리셋이 가정한 스크립트가 실제로 있는지 (**루트** `package.json`) |
| `FE_PACKAGE_JSON` · `FE_NPM_SCRIPTS` · `FE_NPM_MISSING_*` | 화면 하위 모듈의 스크립트. Spring+React 는 여기에만 있다 |
| `FE_NPM_PREFIX` | 화면 명령을 `npm --prefix {이 값} run {스크립트}` 로 만든다 |
| `TOOL_OK_*` · `TOOL_MISSING_*` | 빌드 도구가 PATH 에 있는지. **없으면 모든 명령이 죽는다** |
| `TOOL_PATH_CANDIDATE_*` | 그 도구를 찾은 디렉터리 — `stack.yaml` 의 `toolPaths` 에 넣는다 |
| `TOOL_PATH_UNKNOWN_*` | 후보를 못 찾았다 — **4단계에서 사용자에게 설치 위치를 묻는다** |
| `SERVED_BY_BACKEND` · `FRONTEND_BUILD_OUTDIR` | 화면을 백엔드가 함께 서빙하는가 |
| `PKG_NAME` · `NOTE_NAME_DIFFERS` | `workspaceName`·`projects[].name` — **폴더명보다 우선** |
| `TEST_ROOT` | `scope.yaml` 의 `allowedPaths` (테스트 경로) |
| `PORT_HINT` | `runtime.baseUrl` — 출처 파일이 함께 나온다 |
| `NOTE_*` | 사람 확인이 필요한 신호 |

**`NPM_MISSING_*` 와 `NOTE_*` 를 무시하지 않는다.** 프리셋이 `npm run build` 를 쓰는데
그 스크립트가 없으면 첫 테스트에서 무너진다. 그런 칸은 프리셋 값을 그대로 쓰지 말고
`NPM_SCRIPTS` 에 실제로 있는 이름으로 바꾼다.
쓸 만한 이름이 아예 없으면(순수 JS 라 컴파일 단계가 없는 경우 등)
**그 블록의 `enabled` 를 `false` 로 내리고** 명령은 `none` 으로 둔다.
명령만 지우고 `enabled: true` 로 남기지 않는다 — 무엇을 안 쓰기로 했는지가 안 보인다.

**`package.json` 이 루트에 없을 수 있다.** Spring + React 구조에서는 `frontend/` 에만 있다.
그 경우 `NPM_*` 는 비고 `FE_NPM_*` 가 나온다. **`FE_NPM_*` 를 보고 명령을 만든다** —
`npm --prefix {FE_NPM_PREFIX} run {스크립트}` 형태다.

**`TOOL_MISSING_*` 는 그냥 넘길 수 없는 신호다.** 그 도구를 쓰는 명령이 전부
`command not found` 로 죽고, 그러면 `/develop`·`/qa-test` 가 통째로 무의미해진다.
처리는 2단계 `toolPaths` 파생 규칙을 따른다.

**린터가 설정 파일을 요구할 수 있다.** eslint 9 는 `eslint.config.js`(플랫 설정)가 없으면
어떤 형태로도 돌지 않는다(종료 코드 2). `/setup` 은 소스를 고치지 않으므로 이때는
`lint.enabled: false` · `lint.command: none` 으로 내리고, **8단계 "남은 일" 에 복구 방법을
한 줄 적는다** — "`frontend/eslint.config.js` 를 만들면 `lint.enabled` 를 `true` 로 올릴 수 있다".
그냥 끄고 아무 말도 안 하면 다음 사람이 린트가 없는 이유를 모른다.

### 2단계 — 초안 만들기 (아직 파일에 쓰지 않는다)

프리셋을 읽고, 탐지값으로 덮고, 파생값을 계산해 **최종 설정 3개의 초안**을 만든다.

```bash
cat .claude/config/presets/{PRESET_CANDIDATE}.yaml
```

프리셋이 무엇인지·목록·검증 상태는 `.claude/config/presets/README.md` 에 있다.

**프리셋은 `stack.yaml` 만 담는다.** `project.yaml`·`scope.yaml` 은 프로젝트마다 달라
프리셋이 있을 수 없고, 탐지값과 파생 규칙으로 만든다.
형태가 궁금하면 `.claude/docs/examples/{스택}/` 에 채워진 예시가 있다 — **읽기만 한다.**
그 파일을 복사하면 `acme-*` 같은 예시 이름이 그대로 남고,
`check-profile.sh` 가 "예시값 잔존" 으로 잡아 미연동 판정을 낸다.

**파생 규칙** — 이 값들은 묻지 않는다.

| 키 | 계산 |
|---|---|
| `outputDir` | `.work` (기본값. 이미 `target/` 을 쓰는 관습이 있으면 그쪽) |
| `tempDir` | `{outputDir}/tmp` |
| `projects[].outputDir` | 위 `outputDir` 과 같게 |
| `projects[].shortName` | `name` 에서 접미사(`-api`·`-service`·`-app`)를 뗀 것. 그래도 한 낱말이면 그대로 |
| `projects[].dir` | 루트에 소스가 있으면 `"."` |
| `workspaceName` | `PKG_NAME` 이 있으면 그것, 없으면 `DIR_NAME` |
| `vcs.defaultBranch` | `VCS_BRANCH` (없으면 `main`). **`svn`·`none` 이면 `none`** — 브랜치 개념이 없다 |
| `vcs.commitDeploys` | **묻는다**(4단계). 기본 선택지만 탐지로 정한다 — `svn`+원격없음이면 `true`, `git`+원격있음이면 `false` |
| `runtime.baseUrl` | `PORT_HINT` 가 있으면 그 포트. 없으면 프리셋 기본값. **단 `SERVED_BY_BACKEND=true` 면 아래 참조** |
| `runtime.frontendUrl` | `SERVED_BY_BACKEND=true` 면 **빈 문자열**. 화면 개발 서버를 따로 쓰면 그 주소 |
| `env` · `toolPaths` | `TOOL_*` 신호로 채운다. 아래 참조 |
| `projects[].guideline.backend` | 6단계에서 `DEFAULTS` 로 바꾼 지침 문서 경로 |
| `customDocs.antiPatterns` | `.claude/docs/anti-patterns.md` (파일이 있으면) |

**`toolPaths` 파생** — 빈 배열로 두지 않는다.

| 신호 | 하는 것 |
|---|---|
| `TOOL_OK_*` 만 있다 | `toolPaths: []` 로 둔다. PATH 에 다 있다 |
| `TOOL_PATH_CANDIDATE_*` 가 있다 | **그 디렉터리를 `toolPaths` 에 넣는다.** 4단계에서 묻지 않는다 — 실행 파일을 실제로 찾은 값이다 |
| `TOOL_PATH_UNKNOWN_*` 가 있다 | **4단계에서 사용자에게 묻는다** (아래 질문 문구) |

- `env` 는 탐지로 못 채운다. 비워 두되, 7단계 `--verify-commands` 가 인증서·프록시 관련
  오류로 실패하면 그때 채운다(예: `MAVEN_OPTS`).
- **`toolPaths` 를 비워 둔 채 넘어가지 않는다.** `TOOL_MISSING_*` 가 하나라도 있으면
  이 항목이 미해결이라는 뜻이고, 7단계 명령 검증이 반드시 실패한다.

**`SERVED_BY_BACKEND` 처리** — 이걸 놓치면 트랙2 검증이 통째로 엉뚱한 곳을 본다.

- 참이면 **`PORT_HINT` 를 `baseUrl` 에 쓰지 않는다.** 그 값은 화면 개발 서버 포트다
  (vite 5173 등). 검증 대상은 **백엔드 포트**다.
- 백엔드 포트는 프리셋 기본값(`spring-maven` → 8080)이나 `application.properties` 의
  `server.port` 에서 찾는다. 확실하지 않으면 4단계에서 묻는다.
- `frontendUrl` 은 **빈 문자열**로 둔다. 비어 있으면 `baseUrl` 을 쓰라고 `testing.md` 가 정한다.
- `stack.yaml` 의 `buildCommand` 는 **화면 빌드가 먼저**여야 한다 —
  화면 산출물이 백엔드 정적 경로로 들어가므로 순서를 뒤집으면 이전 화면이 패키징된다.

**`scope.yaml` 초안** — 탐지값으로 만든다.

- `allowedPaths` — `SOURCE_ROOT/**`. **`TEST_ROOT` 가 있으면 그것도 넣는다** —
  안 넣으면 `/qa-test` 가 테스트 파일을 쓰지 못한다. `FRONTEND_ROOT` 가 있으면 스코프를 둘로 나눈다.
- **main 경로를 넣을 때마다 대응하는 test 경로를 같이 넣는다.** 스코프를 여럿으로 나눌 때
  특히 그렇다 — 어느 한 스코프가 `.../main/java/x/**` 만 갖고 `.../test/java/x/**` 를 빠뜨리면
  **그 패키지를 만들 수는 있는데 테스트할 파일은 못 만드는** 상태가 된다
  (2026-09-01 실측 — 구현이 다 끝난 뒤 `/qa-test` 단계에서야 드러났다).

  | main | test |
  |---|---|
  | `src/main/java/{pkg}/**` | `src/test/java/{pkg}/**` |
  | `src/main/kotlin/{pkg}/**` | `src/test/kotlin/{pkg}/**` |
  | `frontend/src/**` | (같은 경로 — 화면 테스트는 보통 co-located) |

  `check-harness-consistency.sh` 의 `scope-test-paths` 가 이 대칭을 검사한다.
- `sharedModules` — `COMMON_DIRS` 중 소스 안에 있는 것. 없으면 빈 배열.
- `protectedPaths` — `SECRET_CANDIDATES` + `DATA_DIR`. **실재하는 것만 넣는다** —
  없는 경로를 넣으면 정합성 게이트가 경고를 낸다.

`protectedPaths` 가 비면 그대로 두지 말고 흔한 패턴을 넣는다(`.env` · `.env.*` · `**/*.pem`).
**지금 파일이 없어도 나중에 생긴다.** 이건 "차단 목록" 이라 앞질러 적어도 손해가 없다.

### 3단계 — 보여주고 한 번 확인

초안 전체를 표로 제시한다. **파일을 쓰기 전이다.**

```
## 연동 초안

**탐지 결과** — {PRESET_CANDIDATE} 프리셋 (검증 상태: {프리셋 머리 주석의 값})

| 항목 | 값 | 어디서 왔나 |
|---|---|---|
| 프로젝트 이름 | {...} | 폴더 이름 |
| 산출물 경로 | .work | 기본값 |
| 형상관리 | git / main | .git 탐지 |
| 빌드 | {compileCommand} | 프리셋 |
| 테스트 | {runAllCommand} | 프리셋 |
| 기동 | {startCommand} | 프리셋 |
| 수정 허용 | {allowedPaths} | 소스 루트·테스트 탐지 |
| 보호 경로 | {protectedPaths} | 시크릿 탐지 |
| DB | {used} / {vendor} | 4단계 답 (아직 안 물었으면 "확인 예정") |
| 화면 | {있음·없음} | 4단계 답 또는 FRONTEND_ROOT 탐지 |

**확인이 필요한 것** — {NOTE_* · NPM_MISSING_* 가 있으면 여기에}

이대로 적용할까?
```

`AskUserQuestion` 으로 1질문. 선택지는 셋.

- **이대로 적용** (추천)
- **몇 개만 고치기** → 어느 항목인지 듣고 그 칸만 다시 묻는다
- **처음부터 하나씩** → 4단계로 간다

4단계에서 얻은 답이 초안을 바꾸면(예: 화면이 있다고 해서 스코프가 갈리면)
**바뀐 부분만 다시 보여주고 확인받는다.** 표 전체를 다시 내지 않는다.

> 표에 **"어디서 왔나" 를 반드시 적는다.** 값이 어디서 나왔는지 보이면
> 틀린 것을 사용자가 알아볼 수 있다. 근거 없는 값은 검토할 수 없다.

### 4단계 — 남은 것만 묻기 (1:1)

3단계에서 못 정한 것과, 애초에 사람만 아는 것을 묻는다. **한 번에 1질문.**

물어도 되는 것 — 개발 지식 없이 답할 수 있는 것들이다.

| 묻는 것 | 형태 |
|---|---|
| 이 프로젝트가 하는 일 (한 줄) | 텍스트. `projects[].description` 이 된다 |
| DB 를 쓰는가 | 예/아니오 → `db.used` |
| (DB 를 쓰면) 무엇인가 | PostgreSQL · MySQL · H2 · 기타 · **모르겠다** → `db.vendor`. 아래 참조 |
| 화면이 있는가 | 예/아니오 → 스코프 분할·`runtime.browser` |
| 기동 주소 | 아는 값이 있으면. 모르면 프리셋 기본값을 쓰고 나중에 고친다 |
| **커밋하면 바로 반영되는가** | 예/아니오 → `vcs.commitDeploys`. **아래 문구를 쓴다** |
| **빌드 도구 설치 위치** | `TOOL_PATH_UNKNOWN_*` 가 있을 때만. 아래 문구를 쓴다 |

**DB 종류 질문 — "모르겠다" 를 반드시 선택지에 넣는다.**

`detect-stack.sh` 에 **DB 탐지가 없다**(2026-09-02 확인 — emit 48개 중 DB 관련 0개).
그래서 이 값은 전부 사용자에게서 온다. 그런데 **비개발자가 답할 수 없는 질문**이다 —
"우리 서비스가 PostgreSQL 을 쓰나 MySQL 을 쓰나" 는 개발자만 안다.

> - **모르겠다 / 확인이 필요하다** → `db.used: true` · `db.vendor: ""` 로 두고
>   8단계 "남은 일" 에 "DB 종류를 확인해 `db.vendor` 에 적는다" 를 넣는다.

- `vendor` 는 **설계·리뷰 판단의 참고값**이고 명령을 만들지 않는다. 비어 있어도 워크플로가 돈다.
  `db.used` 만 맞으면 된다 — 그것은 "DB 를 쓰나" 라는 질문이라 답할 수 있다.
- **`used` 와 `vendor` 를 한 질문으로 묶지 않는다.** 묶으면 답할 수 있는 것까지 못 답하게 된다.

**커밋=배포 질문** — `vcs.kind` 가 `git`·`svn` 이면 **항상 묻는다.**

이 값(`vcs.commitDeploys`)은 **워크플로의 순서를 바꾼다.** 실행 환경 검증(트랙2)이
커밋 앞에 오는지 뒤에 오는지가 여기서 갈리고, 정본은 `rules/testing.md` 의
「트랙2 는 언제 하는가」 절이다. 그런데 프리셋은 전부 `false` 로 고정돼 있어
**묻지 않으면 커밋=배포 프로젝트도 조용히 `false` 로 돈다** — 깨진 것을 배포한 뒤에
트랙2 를 하게 되고, 게이트는 그 사실을 알려주지 않는다(2026-09-01 실측).

> 이 프로젝트는 커밋하면 그것이 바로 반영되나, 아니면 별도의 배포 절차가 있나?
> - **별도 배포 절차가 있다 / 리뷰·PR 을 거친 뒤 나간다** → `commitDeploys: false`
> - **커밋하면 바로 반영된다** (trunk 하나로 운영하는 SVN 등) → `commitDeploys: true`
> - **모르겠다** → **아래 탐지 기본값을 쓰고** 무엇을 근거로 그렇게 뒀는지 8단계에 적는다.
>   `false` 로 고정하지 않는다 — svn 무브랜치 운영에서 그 값은 틀리고,
>   그것이 자리표시자로 올려 막으려던 상황을 그대로 되돌린다.

- 개발 지식 없이 답할 수 있는 질문이다 — "커밋하면 바로 반영되나" 는 운영 방식이지 기술이 아니다.
- **탐지값으로 기본 선택지를 정한다.** `VCS_KIND=svn` 이고 `VCS_REMOTE` 가 없으면
  `true` 를 먼저 제시한다. `git` 이고 원격이 있으면 `false` 를 먼저 제시한다.
- 답을 8단계 완료 보고에 **반드시 찍는다.** 워크플로 순서를 바꾸는 값이 조용히 정해지면 안 된다.

**빌드 도구 설치 위치 질문** — `TOOL_PATH_UNKNOWN_{도구}` 가 나왔을 때만 묻는다.
`TOOL_PATH_CANDIDATE_*` 로 이미 찾았으면 **묻지 않는다.**

> `{도구}` 를 못 찾았다. 이 도구가 없으면 빌드·테스트 명령이 하나도 돌지 않는다.
>
> 어디에 설치했는지 아는가?
> - **경로를 안다** → 그 폴더 경로를 알려 달라 (예: `C:/tools/maven/bin` 또는 `/opt/maven/bin`)
> - **설치한 적 없다 / 모르겠다** → 지금은 넘어가고, 빌드·테스트를 `enabled: false` 로 둔다.
>   나중에 설치하면 `/setup` 을 다시 돌리면 된다.

- 이건 **비개발자도 답할 수 있는 질문**이다 — "어디에 깔았나" 또는 "모르겠다".
  "PATH 에 등록하라" 처럼 답이 곧 작업인 질문을 하지 않는다.
- 받은 경로는 `stack.yaml` 의 `toolPaths` 에 넣는다. 실행 파일이 아니라 **그것이 든 디렉터리**다.
- "모르겠다" 를 고르면 해당 블록(`build`·`test`)의 `enabled` 를 `false` 로 내리고
  8단계 "남은 일" 에 적는다. **명령을 남겨둔 채 연동 완료로 보고하지 않는다** —
  7단계 검증이 반드시 실패한다.

**묻지 않는 것** — 답할 수 없는 질문은 사용자를 막아 세운다.

- 명령 문자열(`compileCommand`·`runCommand` 등) — 프리셋이 정한다
- `test.scopeNote` — 프리셋이 정한다
- `db.metaQueryable` — 이 세션에 DB 조회 도구가 있는지는 **네가 아는 것**이다.
  도구 목록을 보고 정한다. 사용자에게 "MCP 가 있나요" 를 묻지 않는다
- `build.enabled` · `test.enabled` · `runtime.enabled` — 프리셋과 탐지로 정해진다

**프리셋 값이 이 프로젝트와 안 맞으면 고쳐도 된다.** 프리셋은 출발점이지 정답이 아니다.
사용자에게 다시 묻지 말고 네가 판단해 고치고, **무엇을 왜 고쳤는지 8단계 보고에 적는다.**

| 흔한 경우 | 어떻게 |
|---|---|
| 화면이 없다는데 `browser: true` | `false` 로. `frontendUrl` 도 비운다 |
| `scopeNote` 가 화면 테스트를 말하는데 API 전용 | 이 프로젝트에 맞게 고쳐 쓴다 |
| `baseUrl` 포트가 `PORT_HINT` 와 다르다 | `PORT_HINT` 를 쓴다 (출처가 함께 나온다) |
| DB 를 쓴다는데 프리셋은 `used: false` | 4단계 답을 따른다 |

> 사용자가 "모르겠다" 고 하면 그것으로 충분한 답이다.
> 기본값을 쓰고 **무엇을 기본값으로 뒀는지 완료 보고에 적는다.**
> 모르는 것을 캐물어 알아낼 수 있는 종류가 아니다.

### 4.5단계 — 이미 연동돼 있으면 (덮어쓰기 전에 멈춘다)

**진입 조건 — `config/` 에 `__FILL__` 이 하나도 없으면 이 단계로 들어온다.**
이 스킬은 0단계 게이트를 두지 않으므로(위 「이 스킬이 다른 스킬과 다른 점」) **1단계 탐지 직후 직접 본다.**

```bash
grep -rl '__FILL__' .claude/config/*.yaml 2>/dev/null || echo "이미 연동됨 — 4.5단계로 간다"
```

5단계는 조건 없이 "쓴다" 라, 그대로 가면 **손으로 채운 값이 프리셋 기본값으로 되돌아간다.**

2026-09-01 실측 — 연동된 프로젝트에서 새 초안을 만들어 대조하니 **17칸 중 10칸이 유실**이었고,
그중 둘(`lint.command`·`db.metaQueryable`)은 되돌아가면 **게이트가 즉시 FAIL 로 떨어졌다.**

1. **차이만 표로 낸다.** 전체를 다시 내지 않는다.

   | 항목 | 지금 값 | 새 초안 | 어디서 왔나 |
   |---|---|---|---|

2. **어느 칸이 손으로 채워졌는지는 `stack.yaml` 머리의 "출처" 줄이 알려 준다.**
   5단계가 남기게 한 그 줄이 유일한 근거다. 반드시 읽는다.
3. **사용자가 고른 칸만 바꾼다.** 고르지 않은 칸은 읽지도 쓰지도 않는다.
4. 바꿀 것이 없으면 **"변경 0건" 으로 보고하고 7단계 검증만 돌린다.** 그것도 정상 종료다.

**탐지로 재현되는 칸은 규칙으로 만들어 둔다** — 아래는 2단계 파생에 포함된다.

| 신호 | 파생 |
|---|---|
| `FE_NPM_SCRIPTS` 에 `test` 가 있고 백엔드 러너도 있다 | `test.suites` 를 **둘로 나눈다**. 한 명령에 `&&` 로 묶지 않는다 |
| `SERVED_BY_BACKEND=true` | `FRONTEND_BUILD_OUTDIR` 을 `protectedPaths` 와 `lint.excludePaths` 에 넣는다 |
| 언제나 | `runtime.screenshotDir` 은 `{outputDir}/screenshots`. 화면이 없으면 빈 값 |

**탐지로 못 만드는 칸**(`env` · `scopes` · `projects[].description` · `test.scopeNote`)은
**손으로 채운 것으로 보고 기본 보존**한다. 사용자가 명시적으로 고를 때만 바꾼다.

### 5단계 — 쓰기

`config/project.yaml` · `stack.yaml` · `scope.yaml` 을 쓴다.

- `stack.yaml` 은 프리셋을 **바탕으로** 쓰고 덮은 값만 다르게 한다.
  프리셋 머리 주석은 지우고, 대신 **출처 두 줄**을 남긴다.

  ```yaml
  # 출처: .claude/config/presets/{프리셋}.yaml ({날짜} /setup 적용)
  #   프리셋에서 고친 것 — {키}, {키}, ...
  ```

  - 둘째 줄이 **4.5단계가 보존 판단에 쓰는 유일한 근거**다. 프리셋 이름만 남기면
    "어느 칸을 사람이 고쳤나" 를 알 수 없어 재실행 때 무엇을 지킬지 못 정한다.
  - 나중에 손으로 값을 고치면 **그 키를 이 줄에 덧붙인다.**
- 원래 템플릿의 **설명 주석은 지우지 않는다.** 그 주석이 다음 사람에게 유일한 안내다.
- 값을 바꿀 때 주변 형식(들여쓰기·인용부호)을 그대로 따른다.
- **명령 칸에는 값 뒤 주석을 붙이지 않는다.** 설명이 필요하면 윗줄로 옮긴다.

  ```yaml
  # 안 됨 — 검사기가 주석까지 명령으로 실행한다
  compileCommand: none       # 컴파일 단계가 없다

  # 됨 — 설명을 윗줄로
  # 컴파일 단계가 없다
  compileCommand: none
  ```

  대상은 `compileCommand` · `buildCommand` · `runCommand` · `runAllCommand` ·
  `lint.command` · `lint.securityCommand` 다.
  검사기가 주석을 떼도록 고쳐 뒀지만, 값과 설명을 한 줄에 섞으면 읽기도 어렵다.
- 프리셋과 템플릿의 주석이 다르면 **템플릿 주석을 남긴다.** 템플릿 주석은 "이 칸이 무엇인가" 를
  설명하고, 프리셋 주석은 "이 스택에서는 이렇게 쓴다" 를 설명한다. 앞의 것이 오래 쓸모 있다.

### 6단계 — 권고 문서 표식 정리

`rules/convention.md` · `docs/guideline/*.md` 같은 문서에는 **공통 기본값이 이미 채워져 있다**
(계층·트랜잭션·실패 처리·이름 규칙 등). 그대로 써도 되는 내용이다.

그런데 파일 첫 줄에 `HARNESS:UNFILLED` 표식이 있어 검사가 "미작성" 이라고 보고한다.
**기본값을 쓰는 정상 상태가 덜 된 것처럼 보인다.**

그 표식을 아래로 바꾼다.

```
<!-- HARNESS:DEFAULTS — 공통 기본값을 쓰는 중이다. 프로젝트 절을 채우면 이 줄을 지운다. -->
```

표식 종류의 정본은 `check-profile.sh` 의 `adv()` 함수다. 파일을 열어 보고 고른다.

| 표식 | 언제 | 예 |
|---|---|---|
| `HARNESS:UNFILLED` (그대로 둠) | 채울 내용이 프로젝트 고유라 공통 기본값이 있을 수 없다 | `project-meta.yaml`(용어 사전) · `anti-patterns.md`(실제 사고만 적는 곳) · `project-rules.md`(작성 요령만 있음) |
| `HARNESS:DEFAULTS` | 본문에 **공통 기본값이 실제로 들어 있고** 이 프로젝트에 해당한다 | `convention.md` · 백엔드가 있으면 `guideline/backend.md` |
| `HARNESS:NA` | 공통 기본값은 있으나 **이 프로젝트에 해당 없음** | 화면 없는 API 프로젝트의 `guideline/frontend.md` |

```
<!-- HARNESS:NA — 이 프로젝트에는 해당 없는 문서다 (화면 없음). 나중에 생기면 표식을 지운다. -->
```

- `HARNESS:NA` 를 두는 이유 — 화면이 없는 프로젝트에서 화면 지침이 "기본값 사용 중" 으로
  뜨면 거짓 신호다. 있지도 않은 것을 쓰는 중이라고 말하게 된다.
- 판단 근거는 4단계 답과 탐지값이다. `FRONTEND_ROOT` 가 없고 사용자도 "화면 없다" 고 했으면 `NA` 다.
- 애매하면 `UNFILLED` 로 둔다. 표식을 잘못 올리는 것보다 안 올리는 편이 낫다.

> 표식을 **지우지 않고 바꾸는** 이유 — 지우면 "채우면 더 좋아진다" 는 신호가 사라진다.
> 개발자가 나중에 프로젝트 절을 채워 개선할 여지를 남겨 둔다.

### 7단계 — 확인 (여기까지가 연동이다)

세 개를 순서대로 돌린다. **파이프를 걸지 않는다** — 종료 코드가 마지막 단계 것으로 바뀌어
실패가 성공으로 보인다.

```bash
bash .claude/scripts/check-profile.sh > /tmp/p.log 2>&1; echo "profile=$?"
bash .claude/scripts/check-harness-consistency.sh > /tmp/c.log 2>&1; echo "consistency=$?"
bash .claude/scripts/check-profile.sh --verify-commands > /tmp/v.log 2>&1; echo "verify=$?"
```

| 검사 | 무엇을 보나 | 실패하면 |
|---|---|---|
| `check-profile.sh` | 자리표시자가 남았는지 | 남은 칸을 채운다 |
| `check-harness-consistency.sh` | 설정이 가리키는 경로·키가 실재하는지 | 그 항목을 고친다 |
| `--verify-commands` | **적어둔 명령이 실제로 도는지** · **커밋할 준비가 됐는지** | 그 명령을 고친다 / 아래 참조 |

**경고(WARN)를 그냥 지나치지 않는다.** 정합성 검사는 경고가 있어도 `RESULT: PASS` 와
종료 코드 0 을 낸다. 그래서 절차상 통과로 읽히고 **아무도 처분하지 않는다.**

`경고 N건` 이 0 이 아니면 **각 항목을 사용자에게 제시**한다. 성격이 갈린다.

| 경고 | 성격 | 처분 |
|---|---|---|
| `scope-paths` — 없는 경로 | 오타이거나 **아직 안 만든 것** | 어느 쪽인지 묻는다. 답할 수 있는 질문이다 |
| `scope-test-paths` — test 경로 부재 | **설정 결함.** 그 코드를 테스트할 파일을 못 만든다 | 고칠 곳이 정해져 있다 — 대응 test 경로를 만들어 제안한다 (2단계 main↔test 대칭 표) |
| `settings-json` — 파일 없음 | **이 스킬이 안 만드는 파일이다.** 지시를 지키면 항상 뜬다 | 8단계 "남은 일" 에 이미 적혀 있음을 알리고 넘어간다. **처분 불가 경고로 남기지 않는다** |
| `outputs-ignored` — 무시 목록 미설정 | 같음. 무시 목록도 이 스킬이 안 고친다 | 같음 |
| `settings-hook` — 훅 미배선 | 마찰 수집이 꺼져 있다 | `settings.json.example` 의 `hooks` 블록을 옮기라고 안내한다 |
| `settings-protected` — 보호 경로 미반영 | `scope.yaml` 이 선언한 경로가 `deny` 에 없다 | 그 경로를 `permissions.deny` 에 넣으라고 제안한다. 목록을 그대로 찍어 준다 |

- 뒤엣것은 **구현이 다 끝난 뒤 `/qa-test` 단계에서야 드러나던 결함**이다. 검사가 이제 잡는데
  처분이 없으면 경고는 배경 소음이 되고, 소음이 된 경고는 다음 것까지 같이 무시된다.

**첫 연동은 경고 3건으로 끝나는 것이 정상이다** (2026-09-02 실측 —
`scope-paths` · `settings-json` · `outputs-ignored`). 셋 다 **이 스킬이 만들지 않는 파일**
때문이라 사용자가 손을 대야 한다. 그래서 8단계 보고에 **"이 경고는 남은 일을 하면 사라진다"**
를 한 줄 적고, 남은 일 목록과 연결한다.

- 안 적으면 매 실행마다 같은 경고 3건을 보게 되고, **그 상태에서 진짜 경고가 하나 늘어도 안 보인다.**
- 비개발자가 그 셋을 못 하는 경우가 있다. 그때는 **못 한 채로 두는 것이 정상**임을 알린다 —
  워크플로는 그대로 돈다. 꺼지는 것은 마찰 수집뿐이고 그것은 하네스 개선용이지 사용자용이 아니다.

**`--verify-commands` 를 건너뛰지 않는다.** 미검증 프리셋의 명령이 이 프로젝트에서
안 도는 경우가 있고, 그건 여기서만 드러난다. 적어놓기만 한 명령은 첫 테스트에서 무너진다.

**커밋 작성자 검사(`vcs-identity`)가 FAIL 이면 연동을 끝내지 않는다.**
커밋 작성자 정보가 없으면 워크플로 마지막(`/git commit`)에서 죽는다 — 브랜치를 만들고
파일을 스테이징하고 사용자 승인까지 받은 뒤에 실패하는 자리라 가장 비싸다
(2026-09-01 실측 — 정확히 그 순서로 막혔다).

검사가 설정 명령을 그대로 찍어 주니, **사용자에게 그 두 줄을 실행하게 하고 다시 돌린다.**
이건 개발 지식 없이 답할 수 있는 일이다 — 이름과 메일주소를 넣으면 된다.

실패한 명령은 **그 자리에서 고친다.** 탐지 결과의 `FE_NPM_SCRIPTS`·`NPM_SCRIPTS`·`WRAPPER_*` 가 단서다.

고칠 수 없으면(도구가 이 PC 에 없다·설정 파일이 없다) 그 블록의 `enabled` 를 `false` 로 내린다.
검사기는 `enabled: false` 인 블록의 명령을 실행하지 않으므로 이 처방이 실제로 게이트를 푼다.
**되살리는 방법을 그 자리 주석에 남긴다** — 예를 들어 `pytest` 가 없어서 내렸다면
설치 명령과 원래 값을 적어 둔다. 다음 사람이 무엇을 하면 되는지 알 수 있어야 한다.

**`RESULT: PASS (검사 대상 없음)` 이 나오면 그대로 보고한다.**
빌드·테스트를 전부 안 쓰는 프로젝트에서는 실행할 명령이 0건이다.
그건 "명령이 돈다" 가 아니라 "검사할 것이 없다" 는 뜻이고, 둘을 같게 적으면 안 된다.

**`.claude/` 를 저장소에 올릴지도 정해야 한다.** 이 하네스는 **zip 으로 배포**되고
코어의 정본은 골자 저장소에 따로 있다. 코어를 커밋하면 판이 저장소에 박제되고,
사람마다 다른 시점의 zip 을 올려 **저장소가 판 충돌 지점**이 된다.

그렇다고 전부 빼면 **프로젝트가 채운 것이 공유되지 않는다** — 스코프·리뷰 기준·사고 이력이
사람마다 달라진다. **코어는 빼고 프로젝트 소유만 올린다.**

```gitignore
# 코어는 zip 으로 배포된다 — 저장소에 올리지 않는다
.claude/*
# 프로젝트가 채우는 것만 올린다
!.claude/config/
.claude/config/presets/
!.claude/rules/
!.claude/docs/
.claude/docs/agents/
.claude/docs/examples/
.claude/docs/profile/
# project-rules.md 는 skills/ 밑에 있지만 프로젝트 소유다 — 예외를 한 겹씩 뚫는다
!.claude/skills/
.claude/skills/*
!.claude/skills/code-review/
.claude/skills/code-review/*
!.claude/skills/code-review/references/
.claude/skills/code-review/references/*
!.claude/skills/code-review/references/project-rules.md
```

- 2026-09-02 실측 — 이 규칙으로 프로젝트 소유 6종이 전부 추적되고 코어는 전부 빠진다.
- ⚠ **`stack.yaml` 의 `toolPaths`·`env` 에는 PC 경로가 들어간다.** 파일째 공유되면 그 값이 올라간다.

**산출물 무시 수단은 `vcs.kind` 로 갈린다.** `.gitignore` 는 git 에서만 듣는다 —
svn 프로젝트에 그 파일을 만들면 파일만 하나 늘고 그것도 버전 관리에 들어간다.

| `vcs.kind` | 수단 |
|---|---|
| `git` | `.gitignore` 에 한 줄씩 추가 |
| `svn` | `svn propset svn:ignore -F {목록파일} {대상}` — **대상이 버전 관리에 들어간 뒤에** 건다. 안 그러면 `E155010` 이 난다 |
| `none` | 할 것 없음 |

- svn 은 미추적 파일을 `?` 로 보여주고 사용자가 `svn add *` 를 하면 쓸어 담는다.
  `.claude/harness-friction.jsonl` 에는 차단된 경로가 그대로 들어 있다 — **로컬 전용으로 둔다.**

**"남은 일" 은 비어 있어도 적는다.** 이 스킬이 만들지 않는 파일들이라
적어 두지 않으면 아무도 모른 채 지나간다. `.gitignore` 가 없는 저장소에서는
산출물이 그대로 커밋 후보가 된다.

## 안 하는 것

- **`settings.json` 을 만들지 않는다.** 권한·훅은 프로젝트 소유다.
  필요하면 `.claude/settings.json.example` 을 참고하라고 안내만 한다.
- **`CLAUDE.md` 를 채우지 않는다.** 프로젝트 개요는 사람이 쓰는 것이다.
  루트에 없으면 `CLAUDE.md.template` 을 복사하라고 안내한다.
- **소스 코드를 고치지 않는다.** 이 스킬이 쓰는 것은 `config/` 3개와 권고 문서의 표식 줄뿐이다.
- **`.gitignore` 를 만들거나 고치지 않는다.** 8단계 보고의 "남은 일" 에 적어 사용자가 하게 한다.
  저장소 루트 파일이라 프로젝트 관례가 있을 수 있고, 이 스킬이 판단할 일이 아니다.
- **`docs/guideline/*.md` 의 프로젝트 절을 추측해 채우지 않는다.**
  없는 규칙을 근거로 리뷰가 지적하게 된다. 공통 절을 쓰는 상태로 두고 표식만 바꾼다.

## 막혔을 때

| 상황 | 대응 |
|---|---|
| 프리셋에 없는 스택 | `none.yaml` 로 연동을 끝내고, 빌드·테스트를 `false` 로 둔다. 그 사실을 보고한다. 나중에 개발자가 채우면 된다 |
| 빌드 파일이 여러 개 (다중 모듈) | `projects[]` 를 나눠야 한다. 모듈 목록을 사용자에게 확인받는다 |
| 소스 루트를 못 찾음 | 사용자에게 "코드가 어느 폴더에 있나" 를 묻는다. 이건 답할 수 있는 질문이다 |
| `--verify-commands` 가 계속 실패 | 그 항목만 `enabled: false` 로 내리고 보고한다. **연동 자체를 막지 않는다** |

**연동을 완벽하게 만들려고 사용자를 붙잡지 않는다.**
빌드가 `false` 여도 하네스의 절차·리뷰·인수인계는 그대로 돈다.
나중에 채우는 것이 처음부터 막히는 것보다 낫다.
