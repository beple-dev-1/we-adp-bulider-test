# Phase 0-1 기본 정보 수집 체크리스트

> dev-interview SKILL.md Phase 0-1 단계 진입 시 lazy Read.
> 5항목을 **1개씩 순서대로** 1:1 질문.

## skip 판정 (좁게 본다)

사용자가 한 번에 여러 정보를 줬으면 **명시적으로 값을 준 항목만** skip 한다.

- **없다고 단정하지 않는다.** 언급이 없는 것과 "없다" 고 말한 것은 다르다.
- 특히 **항목 5(기획서 경로)는 "없음" 이라는 말을 직접 듣기 전까지 skip 하지 않는다.**
  기획서를 없다고 단정하면 자율 선탐색이 요구사항을 모르는 채로 돈다.
  **잘못 단정한 비용(선탐색 3종 재실행)이 한 번 묻는 비용보다 훨씬 크다.**
- 앞선 대화에 값이 있어 보여도 확신이 없으면 **가설로 제시하고 확인만 받는다** —
  "기획서는 없는 것으로 보고 진행할까?" 한 줄이면 된다.

## 묻지 않아도 되는 항목 (환경이 답을 정한다)

**답이 하나뿐인 질문은 하지 않는다.** 사용자를 붙잡아 세우고 얻는 것이 없다.

| 항목 | 안 묻는 조건 | 대신 |
|---|---|---|
| 1 프로젝트 | `projects[]` 가 **1개** | 그것으로 정한다. `AskUserQuestion` 은 선택지 2개 이상을 요구해 **호출 자체가 불가능하다** |
| 2 과업번호 | 언제나 | `{outputDir}/works/` 를 훑어 **다음 번호를 제안**하고 확인만 받는다 |
| 3 작업 브랜치 | `vcs.kind` 가 `svn`·`none` 이거나 `vcs.defaultBranch` 가 `none` | 브랜치 개념이 없다. "없음" 으로 두고 넘어간다 |

- 1번은 **규정을 지킬 수 없는 형태였다.** 단일 모듈이 오히려 흔한 쪽인데(이 하네스의 대상은
  비개발자·작은 프로젝트다) 그 경우가 정의돼 있지 않았다 (2026-09-01 실측).
- 건너뛴 항목은 **무엇으로 정했는지 한 줄 알린다.** 조용히 넘기지 않는다.
- 남는 질문은 **개요**와 **기획서 유무** 둘이다. 이 둘은 사람만 아는 것이 맞다.

## 질문 항목

| 순서 | 항목 | 용도 | 전달 방식 |
|------|------|------|------|
| 1 | **개발 대상 프로젝트** | 자동 매칭 대조 | `AskUserQuestion` — options = `{{config.projects[].name}}` |
| 2 | **과업번호** | `taskId` (출력 파일명) | 텍스트 (예: 057, 1234) |

| 4 | **개요** | 인터뷰 출발점 | 텍스트 (한두 문장) |
| 5 | **기획서 파일 경로** | Phase 0-2 입력 | 텍스트 (없으면 "없음") |

## 질문 형식

**항목 1 (프로젝트)** — `AskUserQuestion` 1질문 호출:

```jsonc
{
  "questions": [{
    "header": "프로젝트",
    "question": "개발 대상 프로젝트가 어디인가요? (project.yaml 인벤토리 — 걸치면 여러 개 골라도 된다)",
    "multiSelect": true,
    "options": [
      { "label": "{projects[0].name}", "description": "{shortName / role 1줄}" },
      { "label": "{projects[1].name}", "description": "..." }
      // ... 최대 4개
    ]
  }]
}
```

> - options = `{{config.projects[].name}}`. 인벤토리가 4개 초과면 도구 4옵션 제한에 맞춰 **빈도·맥락상 후보 우선 노출** + 나머지는 자동 "Other" 선택지로 흡수.
> - 사용자가 Other 선택 시 자유 입력값을 프로젝트명으로 사용 (다시 묻지 않음).
> - **`multiSelect: true` 다.** 서버와 화면처럼 한 과업이 여러 프로젝트에 걸치는 경우가 흔하다.
>   단일 선택으로 받으면 나중에 기획서·코드를 보고 "사실 걸치는 것 아니냐" 를 되묻는 라운드를 쓰게 된다.
> - 복수로 답하면 브리프 §2 `프로젝트명` 에 전부 적고, §3-1 Primary 를 프로젝트별로 나눠 쓴다.
>   `/develop` 스코프도 그만큼 열린다(`A+B`).

**항목 2~5** — 텍스트 1:1 질문 (선택지 없음). 근거 1줄 제시 후 질문.

## 종료 후 자동 인계

5항목 답변 누적 완료 시 **사용자 확인 없이** 다음 단계로 즉시 인계:

- 기획서 파일 있음 (5번 ≠ "없음") → Phase 0-2 기획서 읽기. `.md`·`.txt` 는 직접 Read,
  그 밖의 형식은 사용자에게 텍스트 추출본을 요청하고 **받을 때까지 선탐색을 시작하지 않는다**.
  읽기가 끝나면 자율 선탐색 자동 트리거.
- 기획서 파일 없음 → Phase 0-2 skip. 자율 선탐색 즉시 자동 트리거.

> "탐색 시작해도 될까요?" / "다음 단계로 갈까요?" 컨펌 질문 금지. 5항목 답변 자체가 트리거.
