# /harness-review

하네스(`.claude/`) 자가검증 **오케스트레이터**. 제품 개발 파이프라인(`/dev-interview … /git`)과 분리된 하네스 전용 루프의 ②사이클 종료 분석·제안 단계다. 단독 실행과 `/pack` 위임 호출 양쪽으로 동작한다.

## 0. 원칙 (위반 금지)

> **자기검토는 독립검증이 아니다.** 결정론 스크립트(`check-harness-consistency.sh` · `check-workflow-artifacts.sh`)만 신뢰 가능한 게이트이고, LLM 판단(설계 적합성)은 **제안에 머문다**. 최종 결정은 항상 사람 컨펌.

- **자가분석 → 자동적용 직결 금지.** 결정론 게이트 + 사람 항목별 컨펌이 유일한 안전장치다.
- 적용·커밋을 사람 승인 없이 진행하지 않는다. 커밋은 직접 하지 않고 `/git` 에 위임한다.
- 모든 `.claude/` 편집은 `base-rule.md` 의 **「하네스 파일 수정」** 절에 따라 **파일별로 (1)대상 (2)변경 전/후 diff (3)영향 제시 → 확인 → 적용** 순서로만 한다.
- 검증 안 된 제안은 `테스트 필요`로, 소스 트리 없이 판단 불가한 항목은 `검증 불가(소스 없음)`로 **명시**한다. 추측을 사실로 확정하지 않는다.

## 절차

### 1단계 — 결정론 게이트 (신뢰 기준)

`check-harness-consistency.sh` 를 실행한다.
직후 `check-workflow-artifacts.sh` 를 병행 실행한다 — 워크플로 산출물 검사(P2). 두 스크립트는 같은 평문 형식을 내므로 아래 소비 규칙을 동일하게 적용한다.

```
bash .claude/scripts/check-harness-consistency.sh
bash .claude/scripts/check-workflow-artifacts.sh
```

**출력은 JSON 이 아니라 평문이다.** 두 스크립트 다 `bash` 만으로 돌도록 만들어져 있어
`jq`·`node`·`python` 에 의존하는 형식을 내지 않는다. 아래 두 가지만 읽으면 된다.

| 읽을 것 | 형식 |
|---|---|
| 항목별 결과 | `PASS` \| `FAIL` \| `WARN` \| `SKIP` 로 시작하는 행 — `{상태}  {검사이름}  {설명}` |
| 전체 판정 | 마지막 `RESULT: PASS` \| `RESULT: FAIL` 줄. 종료 코드도 같이 본다 |

- `FAIL` 행이 있으면(= `RESULT: FAIL`) **그 행을 가공 없이 그대로 보고**한다. `검증됨`(결정론) 신뢰도다.
- `WARN` 행은 `검토 권고` 로 보고한다. 판정을 뒤집지 않는다.
- `SKIP` 행은 `검증 불가` 로 표기한다 — 검사 대상 파일이 없어 건너뛴 것이며 `FAIL` 이 아니다.
- 두 스크립트 결과를 한 표에 합쳐 보고한다. 어느 스크립트에서 나온 행인지 밝힌다.
- 점검 범위는 스크립트가 정본이다. **이 문서에 검사 목록을 복사해 두지 않는다** —
  검사를 늘리거나 뺄 때 문서가 따라오지 않아 실제와 어긋난다(2026-08-31 실측 —
  이 자리에 있던 목록이 존재하지 않는 검사 이름을 가리키고 있었다).
  지금 무엇을 검사하는지는 실행 결과의 검사 이름으로 확인한다.
- `check-workflow-artifacts.sh` 는 워크플로 산출물 고리(결과서 ⟹ 계획서 ⟹ 브리프)를 본다.
  산출물 경로는 `project.yaml` 의 `outputDir` 기준이며 로컬 전용이다.

### 2단계 — 마찰 로그 집계

`harness-friction.jsonl`(로컬 전용·JSONL, 없을 수 있음)을 읽어 **type 별로 집계**한다.

> **로그가 없으면 먼저 훅이 배포됐는지 본다.** 훅을 안 깔면 이 단계는 항상 "마찰 없음" 을 낸다 —
> 마찰이 없는 것이 아니라 **수집하는 주체가 없는 것**이다. 이 둘을 같은 결과로 보고하지 않는다.
>
> ```bash
> ls .claude/settings.json .claude/hooks/friction-log.sh 2>/dev/null
> grep -q 'friction-log' .claude/settings.json 2>/dev/null && echo '훅 등록됨' || echo '훅 미등록'
> ```
>
> 미등록이면 `.claude/settings.json.example` 의 `hooks` 블록을 `settings.json` 으로 옮기라고 안내하고,
> **이번 집계는 "수집 안 됨"** 으로 보고한다.

각 줄은
`{ts,type,path,…}` JSON 객체다. `path` 는 이를 기록한 훅이 이미 슬래시로 정규화해 둔 값이며,
이 스킬은 stdin `tool_input` 경로를 직접 파싱하지 않으므로 별도 역슬래시 정규화가 필요 없다
(역슬래시 이슈는 stdin 을 받는 훅에 국한된 사안이다 — Phase C 발견).

```bash
if [ -f .claude/harness-friction.jsonl ]; then
  # type 별 건수. 콜론 뒤 공백 유무가 기록 주체(훅 echo vs LLM JSON.stringify)마다 달라
  # grep 원문을 그대로 세면 같은 type 이 두 줄로 갈린다 → sed 로 값만 추출해 정규화한다.
  grep -oE '"type":[[:space:]]*"[^"]+"' .claude/harness-friction.jsonl \
    | sed 's/.*"type":[[:space:]]*"\([^"]*\)".*/\1/' | sort | uniq -c
  echo "총 마찰 수: $(wc -l < .claude/harness-friction.jsonl)"
  grep -c '"resolved":' .claude/harness-friction.jsonl || true   # 해소 표기 건수
else
  echo "(마찰 로그 없음)"
fi
```

- **집계는 type-agnostic 이다.** 아래에 없는 type 이 나와도 그대로 집계된다.
  type 목록을 여기에 고정해 두지 않는다 — 생산자가 늘면 이 문서가 따라오지 않아 거짓이 된다.
  **지금 무엇이 실제로 기록되는지는 로그를 집계해 보면 된다.**

  생산 주체는 둘이고, **신뢰도가 다르다.**

  | 주체 | 어디서 | 신뢰도 | 대표 type |
  |---|---|---|---|
  | 훅 (결정론) | `.claude/hooks/friction-log.sh` — 실제 도구 호출을 보고 기록 | `검증됨` | `file-access-block`(`path`) · `bash-secret-block`(`pattern`) · `dml-block`(`keyword`) · `business-table-block`(`table`) |
  | LLM 자가 기록 | `/pack` 5단계 등 — 세션이 스스로 적음 | **`테스트 필요`** | `process-deviation`(`rule`·`detail`) · `config-not-consulted`(`detail`) · `method-quality`(`rule`·`detail`) |

  - 훅이 실제로 내는 type 은 그 스크립트의 `emit` 호출이 정본이다.
  - **LLM 자가 기록은 사실로 확정하지 않는다.** 세션이 자기 행동을 스스로 판정한 것이므로
    훅 기록과 같은 무게로 다루면 안 된다. 보고 시 주체를 갈라 적는다.
  - `.claude/*.json` 구문 오류는 훅이 판정하지 않는다 —
    `check-harness-consistency.sh` 의 `settings-json` 검사가 파일을 직접 읽어 판정한다(더 정확하다).
  - type 별 건수 + 대표 사례를 요약한다.
- **`resolved` 필드 규약**: 항목에 `"resolved":"YYYY-MM-DD"`(+`"resolution":"…"`) 필드가 있으면
  **해소된 마찰**이다. 집계 시 미해소분과 분리하여 "해소됨 N건"으로만 보고하고,
  3단계 재제안 대상에서 제외한다. 해소 표기는 적용·확인 완료 시점에 해당 줄에 필드를
  추가하는 방식으로 한다(줄 삭제 금지 — 이력 보존).
- 로그 파일이 **있는데** 비어 있으면 "마찰 없음 — 이번 사이클 차단·오류 신호 없음"으로 보고한다.
- 로그 파일이 **아예 없으면** "수집 안 됨 — 훅 미배포"로 보고한다. 위 확인 절차를 따른다.
- 총 건수가 임계(예: 100건)를 넘으면 안내 1줄만 덧붙인다(자동 회전·삭제 없음 — 사람이 판단).
- ⚠️ v1 한계: "직전 review 이후분"만 보는 증분 워터마크는 두지 않는다 — 전체 로그를 집계하며, 사람이 신규 여부를 판단한다(증분 추적은 후속 과제).

### 3단계 — 설계 적합성 분석 (제안, best-effort · LLM)

1·2단계 결과와 `.claude/` 설정을 근거로 개선을 **제안**한다. 이 단계 산출물은 전부 `테스트 필요`(LLM 판단) 신뢰도다.

- 예: 마찰 로그에 반복되는 차단 → 정책·allow[] 재검토 제안 / `warn` 비대칭 → 문서화 또는 대칭화 제안 / 설정 간 의미적 불일치(결정론 검사가 못 잡는 것) 제안.
- **소스 대조가 필요한 항목**(예: `scope.yaml` 의 allowedPaths 가 실제 소스 트리와 맞는가)은 작업 트리가 있어야만 판단 가능하다. 없으면 `검증 불가(소스 없음)` 로 낸다.

### 4단계 — 출력 (그리고 정지)

아래를 **항목별**로 출력하고 **정지**한다. 자동으로 다음 단계(적용)로 넘어가지 않는다.

| 항목 | 근거(파일·로그·스캔) | 신뢰도 | 제안 변경 (변경 전 → 후 diff) |
|------|----------------------|--------|-------------------------------|
| … | … | `검증됨`/`검토 권고`/`테스트 필요`/`검증 불가(소스 없음)` | … |

- `검증됨` = 결정론 게이트(1단계) 결과. `검토 권고` = 결정론 `warn`. `테스트 필요` = LLM 제안(3단계). `검증 불가(소스 없음)` = 워킹카피 부재.
- 변경 제안이 있는 항목은 변경 전/후를 diff 수준으로 제시한다.

### 5단계 — 항목별 컨펌 → 적용 → 커밋 위임

- 사용자가 **항목별로** 승인/보류/거부한다.
- **승인된 항목만** `.claude/` 에 적용한다. 각 파일은 `base-rule` 대로 (대상·diff·영향) 제시 → 확인 → 적용.
- 적용 후 커밋은 **직접 하지 않고 `/git` 에 위임**한다: `/git` 이 `config/stack.yaml` 로 레포를 라우팅하고, 하네스는 `harness/{작업명}` 피처 브랜치 → `[harness] TYPE : …` 커밋 → push → PR/MR → squash 머지 순서로 처리한다. **기본 브랜치 직접 push 금지, 하네스 파일만 명시 staging**(`git add -A`/`git add .` 금지).
  스테이징 뒤 `git diff --cached --name-only` 로 `.claude/` 밖 파일이 안 섞였는지 확인한다 — 규칙의 실체는 이 확인이다.
- 승인 항목이 없으면 적용 없이 종료한다(결정론 게이트 결과 보고만으로도 유효한 실행이다).

## 호출 맥락

- **단독**: 사용자가 하네스 점검을 요청할 때.
- **위임**: `/pack` 사이클 종료 안내에서 선택적으로 호출(강제 자동 실행 아님).
- 산출되는 **`.claude/` 개선분만** 하네스 레포(`/git` 이 `config/stack.yaml` 로 호스트 라우팅 — GitHub/GitLab 무관)에 커밋된다. 마찰 로그·`HANDOFF*.md` 는 로컬 전용으로 어느 레포에도 올리지 않는다(decision #1 과 일치).
