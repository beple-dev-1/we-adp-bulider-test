# 테스트 기준

---

## 무엇을 테스트 러너로 검증하는가

프레임워크마다 러너로 갈 수 있는 깊이가 다르다. 그 경계는 `config/stack.yaml` 의
`test.scopeNote` 가 정의한다. 하네스는 경계를 가정하지 않는다.

- 컨테이너·서버 없이 실행되는 코드는 러너로 검증한다.
- 그렇지 않은 코드는 **실행 환경 검증**으로 넘긴다. 러너로 억지로 감싸지 않는다.
- 경계가 어디인지 모르면 사용자에게 묻고 `scopeNote` 에 적는다. 추측으로 진행하지 않는다.

## 테스트 작성

- 테스트 이름은 `{행위}_{상황}_{기대결과}` 형태로 쓴다. 무엇이 깨졌는지 이름만 보고 알게 한다.
- 테스트 하나가 하나를 검증한다.
- 실패를 재현하는 테스트를 먼저 만들고 고친다.
- 통과시키기 위해 단정을 느슨하게 바꾸지 않는다.

## 실행 환경 검증

`config/stack.yaml` 의 `runtime` 설정을 따른다.

| 항목 | 확인할 것 |
|---|---|
| 정상 흐름 | 실제 입력으로 기대 결과가 나오는가 |
| 입력 오류 | 필수값 누락·형식 오류에 정의된 오류가 나오는가 |
| 경계값 | 한도·잔액·개수의 경계에서 판정이 맞는가 |
| 중복 요청 | 같은 요청을 두 번 보내도 한 번만 처리되는가 |
| 인증 | 미인증·만료 상태에서 차단되는가 |
| 외부 연동 | 타임아웃·비정상 응답·빈 응답을 처리하는가 |
| 시드 데이터 | 초기 데이터를 쓰면 그것이 실제로 조회되는가 (스키마만 보고 넘기지 않는다) |

- 요청은 `runtime.baseUrl` 로만 보낸다. **운영 환경으로는 보내지 않는다.**
- **기동 명령을 백그라운드로 돌릴 때는 `env`·`toolPaths` 를 그 명령줄에 직접 붙인다.**
  셸에서 `export` 한 값은 백그라운드 서브셸로 넘어가지 않아, 기동이 조용히 실패한다
  (`command not found` 가 로그에만 남고 검증은 연결 실패로만 보인다).
- **한글·비ASCII 본문은 셸 인라인으로 보내지 않는다.** 윈도우 셸은 시스템 코드페이지로
  내보내 서버가 인코딩 오류로 거절한다. UTF-8 파일로 저장한 뒤 파일을 지정해 보낸다
  (`curl --data-binary @본문.json`). 앱을 의심하기 전에 이것부터 확인한다.
  - ⚠ **이것은 HTTP 요청 본문에 대한 규칙이다. 일반화하지 않는다** — 도구마다 방향이 반대일 수 있다.
    svn 커밋 메시지는 오히려 `-m` 인라인이 맞고, `-F` 파일은 `--encoding UTF-8` 이 필요하다
    (`skills/git/references/commit-convention.md`).
- **띄운 서버는 그 단계가 끝나면 반드시 내린다.** 안 내리면 다음 단계가 통째로 막힌다
  (파일 DB 를 쓰는 프로젝트는 단일 프로세스 제한이라 러너가 락 충돌로 죽는다).

  | `runtime.stopCommand` | 하는 것 |
  |---|---|
  | 실제 명령 문자열 | 그 명령으로 내린다 |
  | `none` 또는 빈 값 | **명령을 실행하지 않는다.** 프로세스를 직접 찾아 내린다 |

  `none` 은 "안 쓴다" 는 뜻이다(하네스 전체 규약). **문자열 `none` 을 명령으로 실행하지 않는다** —
  `command not found` 가 나고 서버는 그대로 떠 있어, 다음 단계가 락으로 막힌다.
- ⚠ **빌드 도구가 자식 프로세스를 분리 실행하는 경우가 있다** (`mvn spring-boot:run`·
  `gradle bootRun` 등). **부모만 죽이면 자식이 orphan 으로 남아** 포트와 파일DB 락을 계속 점유한다.
  **포트가 실제로 닫혔는지 확인한다** — 프로세스를 죽인 것으로 끝났다고 보지 않는다.

  ```bash
  curl -s -o /dev/null --max-time 2 -w "%{http_code}\n" {baseUrl}   # 000 이면 닫힌 것
  ```

- **파일 DB 를 쓰는 프로젝트에서 서버를 강제 종료하면 시퀀스·캐시가 건너뛸 수 있다.**
  H2 는 IDENTITY 를 블록 단위로 캐시해서, 강제 종료 뒤 다음 id 가 수십 건너뛴다.
  **id 가 튀는 것을 데이터 오염이나 테스트 누수로 오해하지 않는다** — 원인 추적에 시간을 쓰게 된다.
- **검증용으로 만든 데이터는 지울 수단을 함께 정한다.** 파일 DB 는 재기동해도 남고,
  `protectedPaths` 라 AI 가 파일을 지울 수 없는 경우가 많다. 삭제 API 가 있으면 그것을 쓴다.
- 검증 도구(스크립트·컬렉션)는 세션마다 사용자에게 확인한다. 하네스는 특정 도구를 전제하지 않는다.

## 화면 검증

- 화면 주소는 `runtime.frontendUrl` 이 비어 있으면 `runtime.baseUrl` 을 쓴다
  (백엔드가 화면을 함께 서빙하는 구조).
- 값 검사만으로 통과 판정하지 않는다. **렌더를 눈으로 확인한다.**
- 스크린샷은 `runtime.screenshotDir` 에 남긴다. 값이 비어 있으면 남기지 않고,
  대신 무엇을 눈으로 확인했는지 결과서에 문장으로 적는다. **VCS 에는 올리지 않는다.**
  값은 정상인데 화면만 깨지는 경우가 있다.
- 화면 일부를 갈아끼우는 경우 **모든 진입 경로**를 확인한다 — 최초 진입 / 인플레이스 갱신 / 닫고 재진입.
- 화면을 백엔드가 함께 서빙하는 구조라면, 화면을 고친 뒤 **빌드 + 리소스 재복사(또는 재기동)**
  까지 해야 반영된다. 빌드만 하고 확인하면 이전 화면을 보게 된다.
- 스크린샷이 예상과 다르면 **캐시를 먼저 의심한다.** 서버가 주는 자원과 DOM 의 계산된 스타일·
  좌표를 확인해 실제 적용 여부를 가른다 — 정상 수정을 실패로 오판해 두 번 고치는 일을 막는다.
- 스크롤 위치·포커스가 유지되는지 본다.

## 트랙2 는 언제 하는가 — 이 문장이 정본이다

`stack.vcs.commitDeploys` 값 하나로 갈린다. **다른 문서가 다르게 말하면 이 문장을 따른다.**

| `commitDeploys` | 순서 |
|---|---|
| `false` (git+PR 등) | 트랙1 → **트랙2** → `/code-review` → 커밋 |
| `true` (커밋=배포) | 트랙1 → `/code-review` → 커밋 → **트랙2** → (실패 시 수정·재커밋) |

- `false` 인데 트랙2 를 커밋 뒤로 미루지 않는다. 미룰 이유가 없고, 깨진 것을 커밋에 남기게 된다.
- `true` 는 배포해야 확인할 수 있는 구조라 트랙2 가 뒤로 밀리는 것이 정상이다. 대신 리뷰를 생략하지 않는다.

## 완료 기준 (DoD)

경계는 커밋이 아니라 **검증 수단**이다.
`stack.vcs.commitDeploys: true` 인 프로젝트에서는 트랙2가 커밋 후로 밀린다.

### 트랙1 — 러너·정적 검사

- [ ] `/code-review` 실행 후 CRITICAL 0건
- [ ] 빌드·컴파일 통과 (`stack.build.compileCommand`)
- [ ] **정적 검사 통과** (`stack.lint.command`) — `lint.enabled: false` 면 건너뛰고 그 사실을 결과서에 남긴다
- [ ] 러너 범위(`test.scopeNote`) 안의 로직에 테스트가 있고 전부 통과
- [ ] 호출 반환값 검사 누락 없음
- [ ] 환경 값이 설정으로 분리돼 있음
- [ ] 컨벤션 준수

### 트랙2 — 실행 환경

- [ ] 정상 흐름과 주요 오류 케이스를 실제로 확인
- [ ] 화면을 변경했으면 렌더를 확인
- [ ] 실패 시 수정 → `/code-review` → (커밋 전이면 재검증 / 커밋 후면 재커밋) 루프백 완료
- [ ] **트랙2 완료 전에는 과업 미완료** — 미완 상태로 `/pack` 에 들어가지 않는다

#### 예외 — 검증 수단이 아예 없을 때 (이 절이 정본이다)

위 항목은 **확인할 수단이 있는데 안 한 것**을 막는 규칙이다. 수단이 없는 경우까지 막지 않는다.
막으면 빠져나갈 길이 없어지고, 길이 없는 규칙은 무시된다. **무시되는 것이 더 나쁘다.**

- 해당하는 경우 — `runtime.browser: true` 인데 이 세션에 브라우저·스크린샷 도구가 없다.
- 갈 수 있는 데까지 간다 — 값 검사 · `curl` 상태코드 · 딥링크 확인.
- 그러고도 못 한 것은 **못 했다고 결과서에 그대로 적는다.** 판정은 `GREEN(조건부)` 로 쓰고
  요약에 한 줄을 넣는다 — `- 미검증: 화면 렌더 (브라우저 도구 없음) → 별도 검증 항목으로 등록`
- **이 표기가 있으면 `/pack` 에 들어가도 된다.**
- 남은 검증 항목은 **`HANDOFF.md` 의 다음 단계로 옮겨 적는다.** 거기서 사라지면 안 한 것이 된다.
- 수단이 생기면 그때 확인한다. **조건부 완료는 면제가 아니라 이월이다.**

### 건너뛴 항목 처리

- `stack` 설정에서 `enabled: false` 로 꺼둔 항목은 건너뛰어도 된다.
- 단 **건너뛴 사실을 결과서에 남긴다.** 하지 않은 것을 한 것처럼 쓰지 않는다.
