# 화면 코딩 지침 (프로젝트가 채우는 파일)

`config/project.yaml` 의 `guideline.frontend` 에 이 파일 경로를 적으면 `/develop` 이 읽는다.
비워두면 지침 없이 진행하고, 그 사실이 세션 시작 요약에 표시된다.

---

## 공통

### 구조

- 화면 하나가 파일 하나다. 한 파일에 여러 화면을 넣지 않는다.
- 재사용되는 조각은 컴포넌트로 뺀다. 복사해서 두 곳에 두지 않는다.
- 공통 레이아웃·헤더가 있으면 반드시 그것을 쓴다. 새로 만들지 않는다.

### 데이터

- 서버 응답 형태를 화면에서 임의로 가정하지 않는다. 빈 값·널을 항상 처리한다.
- 비동기 호출에는 로딩·실패·빈 결과 세 상태를 만든다.
- 실패 메시지는 사용자가 다음 행동을 알 수 있게 쓴다. 코드만 노출하지 않는다.

### 안전

- 사용자 입력·서버 응답을 이스케이프 없이 마크업에 넣지 않는다.
- 화면 검증은 편의다. 같은 검증이 서버에도 있어야 한다.
- 토큰·개인정보를 URL 쿼리나 로컬 저장소에 남기지 않는다.

### 스타일

- 색·간격은 토큰·변수를 쓴다. 값을 직접 쓰지 않는다.
- 인라인 스타일은 동적 값에만 쓴다.

### 확인

- 화면을 바꿨으면 **렌더를 눈으로 본다.** 값 검사만으로 통과 판정하지 않는다.
- 화면 일부만 갈아끼우는 경우 최초 진입 / 갱신 / 닫고 재진입 세 경로를 모두 본다.
