`config/project.yaml` 의 `guideline.backend` 에 이 파일 경로를 적으면 `/develop` 이 읽는다.
비워두면 지침 없이 진행하고, 그 사실이 세션 시작 요약에 표시된다.

아래 "공통" 은 스택과 무관하므로 그대로 둬도 된다.
"프로젝트" 절의 주석을 풀고 이 코드베이스의 실제 관용구로 바꾼다.

---

## 공통

### 계층

- 요청 처리 → 업무 로직 → 데이터 접근 순서를 지킨다. 건너뛰지 않는다.
- 업무 로직에서 요청·응답 객체를 직접 다루지 않는다.
- 데이터 접근 코드가 업무 판단을 하지 않는다.

### 트랜잭션

- 경계를 업무 로직 한 곳에서 연다. 여러 곳에서 겹쳐 열지 않는다.
- 트랜잭션 안에서 외부 API 를 호출하지 않는다. 응답이 늦으면 커넥션이 묶인다.
- 외부 호출이 필요하면 트랜잭션을 끊고, 실패 시 보상 처리를 설계한다.

### 실패 처리

- 호출 결과를 검사하지 않고 다음 단계로 넘기지 않는다.
- 예외를 잡으면 로그와 함께 무엇을 할지 정한다. 삼키지 않는다.
- 재시도는 멱등이 보장될 때만 넣는다.

### 로그

- 실패 로그에는 **판단 근거가 되는 값**을 남긴다 (식별자·상태·응답 코드).
- 개인정보·토큰·카드번호는 남기지 않는다. 마스킹하거나 식별자만 남긴다.
