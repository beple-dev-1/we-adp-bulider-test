# 보안 정책 (공통)

모든 에이전트가 준수해야 하는 보안 규칙이다.

## 절대 금지 항목

### 운영 설정 접근
- 운영 환경 설정 파일 읽기·수정 금지 (경로 목록은 `config/scope.yaml` 의 `protectedPaths`)
- **운영 배포 설정 파일 읽기·수정 금지.** 무엇이 그것인지는 `config/scope.yaml` 의 `protectedPaths` 가 정본이다
  (흔한 형태 — `*.prod.*` · `*.real.*` · `application-prod.*`).
- 시크릿이 담긴 설정 파일 읽기·수정 금지 (API 키·암호화 키·DB 접속 정보)
- **서명 키·인증서가 평문으로 든 파일 읽기·수정 금지** (`*.pem` · `*.p12` · `*.jks` · `*.keystore` 등).
  값이 필요하면 파일을 열지 않고 사용자에게 직접 요청한다.
- `.env`, `.env.*` 파일 읽기·수정 금지

### 보안 자산 접근
- `*.pem`, `*.p12`, `*.jks`, `*.keystore` 파일 접근 금지
- `id_rsa`, `id_rsa.pub` 접근 금지
- `credentials.json` 접근 금지

### 암호화 값 처리
- 암호화된 값을 코드 내에서 복호화 시도 금지
- JWT 시크릿, 암호화 키를 코드·주석에 하드코딩 금지

### 실제 데이터 처리
- 회원 개인정보(이름, 연락처, 주민번호, 계좌번호)를 코드나 테스트에 삽입 금지
- 실제 업무 데이터(거래 내역, 혜택 지급 이력)를 DB에서 직접 조회 금지

### DB 변경
- INSERT, UPDATE, DELETE, DROP, ALTER, TRUNCATE 쿼리 실행 금지
- DB 스키마 변경(테이블·컬럼·인덱스 추가·변경)은 DBA가 직접 수행한다 — Claude가 DDL을 임의로 실행하지 않는다

## 허용 예외
- 개발·로컬 환경 설정 파일 — 시크릿이 없다면 읽기 허용 (프로파일에서 판단)
- `.claude/` 내 하네스 설정 파일
- DB 메타 조회 (`information_schema`, `pg_catalog`): 테이블·컬럼·인덱스 구조 확인 한정
