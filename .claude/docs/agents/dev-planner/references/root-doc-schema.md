# 개발 계획서 루트 문서 형식

`{{config.outputDir}}/plans/{과업번호}/{과업번호}_dev_plan.md` 파일의 섹션 형식이다.

> **단일 출처(SSOT)** — dev-planner 절차·소비자(dev-frontend `§5-1`, develop)가 본 형식을 신뢰한다. 섹션 번호를 임의로 바꾸지 않는다.

```markdown
# 개발 계획서

| 항목 | 내용 |
|------|------|
| 과업번호 | {N} |
| 제목 | {과업 제목} |
| 작성일 | {YYYY-MM-DD} |
| 작성자 | AI (검토: {담당자}) |
| 대상 스코프 | {`config/scope.yaml` 의 `scopes[].id`. 둘 이상이면 `+` 로 잇는다} |
| VCS 경로 | trunk (브랜치 미사용) |

## 1. 과업 개요
{목적과 배경}

## 2. 기능 요구사항
- [ ] {요구사항 1}
- [ ] {요구사항 2}

## 3. 대상 스코프 및 허용 경로
### 3-1. Primary (쓰기 대상)
{scope.yaml 기준 허용 경로 — 실제 수정 대상}
### 3-2. Related (읽기·참조)
{읽기만 하는 관련 경로}
### 3-3. 패턴 참조
{유사 기존 기존 구현 1~2개 — 구현 시 참조할 패턴 출처}

## 4. 전제·가정
{브리프에서 확정되지 않았거나 보강이 필요한 항목을 가정으로 기록.
 브리프 §N이 비어 있으면 "브리프 §N 보강 후 재계획 필요" 형태로 명시한다.}

{**구현 착수 전에 닫아야 할 결정**은 그 줄 끝에 `<!-- OPEN -->` 표식을 단다.
 `/develop` 6-4 가 이 표식을 찾아 구현 전에 사용자에게 묻는다.

 | 항목 | 지금 상태 |
 |---|---|
 | {닫아야 할 결정} | {왜 아직 못 정했나} <!-- OPEN --> |

 표식을 **자연어 문구 대신 쓰는 이유** — 예전에는 `미확정` 같은 낱말을 grep 했는데,
 한국어는 부정을 어미로 만들어(`미확정 아님`) 부분 문자열이 **부정문을 그대로 집어냈다.**
 닫힌 결정이 열린 것으로 올라오고 진짜 미결은 안 걸렸다(2026-09-01 실측 — 오탐 2건·적중 0건).
 표식은 부정형이 없고 사람이 의도해서 단다.}

## 5. 페이즈 분할
### 5-1. 페이즈 목록 테이블
{R10 적용(풀스택) 시 영역(BE/FE) 컬럼 포함. dev-frontend·develop 가 영역 컬럼으로 디스패치 대상을 판별한다.}

| N | 페이즈명 | 영역 | slug | 포함 §11 단계 | 포함 화면 | 예상 기간 | 의존 페이즈 | 독립 배포 |
|---|---------|------|------|-------------|---------|----------|-----------|---------|
| 1 | {제목} | BE | be | … | (없음) | 2d | — | … |
| 2 | {제목} | FE | fe-{화면} | … | {화면} | 1.5d | 1 | Y |

> R9·R10 미적용(비풀스택) 시 영역·포함 화면 컬럼을 생략한다 (`gate-format.md` 참조).

### 5-2. 분할 근거 (R 규칙 적용 내역)
{어떤 R 규칙이 어떤 분할 결정에 쓰였는지 1~2줄씩. R9·R10 적용/미적용 사유 포함.}

### 5-3. 코드 탐색 결과
{`code-exploration.md` 절차 산출 — 재사용 가능 DB 쿼리·서버 로직·유틸 목록, 신규 생성 대상,
 기존 테이블 사용 표(컬럼 셀은 `column_name (data_type)` 형식, data_type 은 `information_schema.columns` 메타).}

## 6. 데이터·인터페이스 계약
### 6-1. DB 변경사항
{DB 쿼리 신규 등록 여부, DDL 변경(CREATE TABLE/ALTER/INDEX) 여부. 없으면 "없음".}
### 6-2. 공통 모듈 변경사항

| 필드명 | 타입 | 필수 | 검증 | 의미 |
|-------|------|:---:|------|------|
| {field} | {type} | Y/N | {규칙} | {설명} |
```
