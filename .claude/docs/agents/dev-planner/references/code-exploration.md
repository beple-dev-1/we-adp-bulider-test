# 계획 수립 전 기존 코드 탐색 절차

dev-planner 에이전트가 개발 계획서를 작성하기 전에 수행하는 5단계 코드 탐색 절차이다.

## 1단계: 도메인 패키지 탐색
```
{소스 루트}/{모듈}/{도메인}/
```
- 요청 도메인과 관련된 기존 서버 로직 클래스 목록 확인
- 유사 기능의 서버 로직 클래스 식별

## 2단계: DB 쿼리·SVC XML 확인
- `{프로젝트}_ETC/xml/service/DB 쿼리/` — 재사용 가능한 DB 쿼리 목록
- `{프로젝트}_ETC/xml/service/SVC/` — 관련 SVC 목록
- 서비스·모듈 등록 설정 — 이 프로젝트가 그런 등록부를 쓰면 그곳에서 도메인 등록 여부를 확인한다

## 3단계: 공통 모듈 확인
```
{프로젝트}/src/util/
{프로젝트}/src/com/
{프로젝트}/src/cnst/
{프로젝트}/src/enums/
```
- 재사용 가능한 유틸·헬퍼 클래스
- 공통 예외 클래스
- 공통 상수

## 4단계: 도메인 전용 vs 공통 분리 판단

신규 구현할 코드가:
- 향후 다른 도메인에서도 쓰일 것 같으면 → `util/` 또는 `com/` (공통)
- 해당 도메인에만 한정된 비즈니스 로직이면 → `{소스 루트}/{도메인}/`

## 5단계: 탐색 결과 정리

다음 항목을 계획서 작성 전에 문서화한다:
- 재사용 가능한 기존 DB 쿼리·서버 로직 목록
- 수정이 필요한 기존 코드 목록
- 신규 생성이 필요한 DB 쿼리·서버 로직·화면 템플릿 목록
- 공통 모듈 변경 여부
- 외부 도구로 등록·생성하는 산출물 (프로젝트에 그런 도구가 있는 경우)
