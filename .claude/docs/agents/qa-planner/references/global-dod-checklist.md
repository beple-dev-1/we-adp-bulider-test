# 테스트 완료 기준 (Global DoD Checklist)

테스트 계획 "완료"를 인정하기 위한 전체 자가점검 항목이다.

## 필수 항목 (모두 통과해야 완료)

### 기능 검증
- [ ] 모든 TC가 GREEN (통과)
- [ ] 정상 케이스 (Happy Path) TC 포함
- [ ] 경계값 케이스 TC 포함
- [ ] 예외 케이스 TC 포함

### 프로젝트 도메인 필수 검증

**여기에 도메인 항목을 적지 않는다.** 이 파일은 코어 소유라 갱신 때 모든 프로젝트로 전파된다.
돈 흐름이 없는 프로젝트에 "잔액 부족 TC" 를 요구하면 체크할 수 없는 항목이 되고,
체크할 수 없는 항목은 사람이 건너뛰기 시작한다. 그러면 **체크리스트 전체가 죽는다.**

**이 과업의 도메인 요구는 브리프가 정본이다.** 브리프는 과업마다 새로 쓰이므로
프로젝트 소유 슬롯을 따로 만들 필요가 없다.

- [ ] **브리프 §8 특수 요구사항**의 각 항목에 대응 TC 가 있다 (보안·인프라·알림 등)
- [ ] **브리프 §5 코드값 사전**의 신규 코드값마다 그것이 실제로 나오는 TC 가 있다
- [ ] **브리프 §9 미결사항**에서 이번에 확정된 결정마다 TC 가 있다 —
      확정만 하고 TC 를 안 만들면 `/qa-test` 가 계획서 기준으로 돌아 **끝까지 아무도 모른다**
- [ ] **되돌리기 어려운 흐름**(삭제·상태 전이·외부 반영)에 경계·중복·실패 TC 가 있다
- [ ] 중복 요청 TC 포함 (같은 요청을 두 번 보내도 한 번만 처리되는가)
- [ ] 인증·권한 TC 포함 — **해당하는 경우.** 없다고 결정한 프로젝트면 그 사실을 적고 넘어간다
- [ ] 외부 연동 예외 TC 포함 — 해당하는 경우 (타임아웃·비정상 응답·빈 응답)

### 코드 품질
- [ ] `/code-review` 실행 후 CRITICAL 0건
- [ ] 단위 테스트 커버리지: 러너로 검증 가능한 범위 기준 (범위 정의는 `config/stack.yaml` 의 `test.scopeNote`. 그 밖은 런타임 검증으로 넘긴다)
