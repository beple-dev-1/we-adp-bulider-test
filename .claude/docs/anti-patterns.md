# 안티패턴 — 이 프로젝트에서 실제로 사고가 난 것
<!-- HARNESS:UNFILLED — 이 파일을 프로젝트 내용으로 채운 뒤 이 줄을 지운다. 지우면 작성 완료로 본다. -->

`config/project.yaml` 의 `customDocs.antiPatterns` 에 이 파일 경로를 적으면
`/code-review` 와 `code-reviewer` 가 함께 읽는다.

일반론은 적지 않는다. `severity-rules.md` 가 이미 담고 있다.
여기 적는 것은 **이 코드베이스에서 실제로 터진 것**뿐이다.

## 쓰는 형식

```markdown
## AP-{번호} {한 줄 제목}

- 증상: 무엇이 어떻게 잘못됐나
- 원인: 코드상 어디가 문제였나
- 판정: 리뷰에서 무엇을 보면 걸러지나  ← 이 줄이 핵심이다
- 근거: 발생 시점·과업번호
```

`판정` 줄은 **리뷰어가 diff 만 보고 적용할 수 있게** 쓴다.
"주의한다" 는 판정이 아니다. "X 가 있고 Y 가 없으면 지적" 이 판정이다.
