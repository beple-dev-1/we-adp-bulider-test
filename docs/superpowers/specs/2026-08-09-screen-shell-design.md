# 아홉 화면이 공유하는 껍데기는 무엇인가 — 화면 껍데기

> **2026-08-27 — 요구사항 추적 매트릭스는 산출물에서 삭제됐다(병주).** 아래에 남은 매트릭스 언급은 이력이다.
> 그린존(기능명세서 · 화면설계서 · 단위테스트 · 통합테스트 · 사용자 매뉴얼)은 같은 날 열렸다 — 정본은 `CLAUDE.md`.

화면 아홉과 그 사이를 오가는 길은 `2026-08-07-ia-design.md` 가 이미 세웠다.
**그 문서는 「화면 생김새 · 색 · 글꼴」을 「여기 없는 것」으로 스스로 밀어냈다.** 이 문서가 그것을 받는다.

받는 방식이 하나 정해져 있다 — **생김새는 새로 짓지 않는다.**
`99.publisher/we-adk-builder` 에 스타일 가이드가 이미 서 있고(2026-08-07 · 상태 「디자인 승인」),
**그것이 스타일의 정본이다.** 이 문서가 하는 일은 **그 스타일을 빌더의 아홉 화면에 어떻게 앉히나**다.

---

## 이 문서가 답하는 것과 안 답하는 것

**답한다** — 아홉 화면이 공유하는 것: 머리 · 왼쪽 메뉴 열 · 본문 너비 · 상태를 어떤 말로 쓰나 ·
알림 ● · 버튼과 폼의 기본형 · 그것들을 Thymeleaf 로 어떻게 만드나.

**안 답한다** —

- **화면 아홉 각각의 본문 내용.** 무엇이 어느 화면에 있나는 `ia-design` 이 정했다
- **색과 글꼴의 값.** 퍼블리셔 `tokens.css` 가 정본이다. 여기서 다시 정하지 않는다
- 검색 · 거르기 · 정렬 · 즐겨찾기 · 모바일 · 좁은 창 (→ 맨 끝 「여기 없는 것」)

---

## 퍼블리셔에서 무엇을 가져오고 무엇을 안 가져오나

⛔ **가져오는 것은 스타일뿐이다. 구성과 내용은 안 가져온다.**
퍼블리셔는 작업대 한 화면만 만들면서 그 화면의 구성까지 정해 놨는데, **그 구성은 여기서 안 쓴다.**

### 가져온다 — 스타일

| 무엇 | 어디서 | 어떻게 |
|---|---|---|
| 색 · 글꼴 · 여백 · 반경 · 그림자 | `assets/css/tokens.css` | **파일을 그대로 복사한다** |
| 브라우저 기본값 고르게 하기 · 포커스링 · 스킵링크 · 모션 줄이기 | `assets/css/reset.css` | 그대로 복사 |
| 제목 · 본문 · 작은 글 크기 | `assets/css/typography.css` | 그대로 복사 |
| 버튼 · 입력 · 배지 · 표 · 대화상자 · 토스트 · 빈 상태 · 뼈대 | `assets/css/components.css` | 그대로 복사 |
| 글꼴 파일 | `assets/fonts/PretendardVariable.woff2` | 그대로 복사 |

**복사다. 참조가 아니다.** 퍼블리셔 저장소를 런타임에 읽지 않는다 — 퍼블리셔 문서가 스스로 그렇게 못 박았고
(「다른 프로젝트 파일을 런타임에 참조하지 않는다」), 빌더 서버가 옆 워크스페이스에 의존하면 배포가 깨진다.

### 안 가져온다 — 구성과 내용

| 무엇 | 퍼블리셔가 한 것 | 여기서는 |
|---|---|---|
| 작업대 구성 | 네 영역 · 사이드바 248px · 지시 패널 390px | **작업대에 메뉴 열이 없다**(아래 「껍데기 두 층」) |
| 상태 표시 | 상태마다 배지 색 배정(라일락 · 라임 · 코랄 · 회색) | **글자가 정본. 색은 오류에만** |
| 레이아웃 CSS | `layout.css` | **안 가져온다.** 그것은 컴포넌트 카탈로그 사이트의 레이아웃이다(`.docs-shell` · `.demo-panel` · `.page-intro`). 빌더 틀은 `shell.css` 를 새로 쓴다 |
| 반응형 | 767 · 1023 · 1199 세 단 | **안 정한다**(→ 「여기 없는 것」). 구성이 다르므로 그 규칙이 그대로 안 맞는다 |
| 어휘 | 「과업 닫기」 · 「요구사항」이 작업 단위 | ⛔ **둘 다 폐어다.** 작업 단위는 **BRD** 이고 일반 명사로는 「작업」이다 |

⚠ **퍼블리셔 문서를 나중에 읽는 사람에게** — 그것은 2026-08-07 문서다. **산출물 체인이 2026-08-09 에
다시 서면서 작업 단위가 요구사항 항목에서 BRD 로 바뀌었다.** 퍼블리셔의 작업대는 「요구사항 제목」을
작업 대상으로 그렸다. **스타일만 보고, 구성과 어휘는 보지 마라.**

## 껍데기는 두 층이다

`ia-design` 이 「틀 셋은 산출물에만 적용된다」고 못 박았다. 그래서 공유하는 것도 두 층으로 갈린다.

```
┌─ 바탕 ─── 아홉 화면 전부가 쓴다 ────────────────────────┐
│  CSS 넷 · 머리 · 버튼 · 폼 · 표 · 대화상자 · 상태 말투     │
│                                                          │
│  ┌─ 틀 ─── 왼쪽 메뉴 열 + 본문 ───────────────────────┐  │
│  │  산출물 목록 · 산출물 상세 · 프로젝트 관리 · 사용자 관리 │  │
│  └────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────┘
```

화면 아홉이 셋으로 갈린다.

| | 화면 | 무엇을 쓰나 |
|---|---|---|
| 1 | 로그인 | **바탕** + 중앙 좁은 카드 |
| 2 | 비밀번호 바꾸기 | **바탕** + 중앙 좁은 카드 |
| 3 | Claude 연결 | **바탕** + 중앙 좁은 카드 |
| 4 | 프로젝트 고르기 | **바탕** + 중앙 좁은 카드 |
| 5 | 산출물 목록 | **틀** (메뉴 = 산출물 열) |
| 6 | 산출물 상세 | **틀** (메뉴 = 산출물 열) |
| 7 | **작업대** | **머리만.** 아래는 작업대가 스스로 잡는다 |
| 8 | 프로젝트 관리 | **틀** (메뉴 = 관리 둘) |
| 9 | 사용자 관리 | **틀** (메뉴 = 관리 둘) |

**작업대에 메뉴 열이 없다.** 나가는 길은 `[ BRD 작업 완료 ]` · `[ 목록으로 ]` 와 머리의 제품명이다.
근거 둘 — ① `ia-design:182` 의 작업대 스케치에 메뉴가 안 그려져 있다
② 미리보기 자리는 **실제 화면을 보여주는 자리**라 가로폭이 생명이다. 메뉴 열이 그것을 248px 먹는다.

**관리 둘에도 왼쪽 열을 준다.** 항목은 「프로젝트 관리 · 사용자 관리」 둘이다.
`ia-design` 은 관리를 「틀 밖」으로 뒀는데 **그것은 *산출물* 틀을 안 쓴다는 뜻이고**,
메뉴 열 장치를 재사용하는 것과는 부딪히지 않는다. 이렇게 하면 왼쪽 열 장치를 하나만 만든다.
그리고 실측 — **지금 `admin/projects.html` 에는 계정 화면으로 가는 링크가 없다.** 주소를 직접 쳐야 간다.

## 머리 — 무엇이 언제 있나

```
┌────────────────────────────────────────────────────┐
│  ⬤ 빌더   경비체계 ▾          ● 2    이영희 ▾      │
└────────────────────────────────────────────────────┘
   제품명     프로젝트           알림     사람 · 관리
```

**세 자리가 비어 있을 수 있다**(`ia-design:130`).

| 언제 | 제품명 | 프로젝트 | 알림 ● | 사람 | 관리 |
|---|---|---|---|---|---|
| 로그인 전 | 있다 | — | — | — | — |
| 로그인 후 · 프로젝트 고르기 전 | 있다 | — | 있다 | 있다 | 슈퍼계정만 |
| 프로젝트 안 | 있다 | 있다 | 있다 | 있다 | 슈퍼계정만 |
| 작업대 | 있다 | **그 자리에 BRD 번호와 제목** | 있다 | 있다 | 슈퍼계정만 |

- **제품명을 누르면 기본 화면(BRD 목록)으로 간다.** 프로젝트를 안 골랐으면 프로젝트 고르기로 간다
- **「관리」는 슈퍼계정에게만 보인다.** 사람 이름 드롭다운 안에 둔다 — 머리에 항목이 하나 늘지 않는다
- 그 드롭다운에 든 것: (관리) · 비밀번호 바꾸기 · Claude 다시 연결 · 로그아웃

### 머리가 쓰는 값은 화면이 안 담는다

`프로젝트이름` · `프로젝트번호` · `안읽은알림` · `알림` · `프로젝트들` 다섯은
**`ProjectContextInterceptor` 한 자리**가 얹는다. 화면 코드는 이 다섯을 모른다.

⛔ **화면에서 직접 담지 마라.** 산출물 화면이 열 개라 손으로 채우면 빠뜨릴 자리가 쉰이 되고,
**알림은 빠뜨려도 조용히 빈 채로 뜬다** — 계약이 막으려던 실패 방식 그것이다.
까닭 전문은 `2026-08-10-project-context-design.md`.

## 왼쪽 메뉴 열

**산출물 열 개를 다섯 묶음으로 나눈다**(`ia-design:31`~`:62` 그대로). 묶음 사이는 선 하나로 가른다.

```
받은 문서
요구사항
요구사항정의서
────────────
BRD              ← 기본 화면
작업 목업
메뉴구조도
개발요청서
────────────
솔루션 목업
────────────
기타 산출물
────────────
추적 매트릭스
```

**관리는 항목 둘이다** — 프로젝트 관리 · 사용자 관리.

- 폭은 **248px**. 「요구사항정의서」가 한 줄에 들어가야 한다
- 지금 있는 항목에 `aria-current="page"` 를 붙이고, **라일락 배경**을 준다
  (퍼블리셔가 「현재 메뉴」에 라일락을 쓰기로 한 그 자리다)
- 항목 높이 42px · 반경 10px · 글자 13px
- **개수 배지도 잠금 표시도 안 붙인다.** 붙일 숫자가 아직 없다 — 겪으면 그때 붙인다

## 본문 너비

⛔ **틀은 늘 화면을 꽉 쓴다.** 가로를 제한하는 것은 **「읽고 쓰는 덩어리」**뿐이다.

| 무엇 | 폭 |
|---|---|
| 틀 · 표 · 목록 | 꽉 (제한 없음) |
| **읽는 글 덩어리** — 요구사항 본문 · 정의서 본문 · BRD 본문 | **70자**(`max-width: 70ch`) |
| **폼 카드** — 로그인 계열 넷 | **380px** · 화면 가운데 |

규칙이 하나라 CSS 도 두 줄이다. 그리고 **추적 매트릭스가 안 잘린다** — 열이 **열**이라 폭 제한을 두면 갇힌다.

## 상태를 어떤 말로 쓰나

⛔ **글자가 정본이다. 색은 거든다.**

**색은 상태족이 아니라 「진행 단계」 다섯에 배정한다** — 대기 · 진행 · 검토 · 완료 · 오류.
`components.css` 의 `.status-badge--waiting`·`--progress`·`--review`·`--complete`·`--error` 다섯이 그것이고,
**더 늘리지 않는다.**

| 진행 단계 | 무슨 뜻인가 | 예 |
|---|---|---|
| **대기** | 아직 아무 일도 안 일어났다 | 처리 대기 · 요청 전 · 작업 대기 · 대기(개발요청서 전달) |
| **진행** | 기계나 사람이 지금 붙어 있다 | 내용 추출 중 · 작업중 · 전송중 · 김철수 편집 중 |
| **검토** | 사람이 봐줘야 넘어간다 | 정리 내용 확인 · 생성 완료 · 검토 필요 · 재작업 필요 |
| **완료** | 그 축에서는 끝났다 | 확정 완료 · 요청 완료 · 작업 완료 · 전송완료 |
| **오류** | 실패했다 | 문서 처리 오류 · 저장소 받기 실패 · 검사기 안 통과 |

**한 색이 여러 상태족에 걸쳐 같은 뜻을 갖는다.** 받은 문서의 「정리 내용 확인」과 BRD 의 「재작업 필요」와
사용자 관리의 「Claude 연결 필요」가 다 주황인 것은 셋 다 **사람이 봐줘야 넘어가는 자리**라서다.

⚠️ **종전에는 색을 통째로 금지했었다.** 그 이유는 「**상태족마다** 색을 배정하면 어느 색이 무엇이었는지
못 외운다」였다. 상태족이 아니라 **진행 단계**에 배정하면 외울 것이 다섯뿐이라 그 이유가 사라진다.
2026-08-13 에 목업 열여섯 장이 이미 그렇게 서 있는 것을 확인하고 규칙을 이쪽으로 옮겼다.

⛔ **색만으로는 여전히 말하지 않는다.** 배지에는 **늘 글자가 같이 있다** — 퍼블리셔가 못 박은
「색상만으로 상태를 구분하지 않는다」는 그대로 산다. 색을 지워도 화면이 읽혀야 한다.

**쓰는 말을 여기서 못 박는다.** 문서마다 다른 말을 쓰면 같은 상태가 두 이름을 갖는다.

| 상태족 | 쓰는 말 | 어느 진행 단계에 붙나 |
|---|---|---|
| **받은 문서 · 처리 구분** (사람이 고른 것) | 처리 대기 · 요구사항 대상 · 참고 문서 | 대기 / — / — |
| **받은 문서 · 현재 단계** (기계가 옮기는 것) | 내용 처리 대기 · 내용 추출 중 · 내용 정리 중 · 정리 내용 확인 · 처리 방향 선택 · 준비 완료 · 요구사항 추출 · 요구사항 검토 · 정의서 검토 · 완료 · **문서 처리 오류** | 대기 / 진행 / 진행 / 검토 / 검토 / 완료 / 진행 / 검토 / 검토 / 완료 / **오류** |
| **요구사항** (검토 상태) | 생성 완료 · 확정 완료 | 검토 / 완료 |
| **정의서 생성 요청** (별도 진행 축) | 요청 전 · 요청 완료 | 대기 / 완료 |
| **요구사항 · 작업 구분** (사람이 고른 갈래) | 작업 포함 · 보류 · 제외 | **진행 단계 색을 안 준다** — 처리 구분과 같다 |
| **BRD** (작업 상태) | 작업 대기 · 작업중 · 재작업 필요 · 작업 완료 | 대기 / 진행 / 검토 / 완료 |
| **개발요청서** (전달 상태) | 대기 · 전송중 · 전송완료 | 대기 / 진행 / 완료 |
| **검사기** | (통과는 **표시하지 않는다**) · **검사기 안 통과 — 어디가 걸렸나** | — / **오류** |

⛔ **갈래에는 진행 단계 색을 안 준다.** 받은 문서의 「처리 구분」과 요구사항의 「작업 구분」 둘이다 —
`.badge--active` / `.badge--outline` 으로 구분한다. 진행 단계 색을 주면 「참고 문서」와 「제외」가 실패나 완료로 읽힌다.

- ⛔ **받은 문서는 상태족이 하나가 아니라 둘이다.** 「처리 구분」은 사람이 고른 것이고 「현재 단계」는 기계가 옮기는 것이다.
  한 열에 뭉치면 「참고 문서인데 요구사항 추출 중」 같은 값이 표현되지 않는다 (→ `intake` 칸 2·3)
- ⛔ **검사기 통과는 화면에 안 걸어 둔다** (2026-08-13 결정). 저장을 누르면 **조용히 돌고 통과하면 그냥 저장**되고,
  **안 통과할 때만** 「규격에 안 맞아 저장하지 못했습니다」와 걸린 자리를 말한다.
  기획자가 규격을 고칠 수 있는 사람이 아니라, 상시 초록불은 읽을 값이 없고 자리만 먹는다.
  ⚠️ **되돌리기는 반대다 — 보인다.** AI 가 엉뚱하게 고쳐놨을 때 사람이 빠져나올 유일한 문이다(→ `ai-run`)
- **「작업중」에는 누구인지를 붙인다** — `작업중 · 나` / `작업중 · 김철수`. 잠금이 누구 것인지가 그 자리에 보인다
- **정의서 생성 요청 전인 요구도 목록에서 사라지지 않는다**(`ia-design:215`) — 확정 상태와 다음 산출물 생성 여부는 별도다
- ⛔ **「과업」을 쓰지 않는다.** 「작업」이다.
  예외는 셋이다 — 과거 설명 · 밖에서 받는 문서 이름(「과업요청서」) · 남의 규격을 인용해 따지는 자리(`CLAUDE.md` 가 정본)

## 알림 ●

**알림의 집은 머리의 `●` 하나다.** 누르면 그 자리에 드롭다운이 열린다.

```
┌──────────────────────────────────────┐
│ ⬤ 빌더  경비체계 ▾     ● 2  이영희 ▾ │
└─────────────────────────┬────────────┘
                          │
      ┌───────────────────┴──────────────────┐
      │ ● BRD-003 목업을 다 고쳤다            │
      │   14:02                              │
      │ ● REQ-007 정의서가 바뀌었다           │
      │   11:40                              │
      │ ──────────────────────────────────── │
      │   BRD-009 저장했다            어제    │
      │   ↑ 읽은 것은 흐리고 ● 이 없다        │
      └──────────────────────────────────────┘
```

- **줄을 누르면 그 산출물 상세로 간다.** 알림은 읽은 것으로 바뀐다
- 안 읽은 것에만 `●` 를 붙인다. 머리의 숫자는 안 읽은 개수다
- **화면을 새로 만들지 않는다** — `ia-design` 의 「화면 아홉」이 그대로 산다

⛔ **「작업대 배너」는 없는 물건이다.** 아래 「앞 문서를 뒤집는 것」에 적는다.

## 버튼 — 나가는 것이 보이게

퍼블리셔 `.button` 을 그대로 쓴다. **Primary 는 검정 · 보조는 흰 바탕에 선 하나 · pill 모양 · 최소 높이 44px.**

`ia-design:176` 이 요구한 것 하나 — **`[ 확정 ]`·`[ 승인 ]` 은 커밋이라 「누르면 나간다」가 사람에게 보여야 한다.**
`:179` 가 요구한 것 하나 — **`[ 이대로 시작 ]` 은 잠금을 만든다는 것이 버튼 옆에 보여야 한다.**

**두 가지로 만족시킨다.**

### ① 버튼 아래 한 줄 설명

```
        【 확정 】
   누르면 받은 문서와 요구사항이
   레포로 나간다
```

| 버튼 | 아래 한 줄 |
|---|---|
| `확정` | 누르면 받은 문서와 요구사항이 레포로 나간다 |
| `승인` | 누르면 요구사항정의서가 레포로 나간다 |
| `이대로 시작` | 누르면 이 BRD 의 화면들이 남에게 닫힌다 |
| `BRD 닫기` | 누르면 이 작업이 끝나고 개발요청서가 만들어진다 |
| `저장` | **없다** |
| `닫기` | **없다** |

### ② 혼자 되돌릴 수 없는 넷에만 한 번 더 묻는다

**확정 · 승인 · 이대로 시작 · BRD 닫기.** 퍼블리셔 `.dialog` 를 쓴다.

**「혼자 되돌릴 수 없다」가 넷을 고른 기준이다.** 셋은 레포로 나가고(확정 · 승인 · BRD 닫기),
하나는 남을 막는다(이대로 시작). **넷 다 누른 사람 혼자서는 없던 일로 만들 수 없다.**

```
 ┌──────────────────────────────────┐
 │ 받은 문서와 요구사항 3건이         │
 │ 레포로 나간다. 계속할까?           │
 │                                  │
 │              [ 아니다 ] 【확정한다】│
 └──────────────────────────────────┘
```

⛔ **넷을 늘리지 않는다.** `[ 저장 ]` 은 하루에 여러 번 누른다 — 거기에 물음이 붙으면
**사람이 읽지 않고 누르게 되고, 그러면 넷에 물어도 안 읽는다.**

- 대화상자는 열릴 때 안으로 포커스를 옮기고, 닫힐 때 누른 버튼으로 돌려준다(퍼블리셔 접근성 규칙)
- **버튼을 비활성으로 둘 때는 사유를 글로 같이 준다.** 회색으로만 만들지 않는다.
  ⚠ **어떤 조건에서 어느 버튼이 비활성이 되나는 이 문서가 정하지 않는다** — 그것은 각 줄기 문서의 몫이다.
  껍데기가 정하는 것은 **비활성이 어떻게 보이나**까지다

## 폼

퍼블리셔 `.field` 를 그대로 쓴다.

```
이름
┌────────────────────────────┐
│                            │   ← 높이 44px · 반경 8px · 선 1px
└────────────────────────────┘
그 레포에만 닿는 토큰을 넣는다      ← 도움말 · 12px · 흐린 글자
```

- **라벨은 입력칸 위에 둔다.** 한 열로 쌓는다. 라벨을 왼쪽에 두면 한글 라벨 길이가 달라 칸이 어긋난다
- 포커스는 **라일락 3px 링 · 2px 띄움**
- **오류는 그 칸 바로 아래 한 줄**로 `--color-error` · `aria-invalid="true"` · `aria-describedby`
- ⛔ **오류 문구에 서버 코드 · 스택 · 명령어를 노출하지 않는다.** 기획자는 개발자가 아니다
- **실패해도 사람이 쓴 것을 지우지 않는다**

## Thymeleaf 로 어떻게 만드나

**pom 에 아무것도 더하지 않는다.** 이미 있는 `spring-boot-starter-thymeleaf` 와
`thymeleaf-extras-springsecurity6` 로 된다. 레이아웃 상속 라이브러리를 안 넣는다 —
화면 아홉짜리에 상속 장치는 과하고, 사내 Nexus 미러가 그것을 갖고 있는지 안 재봤다.

### 파일 자리

```
src/main/resources/
├─ static/
│  ├─ css/
│  │  ├─ tokens.css       ← 퍼블리셔 복사
│  │  ├─ reset.css        ← 퍼블리셔 복사
│  │  ├─ typography.css   ← 퍼블리셔 복사
│  │  ├─ components.css   ← 퍼블리셔 복사
│  │  └─ shell.css        ← 새로 쓴다 (머리 · 메뉴 열 · 본문 · 카드)
│  └─ fonts/
│     └─ PretendardVariable.woff2   ← 퍼블리셔 복사
└─ templates/
   └─ fragments/
      └─ shell.html       ← 프래그먼트 넷
```

⛔ **퍼블리셔에서 복사한 넷은 손대지 않는다.** 고칠 것이 생기면 퍼블리셔 쪽을 고치고 다시 복사한다.
빌더 몫 스타일은 **전부 `shell.css` 한 장에** 넣는다. 그러면 어느 줄이 누구 것인지 파일로 갈린다.

### 프래그먼트 넷

| 프래그먼트 | 무엇 | 누가 쓰나 |
|---|---|---|
| `머리(프로젝트이름)` | 머리 한 줄 | 아홉 전부 (작업대는 이것만) |
| `메뉴(종류, 지금)` | 왼쪽 열. 종류는 `산출물` 또는 `관리` | 틀이 부른다 |
| `틀(제목, 종류, 지금, 본문)` | `<head>` + 머리 + 메뉴 + 본문 | 목록 · 상세 · 관리 둘 |
| `바탕(제목, 본문)` | `<head>` + 머리 + 중앙 카드 | 로그인 계열 넷 |

페이지는 한 줄로 껍데기를 부르고 본문만 쓴다. **본문을 프래그먼트 표현식으로 넘긴다** — Thymeleaf 3 기본 기능이다.

```html
<html th:replace="~{fragments/shell :: 틀('BRD', '산출물', 'brd', ~{::main})}">
<body>
  <main>
    ...이 화면 내용만...
  </main>
</body>
</html>
```

`<head>` 를 프래그먼트가 내므로 **`<link>` 다섯 줄이 아홉 장에 흩어지지 않는다.**
지금은 여섯 장이 각자 `<head>` 를 손으로 쓰고 있고 `<link>` 는 한 장에도 없다.

## 무엇으로 확인하나

**자동으로 잴 수 있는 것** (MockMvc):

- 아홉 화면이 **CSS 다섯 줄과 글꼴을 다 걸고 있나** — `<link>` 다섯 개가 응답에 있나
- `/css/tokens.css` · `/fonts/PretendardVariable.woff2` 가 **200 으로 뜨나**
- **로그인 전 화면에 사람 이름이 없나**
- **슈퍼계정이 아닌 사람에게 「관리」가 안 보이나**
- 메뉴에서 **지금 있는 항목에만** `aria-current="page"` 가 붙나
- 산출물 목록·상세에 **메뉴 열이 있고, 작업대에는 없나**
- 혼자 되돌릴 수 없는 넷에 **`.dialog` 가 딸려 있나** · `[ 저장 ]` 에는 없나
- 나가는 버튼 넷에 **한 줄 설명이 붙어 있나**

⚠ **자동으로 못 재는 것 — 생김새다.** 색이 맞는지 · 여백이 고른지 · 글꼴이 실제로 Pretendard 로 뜨는지는
**사람 눈으로 한 번 본다.** 퍼블리셔에는 Playwright 가 있지만 빌더에 브라우저 테스트를 들이는 것은
이 문서의 몫이 아니다(→ 「여기 없는 것」).

⚠ **글꼴이 안 뜨는 경우가 하나 있다** — `tokens.css` 의 `@font-face` 가 `url("../fonts/…")` 로
상대 경로를 쓴다. 복사한 자리가 `static/css/` 이고 글꼴이 `static/fonts/` 이므로 **경로가 맞는다.**
자리를 옮기면 깨진다 — 그래서 위 파일 자리를 그대로 지킨다.

## 앞 문서를 뒤집는 것

정직하게 갈라 적는다.

### ① 「알림은 작업대 배너다」를 지운다

- `ia-design.md:391` — 「알림은 작업대 배너라 그때 아무도 안 열고 있으면 사라진다」
- `concurrent-edit-design.md:377` — 「알림은 작업대 배너라 어긋난 순간에 아무도 안 열고 있으면 갈 데가 없다」

**작업대 배너라는 물건을 정의한 문서가 없다.** 그리고 `ia-design:390` 은 **바로 위 줄에서**
「알림 | 머리에 하나. 어느 화면에서든」이라고 정했다. **한 문서가 두 줄에서 다르게 말한 것이다.**

**고친다** — 알림의 집은 머리의 `●` 하나이고, 안 읽은 것이 거기 쌓인다. 「갈 데가 없다」는 상황이 안 생긴다.

⚠ **결론은 그대로 살린다** — 「산출물 목록·상세에 어긋남의 흔적이 남는다」는 여전히 참이다.
근거만 바뀐다: 「배너가 사라져서」가 아니라 **「알림은 읽으면 사라지고 흔적은 남아야 해서」**다.

### ② 「화면 생김새 · 색 · 글꼴」을 「여기 없는 것」에서 뺀다

`ia-design.md:407` 의 그 줄을 지운다. 이 문서와 퍼블리셔 스타일 가이드가 답했다.
나머지 셋(검색·거르기·정렬 / 즐겨찾기 / 모바일)은 **그 자리에 그대로 남는다.**

### ③ 관리 둘이 왼쪽 열을 쓴다

`ia-design:116`~`:119` 는 관리 둘을 「틀 밖」으로 뒀다. **그 판단은 살린다** —
관리는 *산출물* 틀(목록·상세·작업대)을 안 쓴다. 다만 **메뉴 열 장치는 재사용한다.**
어긋남이 아니라 「틀」과 「메뉴 열 장치」가 다른 것이라는 뜻이다.

## 여기 없는 것

안 겪은 일이라 세우지 않았다. 겪으면 그때 이 문서를 고친다.

- **모바일 · 좁은 창.** 퍼블리셔가 세 단을 정했지만 그것은 퍼블리셔의 작업대 구성에 매인 규칙이다.
  빌더 구성이 다르므로 그대로 안 맞는다. **기획자는 사무실 모니터로 온다**
- **목록의 검색 · 거르기 · 정렬** · 즐겨찾기 · 최근 본 것 (`ia-design` 이 밀어낸 그대로)
- **다크 모드**
- **메뉴 항목의 개수 배지와 잠금 표시.** 붙일 숫자가 아직 없다
- **브라우저 테스트(Playwright 등).** 생김새를 자동으로 재는 일
- **아이콘 자산.** 지금 필요한 것은 셋뿐이다 — 드롭다운 화살표 · 알림 · 닫기.
  로컬 SVG 로 두고, 늘어나면 그때 모은다
