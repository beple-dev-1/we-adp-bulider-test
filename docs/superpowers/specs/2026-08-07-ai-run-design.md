# AI 를 부르면 무엇이 일어나나 — 실행과 큐

> **이 문서가 답하는 질문 하나: 기획자가 지시를 보낸 뒤 무엇이 일어나나 — 그리고 여럿이 겹치면.**
> 무엇을 지시하는지, 결과를 어떻게 확인하는지는 여기 없다 — 그건 앞 문서들이다.

## 경계 — 문서 준비 API는 개인 Claude 실행과 다르다

받은 문서의 **본문 추출·1차 정리**는 이 문서의 개인 `claude -p` 실행이 아니다. 서버가 소유한 AI API 자격으로 자동 실행하며 `adk_builder_document_processing_run`에 호출별 상태·오류·사용량·비용을 남긴다. 원문은 덮어쓰지 않고, API 결과인 정리본은 사람이 확인해야 `READY`가 된다.

그 뒤의 **요구사항 추출·정의서 작성·목업 수정**은 아래에 정의한 개인 계정 실행 계약을 따른다. 두 실행의 자격, 비용, 상태 이력을 하나의 `ai_run`에 섞지 않는다.

앞의 열 문서에서 AI 실행에 대해 적힌 것은 이게 전부다.

> 「도는 동안 **「고치는 중」**, 끝나면 **알림**」 · 「진행 표시 + 완료 알림」 ·
> 「AI 를 돌리기 직전에 빌더가 **스냅샷**을 남기고 「방금 실행 되돌리기」 버튼 하나를 준다」 ·
> 「스트리밍은 기획자에게 개발 언어를 그대로 노출한다」 · 「동시 실행 **제한 없음. 큐를 두지 않는다**」

**끝나는 경우만 있다.** 실패하면 · 안 끝나면 · 그만두면 · 한도에 걸리면이 하나도 없다.
`CLAUDE.md` 가 「AI 실행 큐는 아직 아무것도 정해지지 않았다」로 세워둔 미결도 여기서 닫는다.

## 큐를 안 둔다 — 근거를 바꿔 적는다

`one-flow` 는 「안 겪은 병목에 장치를 먼저 세우지 않는다」로 큐를 미뤘다. 결론은 그대로 살리되,
**무엇이 병목인지를 실제로 세어보고 적는다.**

| 부딪힐 것 같은 자리 | 실제로 |
|---|---|
| **Claude 쪽** | **안 부딪힌다.** `planner-account` 가 자격을 사람마다 본인 계정으로 정했다 — 열 명이 동시에 돌리면 Claude 는 **열 개의 다른 계정**에서 온 요청으로 본다 |
| **개인 한도** | **부딪히지만 그 사람만.** 「요금과 한도가 각자 구독에 붙어 있다」 — 남에게 안 번진다 |
| **서버** | **여기만 여럿이 함께 부딪힌다.** `claude -p` 프로세스가 한 서버에서 여럿 돈다 |

큐가 여럿을 위해 풀 수 있는 것은 **셋째 하나뿐**이고, 서버가 몇 명을 못 버티는지는 아직 안 겪었다.

⚠️ **개인 한도에 대해 아는 것과 모르는 것을 갈라 적는다.** `planner-account` 가 적은 것은
「요금과 한도가 각자 구독에 붙는다」까지다. **총량 한도라면 줄을 세워도 안 풀린다** —
기다린다고 이번 달 쓴 양이 줄지 않는다. 그런데 Claude 에 **시간당 제한이나 동시 실행 제한**이
따로 있으면 이야기가 달라진다. 그건 어느 문서에도 없고 안 겪었다.
겪으면 그때는 **한 사람 안에서** 줄을 세우는 것이 답일 수 있다 — 여럿을 위한 큐가 아니다.

### 시간 상한이 안전망 노릇을 한다

큐가 없어도 프로세스가 무한정 쌓이지는 않는다. **서버가 느려지면 실행이 시간 상한을 넘고,
그러면 실패로 떨어져 프로세스가 정리된다.**

큐를 세우는 것보다 싸고, 겪으면 그때 큐를 넣기도 쉽다 — 지금 세운 것 중에 뜯을 것이 없다.

## 실행 하나가 도는 모양

```
                    [ 실행 시작 ]
                          │
                    스냅샷을 남긴다              ← one-flow 가 정해둔 것
                          │
                    claude -p 를 돌린다
                          │
     ┌──────────┬─────────┴──┬──────────┬──────────┬──────────┐
   끝났다     실패했다   시간이 넘었다  그만뒀다  한도에 걸렸다  자격이 끊겼다
     │          │            │          │           │           │
     │          │      ┌─────┴──────────┴─────┐     │           │
     │          │      │  프로세스를 죽인다     │     │           │
     │          │      │  **끝난 것을 확인한다** │    │           │
     │          │      └─────┬──────────┬─────┘     │           │
     │          └────────────┴──────────┴───────────┴───────────┘
     │                                 │
결과가 뜬다                    스냅샷으로 되돌린다
검사기가 돈다                  쓴 지시가 있으면 살려둔다
● 알림                         왜 그랬는지 한 줄 · ● 알림
```

**성공은 하나, 나머지 다섯은 끝처리가 같다.** 되돌리고 · 지시를 살리고 · 이유를 말한다.
장치를 다섯 만들지 않는다 — **하나를 만들고 앞뒤만 가른다.**

**다만 문구만 다른 것이 아니다. 앞에 한 걸음이 더 붙는 것이 둘 있다.**

| | 프로세스가 | 그래서 |
|---|---|---|
| 실패 · 한도 · 자격 끊김 | **이미 끝나 있다** | 바로 되돌린다 |
| **시간 초과 · 그만둠** | **아직 돌고 있다** | **죽이고, 끝난 것을 확인한 뒤** 되돌린다 |

⛔ **확인 없이 되돌리면 안 된다.** 죽는 중인 프로세스가 **되돌린 뒤에 파일을 한 번 더 쓴다.**
그러면 「화면은 건드리기 전 그대로다」가 거짓말이 된다.

### 되돌리는 이유

AI 가 도중에 죽으면 **파일이 반쯤 고쳐진 채로 남을 수 있다.** 그것을 그대로 두면
기획자가 「지금 이 모양이 정상인가」를 판단해야 하고, 검사기도 반쪽짜리 파일을 보게 된다.
`one-flow` 가 실행 직전에 스냅샷을 남기기로 한 것이 여기서 값을 한다 — **이미 있는 장치다.**

### 쓴 지시를 살려두는 이유

지시를 길게 써서 보냈는데 실패했다고 지워지면 처음부터 다시 쓴다.
화면은 되돌리되 **사람이 쓴 것은 남긴다.**

### 성공한 지시도 쌓아둔다 — 이유가 둘이고 서로 다르다

살려두는 것이 **실패한 한 건**이면 모자란다. 그런데 **왜 모자란지가 재료마다 다르다.**

| 무엇 | 왜 쌓나 |
|---|---|
| **메뉴구조도 지시** | **다시 해야 할 수 있다.** 구조도는 **시스템마다** 한 장이라 부딪힌다 — `push` 가 「부딪히면 나중 쪽이 지시를 들고 다시 한다」로 정했다. (2026-08-10 정정: 「프로젝트에 한 장」이 아니다. **부딪히는 것은 같은 시스템 안에서다** — 웹뷰와 백오피스는 서로 안 부딪힌다) |
| **목업 지시** | **보여주기 위해서다.** 목업은 부딪히지 않으니 다시 할 일이 없다 — 작업대의 **「지난 지시」** 자리가 이것을 쓴다(→ `planner-one-flow`) |

⚠️ **목업 쪽 이유를 「다시 하기 위해」로 적지 마라.** 목업은 화면이 막히고 파일 경로에
BRD 번호가 들어가서 **두 사람이 같은 목업 파일에 닿을 길이 없다**(→ `concurrent-edit`).
없는 경우를 근거로 적으면 다음 사람이 그것을 보호로 믿는다.

**그래서 한 일에서 보낸 지시를 순서대로 보관한다. 성공한 것도 남긴다.**
텍스트라 싸고, 일이 닫히면 같이 지운다.

### 문구는 다섯이 다르다

| 어떻게 끝났나 | 뭐라고 뜨나 | 다음에 할 일 |
|---|---|---|
| **실패** | 「못 고쳤다. 화면은 건드리기 전 그대로다」 | 다시 해보거나 다르게 써보라 |
| **시간 초과** | 「너무 오래 걸려 멈췄다」 | 지시를 짧게 나눠 보라 |
| **그만둠** | 「그만뒀다. 화면은 건드리기 전 그대로다」 | — |
| **한도** | 「Claude 사용 한도에 걸렸다」 | **한도가 풀리면 다시 된다** (다시 눌러도 안 된다) |
| **자격 끊김** | 「Claude 연결이 끊겼다」 | **[ Claude 다시 연결 ]** ↓ |

⛔ **뒤의 둘에는 「다시 해보라」를 안 붙인다.** 붙이면 **안 되는 것을 다섯 번 더 누르게 되고**,
왜 안 되는지 끝내 모른 채로 남는다.

### 못 가르면 「그냥 실패」로 둔다

문구 다섯은 **`claude -p` 가 한도와 자격 끊김을 그냥 실패와 갈라서 알려준다**에 기댄다.
안 갈리면 **문구를 지어내지 않는다** — 다섯이 셋이 되고, 나머지 둘은 「못 고쳤다」로 떨어진다.

이유는 **개발자용 로그에 남는다.** 거기서 보고 조치한다.
기획자에게 틀린 이유를 대는 것보다 낫다 — 「한도에 걸렸다」고 했는데 실은 자격이 끊긴 것이면
기다려도 영영 안 풀린다.

### 자격 끊김을 따로 세우는 이유

`planner-account` 는 **「확인은 BRD 를 열 때」**로 자리를 하나로 못 박고,
**「일하는 도중에 끊지 않는다」**고 했다. 맞는 결정이다 — 지시를 다 써놓고 돌렸는데
그제서야 막히면 쓴 것이 갈 데가 없다.

**그런데 BRD 를 열어둔 채 며칠 일하면 도중에 만료된다.** 열 때 확인한 것이 지금도 유효하다는
보장이 없다. 그때 실패로 뭉뚱그려 「다시 해보라」를 띄우면 **영원히 안 되는 것을 반복하게 된다.**

그래서 이 하나만 화면에 **버튼**이 붙는다 — 누르면 `ia-design` 이 정한 재연결 화면으로 갔다가
**쓴 지시가 살아 있는 그 작업대로 돌아온다.** 「도중에 끊지 않는다」가 지켜진다 —
끊는 것이 아니라 이어 붙이는 것이다.

`planner-account` 는 「사용량 보여주기」를 「여기 없는 것」으로 뺐다. 그 결정은 그대로 산다 —
**미리 보여주지는 않고, 걸렸을 때만 그렇다고 말한다.**

### 오류 원문은 화면에 안 나온다

`one-flow` 가 「스트리밍은 기획자에게 개발 언어를 그대로 노출한다」를 이유로 스트리밍까지 거부했다.
실패 원문은 그보다 더한 개발 언어다. **개발자용 로그로만 간다.**

## 도는 중에 보이는 것과 못 하는 것

```
┌───────────────────────┬──────────────────────────┐
│                       │  ⟳ 고치는 중…            │
│    목업 미리보기        │     [ 그만둔다 ]          │
│                       │  ┌────────────────────┐  │
│                       │  │ 저장 버튼 왼쪽에    │  │
│                       │  │ 임시저장을 넣어줘   │  │ ← 잠겨 있다
│                       │  └────────────────────┘  │
└───────────────────────┴──────────────────────────┘
```

### 한 일에 한 번에 한 실행 — 서버가 막는다

**도는 동안 새 지시를 못 보낸다.** 보내려면 「그만둔다」를 먼저 누른다.

지어낸 규칙이 아니라 따라 나온다 — `one-flow` 가 **「되돌리기는 실행 1회 = 한 칸이다.
여러 칸을 거슬러 오르는 이력 목록은 만들지 않는다」**로 정했다.
두 실행이 겹치면 **어느 스냅샷으로 되돌리는지 정할 수가 없다.**

⚠️ **잠기는 것은 지시 칸이 아니라 그 일이다.** 화면에서 칸을 회색으로 만드는 것만으로는
못 막는다 — 동시편집이 **「같은 사람이 두 탭에서 열면 그냥 열린다」**로 정했으니
**두 탭에서 각각 지시를 보낼 수 있다.** 그래서 「지금 이 일에 실행이 돌고 있다」를
**서버가 알고 있어야** 하고, 둘째 지시는 서버가 거절한다.

**그 값은 잠금과 같은 자리에 살되 파일이 아니라 「일」에 붙는다** — 한 일이 파일 셋을 쥐어도
실행은 하나라서, 파일 줄마다 적으면 같은 값이 중복된다. 동시편집이 그 자리를 만들어 뒀다.

**숨기지 않는다.** 도는 동안 **어느 탭에서 보든 「⟳ 고치는 중」과 「그만둔다」가 뜨고**
지시 칸이 잠긴다. 거절만 하고 이유를 안 보이면 두 번째 탭에서는 왜 안 보내지는지 알 수 없다.

### 도는 중에 남이 넘겨받으면

동시편집은 **넘겨받기에 시간 조건을 두지 않았다.** 그러니 앞사람의 AI 가 도는 중에도
넘겨받을 수 있다. 그때 무엇을 하나 —

**「그만둠」과 똑같이 친다.** 새 개념을 만들지 않는다.

```
[ 넘겨받기 ]
     │
  1  앞사람 잠금이 죽는다 · 저장이 거절된다        ← 동시편집이 정한 것. 제일 먼저다
     │
  2  앞사람 실행이 돌고 있으면
     │    프로세스를 죽인다 → 끝난 것을 확인한다 → 스냅샷으로 되돌린다
     │
  3  검사기 초록불과 스냅샷을 버린다                ← 동시편집이 정한 것
     │
  4  새 주인에게 워크트리를 넘긴다
```

**순서가 셋 다 중요하다.**

- **잠금이 제일 먼저다.** 동시편집이 「넘겨받는 **순간** 저장이 거절된다」로 정했다.
  뒤로 미루면 죽이고 되돌리는 그 몇 초 사이에 앞사람 저장이 끼어든다
- **되돌리기가 스냅샷 버리기보다 먼저다.** 거꾸로 하면 되돌릴 것이 없어져
  **반쯤 고쳐진 파일이 새 주인에게 넘어간다**
- **넘기는 것이 마지막이다.** 앞의 셋이 끝나야 새 주인이 깨끗한 워크트리를 받는다

앞사람 화면에는 동시편집이 정한 그대로 「김철수가 넘겨받았다」가 뜬다.
**늦게 도착한 앞 실행의 결과는 버린다** — 그 실행은 이미 죽은 것으로 처리됐다.

### 실패한 실행은 되돌리기 한 칸을 안 쓴다

`one-flow` 의 되돌리기는 **「방금 실행」 한 칸뿐**이다. 그러면 실패한 실행이 그 한 칸을
먹는지가 문제가 된다 — 먹으면 **직전에 성공한 실행을 되돌릴 권리가 사라진다.**

**안 먹는다.** 실패·시간 초과·그만둠·한도·자격 끊김은 **이미 자동으로 되돌려졌다.**
되돌릴 것이 남아 있지 않으니 한 칸을 쓸 이유가 없다.
**직전 성공 실행의 「방금 실행 되돌리기」가 그대로 살아 있다.**

### 그만두기가 따로 필요한 이유

되돌리기가 이미 있으니 끝나기를 기다렸다 되돌려도 된다. 그런데 두 가지를 잃는다 —
**몇 분**과 **그 사람 돈**이다. 토큰이 개인 것이라 잘못 보낸 실행을 끝까지 돌리는 것은
남의 지갑이 아니라 **본인 지갑**을 태우는 일이다.

그리고 장치가 새로 안 늘어난다. **그만두기의 뒤처리가 실패·시간 초과와 똑같다.**

### 시간 상한 값은 설치 설정에 적는다

슈퍼계정 비밀번호와 같은 자리다(`project-setup`).
프로젝트마다 목업 크기가 달라서 「10분」을 여기서 지어내면 어딘가에서 안 맞는다.

### 떠나 있어도 된다

`ia-design` 이 **알림을 머리에 하나** 두기로 했다. 작업대를 떠나 다른 산출물을 봐도
끝나면(또는 실패해도) 알림이 온다. 도는 것을 보고 앉아 있지 않아도 된다.

## 실행은 다섯 종류다

지금까지의 그림은 **목업 작업대**다. 나머지도 같은 틀을 쓰지만(`ia`),
**누가 시작하나**와 **무엇을 되돌리나**가 갈린다.

| 실행 | 누가 시작하나 | 되돌릴 것 |
|---|---|---|
| **요구사항 뽑기** | **자동** — 받은 문서를 `요구사항 대상`으로 고르면 | 이번 실행이 만든 요구사항 **전부** |
| **정의서 쓰기** | **자동** — 기획자가 고르고 나면 | 이번 실행이 만든 정의서 **전부** |
| **BRD 초안** | **자동** — 정의서가 승인되면 | 이번 실행이 만든 BRD 내용 **전부** |
| **목업 · 메뉴 트리 고치기** | 사람이 지시를 쓰고 보낸다 | 그 파일 하나 |
| **개발요청서 쓰기** | **자동** — BRD 가 닫히면 | 되돌릴 것이 없다 — **다시 만들면 된다** |

**넷이 자동이고 하나만 사람이 시작한다.** 그래서 이 문서의 「쓴 지시를 살려둔다」가
적용되는 자리는 실제로 하나뿐이다.

### 자동 실행에는 살려둘 지시가 없다

문서 정리본 확인을 마친 받은 문서를 `요구사항 대상`으로 고르면 요구사항 AI가 바로 돈다. `참고 문서`면 돌지 않는다. **사람이 쓴 지시가 없다.**
그러니 「쓴 지시를 살려둔다」가 적용될 것이 없고, 화면에 남는 것도 없다.
실패하면 **받은 문서만 남고 접수는 그 걸음에 그대로 서 있다.** 다시 시키는 것은 사람이 누른다.

그 뒤로는 같다 — 「말로 고쳐라」부터는 사람이 쓴 지시가 있고, 실패하면 그것이 남는다.

### 파일 여럿을 한꺼번에 되돌린다

요구사항 뽑기와 정의서 쓰기는 **파일이 여러 개 생긴다.** 도중에 실패하면
**셋은 생기고 넷째는 안 생긴 상태**가 남는다.

**전부 되돌린다. 반쯤 쪼개진 상태를 남기지 않는다.**
그리고 **앞 걸음에서 확정·승인이 끝난 것은 안 건드린다** — 이번 실행이 만든 것이 아니다.
스냅샷은 실행 직전에 찍히므로 이 둘이 저절로 갈린다.

### BRD 초안 실행에는 위험이 하나 더 있다

다른 실행은 실패하면 **아무것도 안 생긴다.** BRD 초안은 다르다 —
**성공했는데 판단이 틀릴 수 있다.** AI 가 고칠 화면을 잘못 짚는 경우다.

그때 목업을 먼저 만들어 두면 **엉뚱한 화면 파일이 워크트리에 생기고**, 기획자는 그것을 못 지운다.

⛔ **그래서 순서를 못 박는다 — 사람이 BRD 초안을 보고 「이대로 시작」을 누른 뒤에 목업을 만든다.**
BRD 초안 실행은 **DB 에만 쓴다.** 파일을 만들지 않는다.

이 순서가 지켜지면 잘못된 판단은 **말로 고쳐서** 지워진다 — 되돌리기 한 칸으로 충분하다.

## 한 사람이 BRD 를 몇 개 여나 — 제한을 안 둔다

`ia` 가 여기로 미뤄둔 것이다. **막히는 것과 안 막히는 것을 갈라 적는다.**

| 걱정 | |
|---|---|
| 둘이 같은 것을 고친다 | **막힌다** — 파일 잠금(동시편집) |
| 한 일에서 실행이 겹친다 | **막힌다** — 서버가 둘째 지시를 거절한다(위) |
| 열어놓고 방치한다 | **회수된다** — 남이 넘겨받는다(동시편집). 막는 것이 아니라 되찾는 것이다 |
| 열어놓고 잊는다 | **안 막힌다.** 목록의 「██ 작업중 · 나」는 보여줄 뿐이다 |
| 워크트리와 디스크가 쌓인다 | **안 막힌다** |
| 서버에 실행이 몰린다 | **안 막힌다.** 시간 상한이 정리할 뿐이다 |

**안 막히는 셋이 남는데도 제한을 안 두는 이유** — 셋 다 **서버 자원** 문제이고,
그건 이 문서가 큐를 안 두기로 한 것과 **같은 이유로 미룬다.** 안 겪었다.
겪으면 그때 정하는 것이 「한 사람당 몇 개」인지 「서버당 몇 개」인지도 그때 알 수 있다.

지금 숫자를 정하면 **막지도 못하면서 숫자만 지어내는 일**이 된다.

## 정한 것과 그 이유

| 무엇 | 정한 것 | 왜 |
|---|---|---|
| 큐 | **안 둔다** | 여럿이 함께 부딪히는 자리는 서버 하나뿐이고 안 겪었다. Claude 쪽은 계정이 사람마다라 안 부딪히고, 개인 한도는 남에게 안 번진다 |
| 개인 한도의 성질 | **총량인지 시간당인지 모른다고 적어둔다** | 앞 문서가 「각자 구독에 붙는다」까지만 적었다. 시간당 제한이 있으면 **한 사람 안에서** 줄을 세우는 것이 답일 수 있다 — 그건 여럿을 위한 큐가 아니다 |
| 서버 부하 | **시간 상한이 안전망이다** | 서버가 느려지면 실행이 상한을 넘어 정리된다. 큐보다 싸고, 겪으면 그때 큐를 넣어도 뜯을 것이 없다 |
| 끝나는 길 | **여섯 — 성공 · 실패 · 시간 초과 · 그만둠 · 한도 · 자격 끊김** | 앞 문서에는 성공 하나뿐이었다 |
| 성공 아닌 다섯의 끝처리 | **하나다 — 되돌리고 · 지시를 살리고 · 이유를 말한다** | 장치를 다섯 만들 이유가 없다 |
| 다만 앞에 붙는 걸음 | **시간 초과·그만둠은 죽이고 「끝난 것을 확인」한 뒤 되돌린다** | 확인 없이 되돌리면 죽는 중인 프로세스가 되돌린 뒤에 한 번 더 쓴다 |
| 자격 끊김 | **따로 세우고 재연결 버튼을 붙인다** | `planner-account` 는 「확인은 BRD 를 열 때」다. 며칠 열어두면 도중에 만료되는데 실패로 뭉치면 영원히 안 되는 것을 반복한다 |
| 되돌리는 것 | **실행 직전 스냅샷** | AI 가 죽으면 파일이 반쯤 고쳐진 채 남는다. 스냅샷은 `one-flow` 가 이미 만들어 둔 장치다 |
| 실패한 실행과 되돌리기 한 칸 | **안 쓴다** | 이미 자동으로 되돌려졌다. 직전 성공 실행의 되돌리기가 그대로 살아 있어야 한다 |
| 쓴 지시 | **있으면 살려둔다** | 길게 쓴 것을 처음부터 다시 쓰게 하지 않는다. 접수 첫 실행에는 쓴 지시가 없다 |
| 한도·자격 끊김 문구 | **「다시 해보라」를 안 붙인다** | 붙이면 안 되는 것을 다섯 번 더 누른다 |
| `claude -p` 가 못 가르면 | **「그냥 실패」로 떨어뜨린다. 로그에서 본다** | 틀린 이유를 대는 것보다 낫다. 「한도」라 했는데 실은 자격 끊김이면 기다려도 영영 안 풀린다 |
| 사용량 보여주기 | **안 만든다** | `planner-account` 가 뺀 그대로다. 미리 안 보여주고, 걸렸을 때만 그렇다고 말한다 |
| 오류 원문 | **화면에 안 낸다. 개발자용 로그로** | 스트리밍도 「개발 언어를 그대로 노출한다」로 거부했다. 실패 원문은 그보다 더하다 |
| 한 일에 한 번에 한 실행 | **서버가 막는다. 화면만 잠그지 않는다** | 동시편집이 「같은 사람의 두 탭은 그냥 열린다」로 정했다. 화면만 회색으로 만들면 다른 탭에서 뚫린다 |
| 「실행 중」이 사는 곳 | **잠금과 같은 자리. 파일이 아니라 「일」에 붙는다** | 한 일이 파일 셋을 쥐어도 실행은 하나다 |
| 실행 중임을 보이나 | **어느 탭에서 보든 보인다** | 거절만 하고 이유를 안 보이면 둘째 탭에서 왜 안 되는지 알 수 없다 |
| 도는 중 넘겨받으면 | **「그만둠」과 똑같이 친다** | 죽이고 · 확인하고 · 되돌린 **다음에** 넘긴다. 순서가 거꾸로면 반쯤 고쳐진 파일이 새 주인에게 간다 |
| 그만두기 | **버튼을 둔다** | 기다렸다 되돌리면 몇 분과 **그 사람 돈**을 버린다. 토큰이 개인 것이다. 끝처리는 실패와 같아서 장치가 안 는다 |
| 시간 상한 값 | **설치 설정에 적는다** | 프로젝트마다 목업 크기가 다르다. 여기서 숫자를 지어내면 어딘가에서 안 맞는다 |
| 실행 종류 | **다섯. 넷이 자동이고 하나만 사람이 시작한다** | 사람이 시작하는 것은 목업·메뉴 트리 고치기뿐이다. 그래서 「쓴 지시를 살려둔다」가 적용되는 자리도 하나다 |
| 자동 실행 | **살려둘 지시가 없다** | 올리거나 고르면 바로 돈다. 실패하면 그 걸음에 그대로 서 있다 |
| 파일 여럿을 만드는 실행 | **이번 실행이 만든 것을 전부 되돌린다** | 반쯤 쪼개진 상태를 남기지 않는다. 앞 걸음에서 확정·승인된 것은 이번 실행이 만든 것이 아니라 안 건드린다 |
| BRD 초안 실행 | **DB 에만 쓴다. 목업은 사람이 누른 뒤에** | 다른 실행은 실패하면 아무것도 안 생기는데, 이것은 **성공했는데 판단이 틀릴 수 있다.** 먼저 만들면 엉뚱한 화면 파일이 생기고 기획자는 그걸 못 지운다 |
| 개발요청서 실행 | **되돌리지 않는다. 다시 만든다** | 재생성물이다. 되돌릴 원본이라는 개념이 없다 |
| 한 사람이 여는 BRD 수 | **제한 없음** | 안 막히는 셋이 남지만 전부 서버 자원 문제다 — 큐를 미룬 것과 같은 이유로 미룬다. 지금 숫자를 정하면 막지도 못하면서 숫자만 지어낸다 |

## 이 줄기가 기대는 전제

1. **`claude -p` 를 서버에서 돌릴 수 있고, 죽일 수 있다.** 그만두기와 시간 상한이 여기 기댄다.
2. **`claude -p` 가 한도 초과와 자격 끊김을 그냥 실패와 갈라서 알려준다.**
   확인할 것은 API 가 아니라 **이 명령**이다. 안 갈리면 문구도 안 갈린다 —
   그때는 「그냥 실패」로 떨어뜨리고 개발자용 로그에서 본다(위에 적었다).
   **이 전제가 안 서도 문서가 무너지지는 않는다. 문구가 다섯에서 셋이 될 뿐이다.**
3. 기획 레포에 **검사기**가 있다. 성공한 실행 뒤에 도는 것이 그것이다.

## 여기 없는 것

안 겪은 일이라 세우지 않았다. 겪으면 그때 이 문서를 고친다.

- **큐와 우선순위** — 겪으면 그때 넣는다
- **사용량 · 남은 한도 보여주기**
- **실행 이력** — 언제 몇 번 돌렸나
- **서버가 몇 개까지 버티는지 재는 것**
- **자동 재시도** — `handoff-to-dev` 가 전송 실패에 대해 「⛔ 빌더가 몰래 재시도하지 않는다」로
  정한 것과 결이 같다. 다만 그건 개발 API 전송 얘기라 여기 그대로 옮기지는 않는다 —
  여기서 안 하는 이유는 **토큰이 개인 돈이라 두 번 나가기 때문**이다
