# 사람이 어떻게 빌더에서 AI 를 돌릴 자격을 갖나 — 계정과 Claude 연결

> **이 문서가 답하는 질문 하나: 개발자가 기획자 한 사람을 위해 계정을 만드는 것부터, 그 사람이 AI 에게 말로 지시할 수 있게 되기까지, 무엇이 일어나나.**
> 프로젝트가 어떻게 생기는지는 여기 없다(→ `project-setup`). 항목을 어떻게 다루는지도 여기 없다.

`project-setup` 이 프로젝트 쪽을 세웠다. 이 문서는 **사람 쪽**이다. 둘이 짝이다.

---

## 자격이 둘이다

빌더는 사람마다 **성격이 다른 두 가지**를 들고 있다.

| | 무엇 | 누가 만드나 | 없으면 |
|---|---|---|---|
| **빌더 신원** | 아이디 · 비밀번호 · **이름 · 메일** | 개발자(슈퍼계정) | 로그인이 안 된다 |
| **Claude 자격** | 본인 Claude 계정에서 받은 토큰 | **사용자 본인** | 로그인은 되는데 **AI 가 안 돈다** |

하나로 합치지 않은 이유가 이것이다 —
**「로그인은 되는데 AI 가 안 도는」 상태가 실제로 있다.** 합치면 그 상태를 표현할 수가 없다.

**이름과 메일이 그대로 커밋 author 가 된다.**
`planner-one-flow` 칸 1 이 「로그인한 기획자가 그대로 커밋 이름이 된다」고 정해둔 것이 여기서 값을 한다.

**2026-08-31 변경:** 기획자와 슈퍼관리자 모두 본인 Claude 자격을 연결한다.
역할은 관리 권한을 가를 뿐, AI 기능에 필요한 개인 자격을 대신하지 않는다.

---

## 칸 넷

| | 칸 | 무슨 일이 일어나나 |
|---|---|---|
| 1 | **계정 만들기** | 슈퍼계정이 **이름 · 메일 · 임시 비밀번호**를 만든다. 이 자리에서 **Claude 는 안 건드린다** |
| 2 | **전달** | 아이디와 임시 비밀번호를 사람에게 건넨다. **빌더 밖의 일**이다 |
| 3 | **최초 로그인** | **비밀번호 바꾸기**는 필수다. 역할과 관계없이 이어서 Claude 계정을 연결하거나 `나중에 연결`을 고른다 |
| 4 | **프로젝트 고르기** | 기획자는 프로젝트 목록으로, 슈퍼계정은 프로젝트가 없으면 프로젝트 관리로 이동한다. **여기서 이 문서는 끝난다** |

## Claude 연결 — 사용자는 토큰을 보지 않는다

```
[ Claude 계정 연결하기 ]
   │
   ├─ 빌더가 인증 주소를 띄운다  ──▶ 새 창에서 본인이 승인
   │
   └─ 돌아와서 「연결을 확인한다」를 누른다
          └─ 빌더가 토큰으로 바꿔 받아 보관한다
```

**사용자가 하는 일은 「승인」과 「돌아와서 한 번 누르기」 둘뿐이다.**
터미널을 열지 않고, 토큰 문자열을 보지 않는다.

⚠ **2026-08-14 실측 — 끝나는 길이 둘이고 미리 못 고른다.** 승인 창이 **스스로 끝내는** 경우가 있고
(그때는 붙여넣을 코드를 안 준다) **코드를 주는** 경우가 있다. 같은 기계에서 같은 날 둘 다 났다.
그래서 화면은 **「연결을 확인한다」 한 번 누르기**를 기본으로 두고, 코드 칸은 **접어서 대체 길**로 내린다.
⛔ 어느 한 길만 전제하면 다른 길에서 **화면이 영영 안 끝난다.** 실측은
`docs/decided-facts.md` 의 「Claude 개인 자격을 서버가 어떻게 쥐나」가 정본이다.
「HTML 을 안 보게 한다」는 이 도구의 취지가 자격 만드는 자리에서도 그대로 간다.

최초 로그인에서 연결하지 않아도 Builder에는 들어갈 수 있다. 이때 계정 상태는 `Claude 연결 필요`이며
AI가 필요한 행동을 시작하면 연결 화면으로 안내한다. 사용자 메뉴에서도 같은 화면을 다시 열 수 있다.

---

## 토큰을 어떻게 두나

**사람마다 하나씩, 암호로 잠가 서버에 둔다.** 푸는 열쇠는 **설치 설정**에 있고 저장소에는 없다.
서버 파일이 통째로 새도 그것만으로는 안 열린다.

⛔ **서버 전체에 Claude 자격을 설정해 두지 않는다.**

그런 것이 하나라도 있으면 **개인 토큰이 전부 무시되고 조용히 그것으로 나간다.**
오류가 안 난다. 누가 얼마 썼는지가 통째로 뒤섞이고,
사람마다 자격을 나눈 뜻이 그 자리에서 사라진다.

---

## 확인은 BRD 를 열 때

토큰은 언젠가 만료된다. 확인하는 자리를 하나로 못 박는다.

```
BRD 열기 (「이대로 시작」)
   ├─ git fetch origin          ← project-setup
   ├─ Claude 자격 확인          ← 이 문서
   └─ 워크트리 따기
```

만료됐으면 **BRD 가 안 열리고** 「Claude 계정 다시 연결」이 뜬다. 재연결은 칸 3 과 같은 화면이다.

**일하는 도중에 끊지 않는다.** 지시를 다 써놓고 돌렸는데 그제서야 막히면
쓴 것을 들고 오갈 데가 없다. 일을 시작하는 순간이 유일하게 「지금 확인해야 하는」 자리다.

---

## 왜 개인 계정인가 — push 와 반대로 가는 자리

`push` 는 **개인 GitLab 토큰을 서버에 안 맡긴다**고 정했다.
여기서는 **개인 Claude 토큰을 맡는다.** 같은 논리를 반대로 쓰는 것이니 근거를 적어둔다.

1. **새면 잃는 것이 다르다.** GitLab 토큰이 새면 남이 **회사 코드에 쓴다.**
   Claude 토큰이 새면 **남의 사용량이 나간다.** 되돌릴 수 있는 피해와 없는 피해다
2. **공용으로 묶을 수가 없다.** 요금과 한도가 각자 구독에 붙어 있다.
   하나로 묶으면 「누가 얼마 썼나」를 빌더가 직접 세야 한다
3. **Git 을 모르는 것과 Claude 를 모르는 것은 다르다.**
   Claude 계정은 이미 본인 것이고, 연결은 버튼 두 번이다.
   GitLab 토큰은 발급받아 오라고 시켜야 했다

## 정한 것과 그 이유

| 무엇 | 정한 것 | 왜 |
|---|---|---|
| 자격의 개수 | **빌더 신원 + Claude 자격, 둘** | Claude 연결을 미뤄도 로그인은 가능하고 AI만 사용할 수 없는 상태를 표현해야 한다 |
| Claude 자격 | **사람마다 본인 계정** | 요금·한도가 각자 구독에 붙는다. 새도 나가는 것은 사용량이지 회사 코드가 아니다 |
| 토큰 받는 법 | **빌더가 안내해 끝낸다** | 기획자에게 터미널을 열게 하지 않는다. 승인과 코드 하나가 전부다 |
| 토큰 두는 곳 | **사람마다 하나씩 잠가서. 열쇠는 설치 설정** | 서버 파일이 새도 그것만으로는 안 열린다 |
| 서버 공용 Claude 자격 | **두지 않는다** | 하나라도 있으면 개인 토큰이 조용히 무시된다. 오류조차 안 난다 |
| 만료 확인 | **BRD 를 열 때** | fetch 와 같은 자리. 지시를 써놓고 돌린 뒤에 막히면 쓴 것이 갈 데가 없다 |
| 계정 전달 | **임시 비밀번호 + 최초 로그인 때 변경** | 초대 링크는 만료·재발급을 또 정해야 한다 |
| 커밋 신원 | **계정의 이름과 메일** | 첫 문서가 「로그인한 기획자가 커밋 이름이 된다」고 정했다 |
| 슈퍼계정 | **본인 Claude 자격을 연결한다. 비밀번호도 바꾼다** | 관리 권한과 AI 실행 자격은 별개다 |
| 프로젝트 접근 | **등록된 것 전부** | `project-setup` 과 같은 판단 — 계정×프로젝트 연결표를 두지 않는다 |

---

## 여기 없는 것

안 겪은 일이라 세우지 않았다. 겪으면 그때 이 문서를 고친다.

- 계정 **수정 · 삭제 · 잠금**
- 비밀번호 찾기
- 사용량 보여주기
- 만료 **미리** 알림

---

## 이 줄기가 기대는 전제

빌더가 만들지 않는다. **없으면 이 줄기가 서지 않는다.**

1. **기획자에게 본인 Claude 계정이 있다.** 회사가 사줬거나 본인 것이거나 — 빌더가 만들어주지 않는다.
2. 기획자가 **브라우저로 claude 에 로그인해 승인**할 수 있다.
3. **슈퍼계정이 서 있다.** (→ `project-setup` 칸 0)

프로젝트는 전제가 아니다 — 하나도 없어도 계정은 서고 로그인도 된다. **프로젝트 고르기가 비어 보일 뿐**이다.

---

## 여기서 끝난다

프로젝트 고르기가 뜨면 끝이다. 사람은 이제 프로젝트를 고르고 일을 시작할 수 있다.

다른 문서로 가는 것들:

- **프로젝트가 어떻게 빌더에 생기나** — 이 문서의 짝. 고를 프로젝트를 만들어 내는 곳이다
- **접수** — 요구사항이 어떻게 항목으로 들어오나
- **기획자가 화면 하나를 고치는 한 줄기** — 이 문서가 세운 자격으로 AI 를 돌린다
