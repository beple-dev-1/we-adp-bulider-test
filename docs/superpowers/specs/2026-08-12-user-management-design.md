# 슈퍼관리자는 Builder 사용자를 어떻게 등록하나

> **이 문서가 답하는 질문 하나: 슈퍼관리자가 Builder 사용자 목록을 확인하고 새 기획자 계정을 만드는 화면은 어떻게 구성되는가.**

## 관리 대상

사용자 관리는 Builder에 로그인하는 내부 계정을 다룬다. GitLab 계정이나 프로젝트 구성원을 관리하지 않는다.
등록된 기획자는 준비된 프로젝트를 모두 볼 수 있다.

최초 슈퍼계정은 설치 설정으로 한 번 만들어지는 운영 계정이다. 사용자 등록 화면에서 슈퍼관리자를 추가하지 않는다.
슈퍼계정은 목록에는 표시하지만 Claude 계정 상태는 `해당 없음`으로 표시한다.

## 목록

목록에서 다음을 확인한다.

- 이름과 로그인 아이디
- 이메일
- 권한: 슈퍼 관리자 또는 기획자
- 최초 설정: 비밀번호 설정 필요 · Claude 연결 필요 · 설정 완료
- Claude 계정: 해당 없음 · 연결 전 · 연결 완료

Claude 연결을 미룬 기획자는 로그인할 수 있으므로 `Claude 연결 필요`는 사용 중지 상태가 아니다.

## 새 사용자 등록

슈퍼관리자가 입력하는 값은 로그인 아이디·이름·이메일·임시 비밀번호다. 모두 필수다.
이름과 이메일은 기획 저장소 커밋 작성자 정보로 사용한다. 새로 등록되는 계정의 권한은 기획자로 고정한다.

등록 뒤 로그인 아이디·임시 비밀번호·Builder 접속 주소를 사용자에게 전달한다. 전달은 Builder 밖에서 한다.
사용자는 최초 로그인에서 비밀번호를 바꾸고 Claude 연결 여부를 선택한다.

## 임시 비밀번호 재발급

사용자가 비밀번호를 잊으면 슈퍼관리자가 사용자 상세에서 임시 비밀번호를 다시 발급한다.
발급하면 그 계정은 다시 `비밀번호 설정 필요` 가 되고, 최초 로그인 흐름을 한 번 더 밟는다.

새 임시 비밀번호는 **발급 직후 화면에 한 번만 보여 준다.** Builder 는 그것을 어디에도
다시 보여 주지 않는다 — 전달은 Builder 밖에서 한다.

⚠️ **`사용자 정보 수정` 은 아직 범위 밖이다**(2026-08-14 병주 결정). 목업 `00f` 에서 그 버튼을 지웠다.

## 이번 범위에 없는 것

- 사용자 수정·삭제·잠금
- 추가 슈퍼관리자 생성
- 계정별 프로젝트 접근 설정

이 기능이 필요해지면 목록의 임의 행동 열에 먼저 넣지 않고 별도 질문으로 설계한다.
