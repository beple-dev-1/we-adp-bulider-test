# 신규 화면의 이름을 누가 언제 짓나

> **2026-08-22 · 병주 확정.** 결정과 못만 남긴다 — 구현은 저장소가 정본이다.

> **2026-08-26 변경.** `tmp-*`를 내부 작업 키로 유지하는 결정은 그대로다. 다만 개발요청서에는
> 별도로 예약한 개발 전달용 **화면 ID**와 `<화면 ID>.html` 파일명을 고정한다. `PS-*`는
> **화면 관리번호**이며 미확정이어도 개발요청을 차단하지 않는다. 정식 IA 위치도 후속 화면 관리에서
> 확정하며, FRD 완료 시 시스템 IA 문서를 자동 변경하지 않는다. 아래의 표준 화면ID 중심 설명은
> 2026-08-26 이전 결정 이력으로 읽는다.

## 문제

`fragments/frd-screen-dialog.html` 의 「신규 화면 개발」이 화면ID 를 **자유 입력**으로 받는다.
형식도, 기존 508장과의 중복도, 다른 FRD 가 만든 신규 화면과의 중복도 안 본다
(`FrdService.validateSelection`·`addScreen`). 그리고 그 값이 그대로
**클론 안의 파일 이름**이 된다 (`ScreenMockupWorker.safeScreenFile` — `core/<시스템>/pages/<화면ID>.html`).

## 결정 — 이름이 둘이고, 나는 시점이 다르다

| | 임시 화면ID | 표준 화면ID |
|---|---|---|
| **값** | `tmp-0000042` (`tmp-` + `adk_builder_frd_screen` 의 기본키) | `PS-BO-MRC-010-L02-N` |
| **언제** | 「신규 화면 추가」를 누를 때 | **개발요청서를 만들 때** (`DevelopmentRequestService.createFromFrd` → `ScreenStandardIdService.allocateForNewScreen` · **2026-08-25 구현**) |
| **어디** | `adk_builder_frd_screen.screen_id` | `adk_builder_screen_standard_id` (`origin = 'N'`) |
| **쓰는 자리** | 파일 경로 · 동시편집 잠금 · FRD·IA 조인 | 개발요청서 · 화면 목록 표시 |
| **재료** | **없다** | 기준 화면의 시스템·업무영역·기능그룹·유형 + 그 묶음의 `max + 1` |

### 왜 표준 채번을 개발요청서까지 미루나

**화면을 만드는 순간에는 재료가 안 익었다.** 유형(`L`·`D`)도 메뉴 자리도 그때는 기준 화면에서
빌려 온 짐작이고, FRD 작업이 끝나야 확정된다. 그 짐작으로 이름을 지으면 **나중에 다시 지어야** 하고,
그 순간 파일 이름 · 화면 이력 · 동시편집 잠금이 흔들린다.

**개발요청서는 표준 화면ID 가 처음으로 「필요한」 자리다** — 밖으로 나가는 문서이기 때문이다.
그때는 재료가 다 모였다. **미루니 「다시 짓기」라는 것이 아예 없어졌다.**

### 왜 `tmp-` + 기본키인가

기본키는 `IdSequence.Kind.FRD_SCREEN` 이 이미 일곱 자리로 낸다 — **새 채번기가 0개**, 중복이
**구조적으로 불가능**, 기준 화면의 IA 자리도 유형도 안 본다(**번호를 못 받은 화면도 기준이 될 수 있다**).
**뜻이 없는 것이 의도다** — 뜻을 담으면 그 뜻이 틀렸을 때 이름이 거짓말이 된다.

⭐ **기본키는 행을 앉힐 때만 나온다.** 그래서 **누구도 미리 이름을 가질 수 없다** — 사람도, AI 도,
미리보기도. 구조가 아래 못 넷을 대신 지켜 준다.

## 레이어 — 탭 셋, 묻는 것 둘

```
[1] 기존 화면 추가        [2] 이미 만든 신규 화면        [3] 신규 화면 개발
    현재 운영 화면            이 프로젝트가 만든 것            기준 화면 + 새 화면명
```

**2번이 새 탭이다.** 이름 짓기는 **중복을 못 막는다** — 두 사람이 같은 화면을 만들면
`tmp-0000042` 와 `tmp-0000043` 이 나란히 난다. 신규 화면 목업은 그 FRD 의 워크트리에만 쓰이고
커밋되지 않으므로 다른 FRD 가 못 본다. **빌더 DB 가 명부다.**

3번 탭에서 기준 화면을 고를 때, 그 기준으로 만든 신규 화면이 이미 있으면 경보를 띄우고 2번 탭으로
보낸다 — **화면에 이미 실려 있는 2번 탭 목록으로 판단한다. 서버에 다시 묻지 않는다.**

⚠ 2번 탭에서 고른 화면은 「기존 화면 추가」와 같은 길로 앉는다(`screenId = baseScreenId = 그 화면ID`).
그래서 `addScreen` 의 기준 검사는 **클론에 있거나, 이 프로젝트가 이미 쓰는 화면ID 이거나** 둘 중
하나면 통과한다.

## 개발이 정한 진짜 이름

`adk_builder_frd_screen.confirmed_screen_id` 한 열이 받는다. **`screen_id` 는 안 바뀐다** —
바꾸면 `screenId` 를 붙든 파일 30여 개가 이사한다(목업 · 화면 이력 · 화면별 대화 · IA 조인 ·
개발요청서 본문). 개발요청서가 「임시ID ↔ 표준ID」 짝을 실어 나가고, **파일을 만드는 것은 개발이다.**
⛳ 채우는 역류 창구는 그린존이라 지금 안 만든다 — **열만 낸다.**

## ⛔ 못

| # | 못 | 왜 |
|---|---|---|
| 1 | **표준 채번을 화면 추가 시점으로 되돌리지 마라** | 재료가 안 익었다. 되돌리면 「다시 짓기」가 되살아난다 |
| 2 | **표준 화면ID 를 파싱해 업무영역·유형을 알아내지 마라** | 유형 마디는 기준 화면에서 물려받은 **짐작**이다. 아무도 안 파싱하기 때문에 틀려도 안 깨진다 |
| 3 | **표준 화면ID·`confirmed_screen_id` 로 화면을 찾지 마라** | 조회·잠금·경로·조인의 열쇠는 언제나 `screen_id` 다 |
| 4 | **이름을 미리 내주는 API 를 만들지 마라 — 사람에게도 AI 에게도** | 아래 |
| 5 | **개발요청서 만들기 안에서 AI 를 부르지 마라** | `createFromFrd` 는 동기 트랜잭션 하나다(실측). 버튼이 몇 분 멈추고 커넥션 풀이 굶는다 |
| 6 | **기본키로 파일 경로를 짓지 마라** | 같은 화면을 다음 FRD 가 이어 작업하면 그 행의 기본키는 다르지만 화면ID 는 그대로다 |
| 7 | **기준 화면 목록을 번호 유무로 거르지 마라** | 임시 이름은 재료를 안 본다. 번호 없는 기준으로 만든 화면은 「번호 없음」으로 나갈 뿐이다 |

### 못 4 를 푼다 — 사람에게도, AI 에게도

**사람에게**: 지어진 화면ID 를 레이어에 **보여 주지 않는다** (병주 지시 —
*"기획자는 화면ID를 확인할 이유는 없어, 그 팝업에서"*). 보이면 확인할 것이 되는데 판단할 재료가 없고,
지어지는 것이 `tmp-0000042` 라 **볼 것도 없다.**
⚠ 1번·2번 탭의 화면ID 는 남긴다 — 그건 「이미 있는 화면을 가려내는 이름표」라 성질이 다르다.

**AI 에게**: AI 가 신규 화면을 짚게 되면 **`{isNew, screenName, baseScreenId}` 까지만 내게 한다.**
이름은 행을 앉히는 코드가 붙인다 — 사람이 만들든 AI 가 짚든 **같은 자리를 지난다.**

| 왜 AI 에게 채번 API 를 주면 안 되나 | |
|---|---|
| **AI 호출은 재시도가 기본이다** | `ScreenPickWorker` 는 모델을 여러 개 돌린다. 채번은 부작용이라 재시도 자리에 두면 **버려진 번호가 쌓인다** |
| **AI 출력은 아직 검증 전이다** | 사람이 「이 화면은 빼자」 하면 딴 번호가 허공에 뜬다 |
| **못이 이미 있다** | 지시문이 *"`index.json` 에 있는 화면ID 만 적어라"* 다. 짓게 하면 **환각한 화면ID 가 파일 이름이 된다** |

## 밖에 걸어 둔 것

- **기획 레포 검사기가 `tmp-` 화면ID 를 받나** — 클론이 없어 실측 못 했다.
  `docs/requests-to-planning-repo.md` §5 에 「빌더는 이렇게 짓는다」를 적고 답을 받는다
- **역류가 진짜 이름을 어떤 꼴로 실어 오나** — 그린존이다. 받을 열만 비워 둔다
- **`FrdScreen` 이 유형 칸을 갖나** — 가지면 표준 채번의 유형이 짐작을 면한다. **한 줄이다**
