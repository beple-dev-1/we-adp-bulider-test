# 프로젝트 관리는 어디에서 여는가

> **이 문서가 답하는 질문 하나: 최초 슈퍼계정이 프로젝트와 Builder 계정을 관리하는 화면은 어디에서 여는가.**

## 결정

프로젝트 관리는 산출물 왼쪽 메뉴나 `설정`에 두지 않는다.
오른쪽 위 슈퍼계정 메뉴의 **`관리`**에서 연다.

```text
오른쪽 위: 슈퍼관리자
├─ 관리
│  ├─ 프로젝트 관리
│  └─ 사용자 관리
├─ 비밀번호 변경
└─ 로그아웃
```

`관리`를 열면 프로젝트 작업 화면과 분리된 관리 셸을 사용한다. 관리 셸의 왼쪽 메뉴는
`프로젝트 관리`, `사용자 관리` 두 항목이며 기본 진입 화면은 `프로젝트 관리`다. 이 구조는 현재 공통 셸의
관리 메뉴 계약과 `/admin/projects` 경로를 유지한다.

## 두 관리 화면의 책임

### 프로젝트 관리

Builder가 사용할 기획 저장소의 연결을 슈퍼계정이 관리한다.

- 프로젝트 이름과 GitLab 저장소 정보 등록
- 기본 브랜치 등록
- 저장소 받기 상태 확인
- 저장소 받기 재시도
- 만료된 프로젝트 토큰 교체
- 적용 구분 항목 등록과 수정 (익산·제주처럼 한 시스템 안에서 요구사항이 갈리는 기준.
  ⚠ 0개가 정상이다 — 그러면 그 프로젝트엔 적용 구분 축이 아예 없다. `data-model.md` §6)

GitLab 토큰은 Builder 로그인 계정이 아니다. 프로젝트 저장소에 접근하기 위한 자격이며
프로젝트마다 관리한다.

### 사용자 관리

`사용자 관리`는 **이 Builder에 로그인해 사용하는 내부 사용자 계정**을 관리한다.

- 기획자 계정 생성과 상태 확인
- 비밀번호 초기화 등 Builder 접근 관리

GitLab 계정이나 프로젝트별 구성원 목록을 관리하지 않는다. 등록된 Builder 계정에는 준비된
프로젝트가 모두 보이며, 별도의 계정-프로젝트 연결 기능은 두지 않는다.

## 최초 진입

최초 슈퍼계정으로 로그인했는데 등록된 프로젝트가 하나도 없으면 메뉴를 찾아가게 하지 않고
프로젝트 관리 화면으로 바로 이동한다. 프로젝트 등록과 저장소 받기가 끝나 `준비됨`이 되면
해당 프로젝트의 `받은 문서` 화면으로 이동할 수 있다.

프로젝트가 이미 있는 뒤에는 어느 화면에서든 오른쪽 위 슈퍼계정 메뉴의 `관리`로 다시 들어간다.
일반 기획자에게는 `관리` 진입점을 표시하지 않는다.

## 배치하지 않는 곳

- **산출물 왼쪽 메뉴:** 선택한 프로젝트의 현재 산출물 10종만 둔다. 서버 전체 관리 기능을 섞지 않는다.
- **설정:** 개인 환경설정이나 현재 프로젝트 옵션으로 오해하기 쉽다. 슈퍼계정의 운영 책임은
  `관리`라는 이름으로 드러낸다.
- **프로젝트 선택 목록:** 프로젝트를 바꾸는 기능과 프로젝트를 등록·복구하는 기능을 한 팝업에
  섞지 않는다.

## 목업 범위

슈퍼계정용 관리 셸의 `프로젝트 관리` 화면은 목록에서 프로젝트 이름, 저장소,
기본 브랜치와 상태를 확인하고 새 프로젝트를 등록할 수 있어야 한다. 복구 행동은 목록 열에 섞지 않고
프로젝트 이름을 눌러 여는 상태별 상세 화면에 둔다. 등록 입력이 많으므로
목록 위의 작은 레이어에 모두 넣지 않고 독립 등록 화면을 사용한다.

`사용자 관리` 화면의 상세 구성은 `2026-08-12-user-management-design.md`가 맡는다.
