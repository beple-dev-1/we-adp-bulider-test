# 추출기 실측 — 무엇을 내고 무엇을 안 내나

> **이 문서가 답하는 질문 하나: 추출기가 실제로 기획 레포에 무엇을 내주나.**
> 무엇을 더 해달라고 할지는 여기 없다 — 그건 `docs/requests-to-extractor.md` 와 `docs/requests-to-planning-repo.md` 다.

**잰 날: 2026-08-09.** 잰 대상은 옆 워크스페이스 `../extractor` 의 **커밋 `bb56161`**
(`bb561614bb18d2ba394e972f3c5be00a1c47c454`) 작업트리다.
**문서가 아니라 코드로 쟀다** — 규격 문서와 코드가 갈리는 자리가 실제로 있었고, 그때는 코드를 적었다.

**다시 재는 법**: 그 저장소에서 `git rev-parse --short HEAD` 로 지금 판을 확인하고,
`bb56161` 과 다르면 아래 수치는 다시 재야 한다. **계속 개발 중인 저장소라 날짜만으로는 부족하다.**

⚠️ **절마다 잰 날과 커밋이 다르다.** 위 `bb56161` 은 §1~§10 것이다 —
**§11 은 `c3837a6`(2026-08-14) · §12 는 `37a25fb`(2026-08-15)** 이고 각 절 머리에 적어 뒀다.

⚠️ **이건 사실이고 계획이 아니다.** 새 계획을 쓸 때 여기 있는 것은 다시 재지 않는다.
⚠️ **추출기는 계속 개발 중이다.** 여기 「없다」로 적힌 것이 나중에 생길 수 있다 — 착수 전에 다시 재라.

## 1. 갓 나온 기획 레포는 비어 있다

추출기 3단계(`emitTree`)가 내는 것은 **저장소 한 채의 뼈대**이고, 내용물이 없다.

| 자리 | 갓 나왔을 때 |
|---|---|
| `core/<시스템>/pages/` | **`.gitkeep` 뿐** |
| `core/<시스템>/assets/` | **`.gitkeep` 뿐** |
| `core/<시스템>/styleguide.md` | 울타리(`<!-- classes:begin/end -->`)만 있고 **안이 비었다** |
| `domains/` | **`.gitkeep` 뿐** |
| `reqs/` | **`.gitkeep` 뿐** |
| `spec/` | 규격 6장 (`page`·`domain`·`reqs`·`anchor`·`manifest`·`layout`) |
| `verify/` | **검사기 실물 통째** (`node_modules` 제외) |
| `.claude/skills/extract-planning-repo/` | 추출기 스킬 사본 |
| `taxonomy.md` · `README.md` · `CLAUDE.md` · `.gitignore` · `.gitattributes` | 각 한 장 |
| `manifest.json` · `index.json` | 각 한 장 |

⛔ **화면이 0개다.** 운영 화면(v1 기준 508장)을 옮기는 **변환기가 아직 없다** — 추출기 단계 2 일감이다.
**빌더가 클론해도 볼 화면이 없다.** 시연·개발 일정을 여기에 맞춰야 한다.

**`source-index.json` 은 이때 안 나온다.** 4단계(`scan.mjs`)가 소스를 훑을 때 나오고,
그 파일이 생기는 순간 `manifest.json` 에 그 줄이 함께 적힌다.

## 2. 추출기가 아는 층은 셋뿐이다

```
core/<시스템>/pages/     사실 — 소스에서 유래한 화면          (시스템 축)
domains/<도메인>/<모듈>.md  사실 — 화면 없는 업무 규칙·흐름     (도메인 축)
reqs/<과업ID>.md          판단 — 있어야 할 것 (사람이 채운다)  (과업 축)
```

**빌더의 층 다섯 중 셋이 추출기에 없다** — 요구사항정의서 · BRD · 개발요청서.
작업 목업 · 추적 매트릭스도 없다. 추출기 문서 전체에 그 이름들이 **0건**이다.

이건 빠뜨린 것이 아니라 **경계다.** 추출기는 *"빌더를 모른다. 기획 레포를 직접 쓰지 않는다"* 를 선언한다.

### 「목업」이라는 말이 추출기에 없다

`pages/<화면ID>.html` 은 규격상 **"사실 — 소스에서 유래한 화면"** 이고 v1 에서 **무변환**으로 옮겨온다.
빌더가 부르는 「③ 솔루션 목업」이 그것이다. **「작업 목업」은 빌더만 쓰는 말이다.**

---

## 3. 업무 ↔ 화면 연결은 없다 — 그리고 안 만들기로 한 것이다

근거 넷 (전부 코드):

1. `manifest.json` 의 `systems[]` 와 `domains` 는 **서로를 참조하지 않는 별개 필드**다.
2. `index.json` 은 `screens[<화면ID>] = { system }` 뿐 — **도메인 칸이 없다.**
3. `source-index.json` 에 **도메인 축이 없다.**
4. 앵커 검사는 `reqs/` → (`core/` | `domains/`) **한 방향**뿐이다.

추출기 설계가 *"축이 셋 다 다르므로 섞지 않는다"* 로 명시했다. **기다려도 안 온다.**

### 다만 — 연결이 아예 없는 것은 아니다

`reqs/<과업ID>.md` 한 장이 **화면 앵커와 도메인 앵커를 같이 부르면** 그 파일이 곧
「이 업무가 이 화면에 걸린다」이고, 검사기 A-3 가 그 둘의 실재를 이미 확인한다.

없는 것은 연결이 아니라 **화면 기준 역인덱스**다 — 「이 업무에 속한 화면 전부」를 한 번에 뽑는 길.
그건 `reqs/` 가 차면 파생물로 구울 수 있는 것이지 새 규격이 아니다.

⚠️ 예약된 이름 `domain-index.json` 은 **이 매핑이 아니다.** 모듈↔소스파일 커버리지 등식용이고,
구울 도구가 없어 `manifest.json` 에 선언조차 안 돼 있다.

> **값도 자리도 왔다** — 커밋 `c3837a6` 에서 화면 **251장**이 소속을 얻었고, IA 의 정본이
> 화면 md 가 아니라 `core/<시스템>/ia.md` 의 `--- 배치 ---` 블록(행 92개)으로 옮겨졌다.
> **지금 살아 있는 실측은 `docs/requests-to-extractor.md` 8번**이다. 아래는 이력으로만 남긴다.

- 추출기는 IA 를 **명시적으로 안 내기로 결정했다.**
- 대신 *"메뉴는 이미 화면 md 에 있으니 `index.json` 이 인덱싱하면 된다"* 고 적었는데,

**빌더가 IA 를 AI 의 재료로 쓰려면 그 자리를 새로 열어야 한다.**

## 5. 검사기 — 실제로 무엇을 하나

**호출 모양은 하나뿐이다.** `node verify/run.mjs <레포뿌리>` — 인자는 뿌리 하나이고,
안 주면 `.` 으로 본다. **파일 경로 인자도, 플래그 파싱도 코드에 없다.**

**실제로 도는 게이트 12개**

| ID | 무엇을 보나 |
|---|---|
| MANIFEST | `manifest.json` 존재·JSON·`systems[]` 필수 칸·선언한 폴더 실재 |
| A-1 | `pages/` 의 html·md 짝, 폴더 혼입, 대문자 확장자 |
| A-2 | html 의 `data-screen-id` 가 파일명과 같은가 |
| A-3 | `reqs/` 의 앵커가 화면·도메인에 실재하는가 |
| A-4 | **화면 md 안에서** 앵커 번호표가 유일한가 (도메인 md 는 안 본다) |
| A-5 | html 의 class 가 `styleguide.md` 허용목록 안인가 |
| A-6 | 커밋된 `index.json` 이 재생성 결과와 같은가 |
| A-7 | 정의 블록의 `구분` 값이 `항목`·`기능`·`이동` 중 하나인가 |
| A-0 | 정의 블록 줄이 슬롯으로 모호함 없이 갈리는가 |
| COVERAGE | `source-index.json` 의 `scanned = templates + excluded`, 그리고 판 번호·모듈별 출처의 모양 |
| PARSE | 같은 파일의 `opaque_refs = resolved + declared` |
| RATCHET | 사람이 볼 항목(review)이 기준선보다 늘었는가 |

**종류는 폴더 위치로 안다** — `manifest.json` 이 선언한 경로 트리가 전부다. 내용이나 인자로 판별하지 않는다.

⚠️ **이건 파일이 레포 안 제자리에 있을 때만 참이다.** 레포 **밖**의 임시 파일(빌더가 DB 초안을 뱉은 것)은
앉은 자리가 없으므로 **종류를 못 정한다.** 그래서 「검사기에 종류를 알려줄 길이 필요한가」는
레포 안 파일에 한해 닫혔고, **레포 밖 파일을 검사하려는 순간 다시 열린다.**

### 빌더가 걸리는 자리 넷

1. **파일 한 장만 넘겨 판정받을 수 없다.** 진입점이 없고, A-1·A-3·A-4·A-6·COVERAGE 가 레포 전집을 요구한다.
2. **검사할 파일을 인자로 못 준다.** 확정 전 초안을 레포 밖에 두면 검사할 방법이 없다.
3. **결과가 기계가 읽을 형식이 아니다.** 종료코드 + 사람이 읽는 글뿐이고 JSON 출력 모드가 없다.
   글 모양은 `✘ {파일}:{줄}   [{게이트}] {무엇}` · `→ {고칠 것}` · `검사 통과 — green` · `red N건 · 사람이 볼 M건` 인데,
   **규격으로 약속된 것이 아니라 지금 코드가 그렇게 찍을 뿐이다.**
4. **BRD · 개발요청서 · 메뉴구조도 · 목업을 보는 게이트가 하나도 없다.**

### 반가운 것 하나

**`run` 은 순수 읽기다** — 파일을 쓰지 않는다. 쓰는 것은 `reindex` 뿐이다.
그래서 **여럿이 동시에 검사기를 돌려도 서로를 덮어쓰지 않는다.**
전에 「동시에 돌리면 서로의 초안을 덮어쓴다」고 걱정한 것은 검사기 실행 자체로는 사실이 아니다 —
부딪히는 것은 초안을 레포 안에 **써 넣는** 행위다. 워크트리가 갈라져 있으면 그것도 안 부딪힌다.

## 6. 추출기가 「빌더가 정한다」고 넘긴 것 셋

규격 본문이 명시적으로 빌더에게 공을 넘긴 자리다. **기획팀에 물을 것이 아니라 빌더가 정할 것이다.**

| 무엇 | 규격이 뭐라 했나 |
|---|---|
| **`index.json` 이 담을 필드** | *"빌더가 화면 목록 UI 를 실제로 그려 본 뒤에 정한다"* |
| **`<과업ID>` 의 형식과 발번 주체** | *"정해지지 않았다 … 빌더가 착수할 때 정한다"* |
| **소스 색인이 낡았는지 판정** | *"근거는 색인 안의 `source.modules[].commit` 이고, 그 판정은 빌더가 한다"* — 색인 `/2` 부터 출처는 **모듈마다** 담긴다(모듈별로 저장소가 다르면 커밋도 다르다). **빌더에 그 판정 코드는 아직 없고**, 빌더는 운영 소스에 닿을 자격증명을 갖지 않기로 설계됐다 — 「굽는 쪽이 증명하나 읽는 쪽이 판정하나」가 아직 안 열린 질문이다 |

## 7. 검사기가 지금 못 잡는 것 (규격 문서가 스스로 밝힌 것)

- **역방향 고아 앵커** — 화면·도메인이 발번했는데 `reqs/` 어디서도 안 부르는 번호표는 검사하지 않는다.
- **도메인 md 안의 중복 앵커** — 화면 md 는 A-4 로 잡지만 도메인 md 는 안 본다.
- **도메인 앵커 표기가 두 갈래다** — `<모듈>#rule-07` 과 `<도메인>/<모듈>#rule-07`. 정본 미확정이고,
  검사기는 문자열 그대로만 맞춰서 반대쪽이 거짓 고아가 된다.
- **`좌표:`·`라벨:` 값이 소스에 실재하는지** 대조하는 게이트가 없다 — 지어낸 값인지는 사람이 봐야 한다.
- **색인이 낡았는지** 안 본다 — 옛 색인이 제자리에 있으면 소스가 바뀐 뒤에도 green 이 나온다.
- **`manifest.taxonomy`** 를 어느 게이트도 안 읽는다 — 적어 놓고 파일을 지워도 green 이다.
- **`source-index.json` 에 시스템 축이 없다** — 한 시스템의 화면을 통째로 빠뜨려도 커버리지 등식이 닫힌다.

## 9. 어휘가 부딪힌다

**나가는 규격 본문이 「과업」을 쓴다** — `spec/reqs.md`(`# 요구사항 — reqs/<과업ID>.md` · "과업 1개 = 파일 1개" · 예시 본문 `# 과업` 등)와

| `spec/` | — | **7장** — `anchor`·`domain`·`ia`·`layout`·`manifest`·`page`·`reqs` |
| `reqs/` | 빔 | **아직 `.gitkeep` 뿐** |
| `pages/` | 빔 | **폴더 자체가 없다** |

### ⛔ 계획 3 의 관문은 아직 안 열렸다

`requests-to-extractor` **B-3** 이 요구한 셋 중 **하나도 안 왔다.** 코드로 쟀다(`verify/run.mjs:90-93`):

```
node verify/run.mjs [--json] [<뿌리>]      ← 인자는 이것뿐이다
```

- ✘ 후보 파일의 실제 경로 · ✘ 레포 안 가상 위치 · ✘ 얹기 전후 진단 차이
- ⛔ **모르는 인자는 조용히 무시된다.** `--file`·`--as` 를 줘도 오류가 아니라 **레포 전체 판정이 그냥 나온다** —
  빌더가 낡은 검사기에 새 인자를 주면 **한 장 판정을 받은 줄 알고 전집 판정을 읽는다.**
  이것이 `requests-to-extractor` **12번(판 번호)** 이 급한 진짜 이유다
- ✔ **`--json` 은 생겼다** — §5 「출력이 사람이 읽는 글뿐」은 해소됐다

### ⛔ 새로 드러난 것 — 클론 직후에는 검사기가 아예 못 돈다

`node_modules` 는 커밋 대상이 아니라 **클론에 안 딸려온다.** 그래서 돌리면 이렇게 끝난다:

```
검사기 의존이 없다 — 패키지 'node-html-parser' 를 못 찾는다.
    cd verify && npm install
```

**실측**: 종료코드 **1** · **stdout 0바이트** · 안내는 stderr. 설계가 그렇게 해 놨다 —
빌더는 「빈 stdout + 1」을 **「판정을 못 냈다」**로 읽으면 되고 초록·빨강과 안 섞인다. **거기까지는 좋다.**

⛔ **그러나 빌더가 답해야 할 것이 새로 생겼다** — **프로젝트마다 `npm install` 을 누가 언제 하나.**
클론 뒤 자동으로 돌릴 것인가, 사람이 할 것인가.

### ⭐ 그래서 재봤다 — 빌더가 스스로 할 수 있다 (같은 날 이어서)

| 잰 것 | 값 |
|---|---|
| `npm install` | **1초 · 안 막힌다** (⚠ Maven 은 사내 TLS 가로채기에 막혔는데 npm 은 안 걸렸다) |

| 워크트리에 `node_modules` | **없다** — 커밋 대상이 아니라 체크아웃에 안 딸려온다 |

⭐ **마지막 두 줄이 짝이다.** 워크트리의 검사기를 부르면 **검사마다 `npm install` 을 새로 한다.**
**클론에 한 번 깔고 그 검사기로 워크트리를 검사하면** 그 값을 안 치른다 — 그래서 빌더의
`CheckerCommand` 는 「검사기가 설치된 자리」와 「검사할 자리」를 **따로 받는다.**

### ⭐ 그리고 「누구 탓인가」를 빌더가 스스로 가를 수 있다 — 실물로 증명했다

워크트리를 따고, 일부러 깨진 요구사항 한 장(`reqs/RQ-TEST-001.md`)을 얹어 전·후를 견줬다:

```
얹기 전 findings: 43  {"red":26,"review":17}
얹은 뒤 findings: 45  {"red":28,"review":17}
★ 새로 생긴 것: 2 — 둘 다 얹은 그 파일만 가리킨다
   [red] reqs/RQ-TEST-001.md:2 (A-3) 앵커 rule-7 가 화면 앵커 형식이 아니다.
   [red] reqs/RQ-TEST-001.md:3 (A-3) 앵커 없는화면-e01 를 가리키는데 그런 번호표가 어디에도 없다.
```

**남이 만든 red 26 개는 하나도 안 섞였다.** 전체 검사를 두 번 돌려도 **2초**다.

⛔ **그러므로 `requests-to-extractor` B-3(「후보 파일을 인자로 받아라」)은 계획 3 의 관문이 아니다.**
없어도 빌더가 한다. **여전히 있으면 좋지만 급한 것은 아니다** — 급한 것은 12번(판 번호)이다.

⚠ **못 잰 것 둘** — **운영 서버(리눅스)에서 npm 이 되는지**, 그리고 **더 큰 사업 레포에서도 1초인지.**

## 12. 검사기가 자기 판을 말한다 — `--json` 계약 실측 (2026-08-15 · `37a25fb`)

**잰 대상**: `../extractor` 커밋 **`37a25fb`**(직전이 `a265e3a` — **한 커밋 차이**다).
**실제로 돌려서 쟀다** — 그 저장소의 검사기로 `../planning-g2c` 를 검사했다.

```bash
cd ../extractor && node verify/run.mjs ../planning-g2c --json
```

### 최상위 키가 넷에서 **여섯**이 됐다

| 칸 | 실측값 | 뜻 |
|---|---|---|
| `toolchain` | `"we-adk-toolchain/1"` | **실제로 돈 검사기 자신의 판.** `manifest.json` 것은 주장, 이것은 증언 |
| `status` | `"complete"` | `complete` = 끝까지 돌렸다 · `incomplete` = **게이트를 하나도 안 돌렸다** |
| `exitCode` | `1` | 프로세스 종료코드와 같다 |
| `counts` | `{"red":27,"review":17}` | ⚠ **래칫 초과분이 `red` 에 더해진다** |
| `findings[]` | 44건 | 키 여섯 고정 — `file`·`line`·`gate`·`level`·`what`·`fix` |
| `ratchet` | `{"status":"ok","baseline":17,"reviewCount":17,"message":null}` | 상태 넷 |

⛔ **판 번호를 `findings[]` 안에서 찾지 마라** — 거기는 키 여섯이 고정이다.

### red 26 → **27**. 늘어난 1건의 정체

```
MANIFEST/red 1 · DOMAIN-COVERAGE/red 13 · IA-1/red 12 · IA-7/red 1
A-3/review 14 · DOMAIN-COVERAGE/review 2 · IA-4/review 1
```

늘어난 것은 `MANIFEST` red 하나다 — *"manifest.json 이 자기 판을 안 밝힌다 — toolchain 칸이 없다."*
**회귀가 아니라 설계된 1건**이고, `planning-g2c` 를 재동기화하면 꺼진다(추출기 쪽 몫).

### 래칫 상태 넷을 손으로 만들어 봤다

`planning-g2c` 사본을 스크래치패드에 뜨고 `index.json` 의 `baseline.review` 만 옮겼다.

| 만든 상태 | `ratchet.status` | `findings` 안 `RATCHET` |
|---|---|---|
| 17 = 17 | `ok` | 0건 |
| **5** < 17 | `exceeded` | **1건** — `{"file":"index.json","line":1,"gate":"RATCHET","level":"red"}` · `counts.red` 에도 더해진다 |
| **30** > 17 | `below` | 0건 (`message` 에 안내만) |
| 기준선 없음 | `none-baseline` | 0건 |

⚠ **`index.json` 을 손으로 고치면 `A-6` red 가 하나 더 붙는다**(재생성 색인과 안 맞는다).
위 표에서 그 1건은 빼고 읽어라 — 내가 만든 것이다.

### 못 돌렸을 때도 **계약 모양을 지킨다**

`node_modules` 없이 `verify/` 만 떠서 돌렸다:

```json
{ "toolchain":"we-adk-toolchain/1", "status":"incomplete", "exitCode":1,
  "counts":{"red":1,"review":0},
  "findings":[{"file":"verify/package.json","line":1,"gate":"DEPS","level":"red", ...}] }
```

⚠️ **`DEPS` 를 「낡은 검사기」로 읽지 마라.** 갓 클론한 레포는 늘 여기 걸리고, 그때도 검사기는 **오늘 판**이다.
갈라 주는 것은 `gate` 다 — **`MANIFEST` 면 재동기화 · `DEPS` 면 `npm install`.**

### 모르는 인자는 이제 **사용법 오류**다

```
node verify/run.mjs ../planning-g2c --bogus --json
→ stderr 에 사용법 · 종료코드 1 · stdout 0바이트  (od -c 로 쟀다)
```

앞자리도 같다. ⚠ **전에는 뒷자리에서 조용히 무시되고 종료코드 0 이 나왔다** —
추출기가 앞자리에서만 확인하고 「지금은 틀렸다」고 회신했다가 스스로 정정해 같이 닫았다.
⚠️ **이미 나간 레포의 옛 검사기에서는 「조용히 무시」가 여전히 참이다.**

### ⛔ 여기서 빌더 결함 하나가 드러났다 — `status` 를 안 읽는다

`manifest.json` 의 `toolchain` 을 `we-adk-toolchain/9` 로 어긋내고 돌렸다:

```json
{ "status":"incomplete", "exitCode":1, "counts":{"red":1,"review":0},
  "findings":[{"gate":"MANIFEST","level":"red","what":"… 지금 돌고 있는 검사기는 we-adk-toolchain/1 이다."}] }
```

**게이트를 하나도 안 돌린 판정이다.** 그런데 `NodeCheckerCommand.parse()` 는 `status` 를 안 읽고
`CHECKED` + red 1건으로 읽는다. `DraftChecker` 는 **얹기 전·후를 견줘 새로 생긴 것만** 탓하므로,
**양쪽에 똑같이 있는 그 `MANIFEST` red 는 상쇄되고 판정이 `GREEN` 이 된다**
(`Finding.key()` 가 `file`·`line`·`gate`·`level`·`what` 을 그대로 잇는다).

**검사가 하나도 안 돈 레포에서 저장이 그냥 열린다.** 요청이 아니라 **우리가 고칠 것**이다.

### 잰 김에 확인한 것 하나 — `fix: null` 은 안 깨진다

`node.path("fix").asText("")` 가 `NullNode` 에서 무엇을 내나 의심했는데, **빈 문자열이다**
(jackson-databind 2.19.4 · `jshell` 로 확인). 문자열 `"null"` 이 새지 않는다.

### ⭐ 이어서 (2026-08-15 · 추출기 `12fe2ed` · 기획 레포 `e2c8212`) — **red 27 이 26 으로 줄었다**

위 §12 의 **red 27 은 그날의 값이고 이미 낡았다.** 기획 레포가 재동기화되면서 `manifest.json` 에
`toolchain` 칸이 생겨 **`MANIFEST` red 가 꺼졌다.** 직접 다시 돌려 쟀다:

```
cd planning-g2c && node verify/run.mjs . --json
→ status complete · toolchain we-adk-toolchain/1 · counts {red:26, review:17} · ratchet ok
   DOMAIN-COVERAGE/red 13 · IA-1/red 12 · IA-7/red 1
   A-3/review 14 · DOMAIN-COVERAGE/review 2 · IA-4/review 1
```

⭐ **새 게이트 `A-8`(화면이 실제로 보이나)이 들어왔는데 red 도 review 도 0건이다** — 화면이 다 보인다.
**우리가 「A-8 이 들어오면 27 이 움직인다」로 열어 둔 자리는 이렇게 닫혔다** — 움직이긴 했는데
**늘어난 게 아니라 줄었다.** ⛔ **26 도 기준선으로 굳히지 마라** — 게이트는 계속 는다.

⚠️ **판 번호는 안 올랐다**(`we-adk-toolchain/1` 그대로). 게이트가 하나 늘어도
`--json` 계약과 manifest 모양이 안 바뀌었으면 안 올린다는 뜻이다 — **14번이 세운 그 구분이다.**

### ⛔ 요청해서 세운 게이트가 되돌려졌다 — 그 이유가 우리도 쓸 기준이다

우리가 「팝업 다섯의 상위화면이 비었다」를 곁가지로 걸었고, 그것이 **「팝업·모달은 상위화면 필수」**

> **기계가 그 값을 「틀렸다」고 말할 수 있는 칸만 필수로 만든다.**

⛳ **그리고 이것이 「기획자가 답할 것」 하나를 없앴다.** 그 다섯이 바로 **부모가 여럿이라 사람이
칸을 비운 화면들**이었고, 파생이 자리를 찾아냈다 — **셋은 자리를 받고 둘은 공용으로 갔다.**
**사람에게 묻기 전에 실물에서 파생할 수 있나를 먼저 본다.**

같은 팝업을 연다). **부모 수로 판정했으면 자리가 멀쩡한 화면 셋을 트리에서 잃었다.**

### 색인이 `we-adk-index/3` 이다 — 우리가 등식으로 검산했다

| 잰 것 | 값 |
|---|---|
| `counts` | `{screens: 263, iaScreens: 256, iaShared: 2, facetScreens: 4}` |

`bo-front-lnkgpop` 은 `경로` 가 없지만 `iaShared` 에 있다. **등재 여부가 가르는 유일한 값이다.**

### 회신에 안 적혔는데 규격 원문에 있던 것 셋

- **`여는곳: 셸`** — 팝업·모달 전용 예외 선언. IA-9 red 를 면제하고 공용으로 보되
  **`IA-9 review` 를 대신 낸다**(기계가 확인 못 하는 주장). **래칫이 review 총수를 기준선으로
  잡으므로 이 도피구가 조용히 늘지 못한다.** 규격이 *"부모를 못 찾을 때 쓰는 도피구로 쓰지 마라"*
  라고 적었다 — v1 웹뷰 부모 0장 29장 중 진짜 셸은 **2장뿐**이었다.

`상위화면` 을 적는 것 자체가 이제 red 이기 때문이다.

### 판은 안 올랐다 — 그리고 그것이 「게이트가 안 늘었다」가 아니다

`we-adk-toolchain/1` 그대로고 `spec/manifest.md` 판올림 기록의 **`--json 계약 영향: 없음`** 이다

⛔ **`gate` 값을 아는 목록으로 걸러 버리면 새 red 를 조용히 잃는다.**

⚠️ **그쪽 규격 안에 판올림 조문이 둘이고 서로 어긋난다**(`spec/manifest.md:100-101` 대 `:111`).
**우리가 실물에서 두 문장을 확인했다.** 그쪽이 한쪽으로 맞추겠다고 했다 — **맞춰지면 다시 잰다.**

## 14. 기관별 목업 자리가 섰다 — 그리고 빌더 렌더에 하드 의존이 생겼다 (2026-08-15 · 회신 #4)

**무엇을 쟀나** — 추출기 **`08a42ea`** · 기획 레포 **`9886e9c`**. ⭐ **둘 다 푸시됐고 작업트리가 깨끗하다**
(§13 은 미커밋 판에서 잰 것이었다 — 그 값이 이제 커밋으로 굳었다).

### ⭐ 두 검사기 출력이 바이트로 같아졌다 — 「어느 검사기로 쟀나」가 실제로 갈랐던 자리다

**그쪽이 여기서 헛짚었다고 밝혔다** — 사본이 두 판 밀려 **레포 안 검사기로 자기를 재면 red 71,
추출기 원본으로 재면 24** 였다. 원인은 사본에 `verify/lib/def-scan.mjs` 가 **아예 없어** 옛 규칙이
`IA-1` 을 **56건** 내던 것. **재동기화로 닫혔고 우리가 확인했다:**

```
cd planning-g2c && node verify/run.mjs . --json          > A
cd extractor    && node verify/run.mjs <planning-g2c> --json > B
diff A B → 차이 0
```

⛔ **그래서 red 수를 적을 때는 「어느 검사기로 쟀나」를 같이 적는다.** 우리도 §13 에서 그 함정을
적어 뒀었다(그때는 사본이 IA-9 를 몰랐다) — **이번부터 실측 표에 검사기 출처를 고정으로 적는다.**

### 실측 — 앞 판과 한 건도 안 움직였다

### 그쪽이 반영하라 한 셋 — 우리 코드에서 확인했다. **셋 다 이미 안전하다**

- **`gate` 필터 없음** — `NodeCheckerCommand:123` 이 `gate` 를 **문자열 그대로 옮긴다.** 아는 값과
  대조하는 자리가 없다. ⭐ **막는 쪽 규율은 `level` 에 서 있다** — 모르는 등급을 버리지 않고
  **red 로 센다**(`:166-174` · *"조용히 버리면 저장이 열린다"*).
- **`counts` 를 안 읽는다** — 코드 전체에 없다. 등식 검산은 **문서에서 손으로 한 것**이라 안 깨졌다.
- **`status` 는 이제 읽는다** — §12 에서 우리가 찾은 결함(`incomplete` 를 판정으로 읽어 저장이 열림)이
  `NodeCheckerCommand:153-164` 로 닫혀 있다. **칸이 없으면 통과시키고, 있는데 `complete` 가 아닐 때만 막는다** —
  칸이 생기기 전 검사기를 쥔 레포를 전부 판정불가로 만들지 않기 위해서다.

### ⛔ 그쪽이 안 적은 것 하나 — **갈래 화면에는 기저 html 이 「없어도 되는」 게 아니라 「있으면 red」다**

`verify/lib/gates/a1a2-pages.mjs:36-44` 를 읽었다:

> *기저 html 과 갈래 목업이 둘 다 있으면 어느 것이 정본인지 기계가 못 정한다.*
> → **A-1 red** · `fix`: *"둘 중 하나를 지워라"*

**상호배타다.** 그리고 A-1 은 반대쪽도 막는다 — 갈래 목업이 있으면 **짝 md 없음**을 red 로 내고
(`:28-33`), 기저도 갈래도 없으면 「짝이 되는 html 이 없다」 red 다(`:17-20`).

⛔ **그래서 「`pages/<화면ID>.html` 을 연다」가 갈래 화면에서 항상 실패한다.**
빌더는 **`screens[<ID>].variants` 를 읽어 기관 하나를 골라야** 하고, 고를 재료는
**프로젝트의 「적용 구분」**으로 이미 있다. ⛔ **선택 기능이 아니라 렌더의 하드 의존이다** —
`facet-axis` 설계 결정 3 에 단서로 박았다(그 결정의 근거 넷이 `variants` 에는 하나도 안 걸린다).

### `facet` 과 `variants` 는 축이 다르다 — 겹쳐 읽으면 안 된다

| | `facet` | `variants` |
|---|---|---|
| 뜻 | 그 기관에**만** 있다 | 그 기관 **목업이** 있다 |
| 값 | 문자열 하나 | 정렬 배열(여럿) |
| 출처 | 사람이 적은 꼬리표 | **폴더 실물에서 계산** |
| 둘 다 있으면 | **`FACET-6` red** — 한 기관 전용이면 갈릴 상대가 없다 | |

**색인은 판정하지 않으므로 그런 레포에서는 두 곳에 다 실린다** — 그건 이미 red 인 레포라는 뜻이다.
실측: `facetIndex {"jeju": 4장}` · `variantIndex {}` — **겹치는 화면이 지금은 없다.**

### 폴더 자리를 `pages/` 와 같은 깊이로 잡은 이유 — 실측이 시켰다

목업들이 자산을 전부 **`../assets/…` 한 단계**로 부르고 **절대 경로가 하나도 없다.**
한 단계만 더 내려가면 **63건이 통째로 안 맞고**, 목업을 고쳐야 하며, 고치는 순간
**원본과 바이트로 대조할 수 있다는 이식의 유일한 증거가 사라진다.**

### ⛔ 이 검사들이 못 막는 것 — 그쪽이 밝혔고 우리가 그대로 물려받는다

- **화면을 md 까지 통째로 지우면 못 잡는다** — 애초에 없었던 것과 구별이 안 된다.
